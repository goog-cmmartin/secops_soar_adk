# AI Generation Playbook: CrowdStrike Falcon EDR (CS_EDR) Telemetry

## 1. Overview & Log Purpose
**CrowdStrike Falcon Endpoint Detection and Response (EDR)** event streams—typically ingested via the **Falcon Data Replicator (FDR)** or Streaming API—record low-level kernel, OS, process, file system, registry, network, user logon, and telemetry activity from managed endpoints across Windows, macOS, and Linux platforms.

### Key Monitored Activities
* **Process Lifecycle**: Process start (`ProcessRollup2`), execution statistics (`ProcessRollup2Stats`), process termination (`EndOfProcess`).
* **File System**: Binary creation (`PeFileWritten`, `MachOFileWritten`, `NewExecutableWritten`), script writes (`NewScriptWritten`), archive creation (`ZipFileWritten`, `OleFileWritten`), file deletion (`ExecutableDeleted`), ASEP modifications (`AsepFileChange`).
* **Authentication & Identity**: Successful logons (`UserLogon`), logoffs (`UserLogoff`), failed authentications (`UserLogonFailed`, `UserLogonFailed2`), identity associations (`UserIdentity`).
* **Network & DNS**: TCP/UDP connections (`NetworkConnectIP4`, `NetworkConnectIP6`), listeners (`NetworkListenIP4`), DNS queries (`DnsRequest`, `SuspiciousDnsRequest`), ARP/neighbor tables (`NeighborListIP4`).
* **Persistence & System Changes**: Scheduled task modification (`ScheduledTaskModified`), Windows service starts (`ServiceStarted`), registry updates (`RegSystemConfigValueUpdate`), driver loading (`DriverLoad`, `KernelModeLoadImage`).
* **Security & Sensor Status**: Firewall rules (`FirewallSetRule`, `FirewallDeleteRule`), sensor heartbeats (`SensorHeartbeat`), ETW hooks (`SetWinEventHookEtw`, `ScreenshotTakenEtw`), ML detections (`DeliverLocalFXToCloud`, `AssociateIndicator`).

## 2. Format Specification

### Classification
* **Base Format**: Single-line **Newline Delimited JSON (NDJSON)**.
* **Strict Typing Rule**: **All values (including integers, floats, timestamps, hashes, and boolean flags) are encoded as JSON Strings (`"key": "value"`)**.

### Quoting & Delimiters
* Every JSON key and value MUST be enclosed in standard double quotes `""`.
* Key/value pairs are separated by commas `,` without trailing commas.
* One complete JSON record per line (`\n` line break).

### Character Escaping & Encoding
* **Windows File Paths**: Device paths use escaped backslashes: `\\Device\\HarddiskVolume2\\Windows\\System32\\cmd.exe`.
* **NT Path Syntax**: `\\??\\C:\\Windows\\system32\\...`.
* **HTML/Unicode Entity Escaping**: Certain nested structures (e.g., XML in `TaskXml` or firewall rules in `FirewallRule`) use Unicode escape sequences:
  * `<` becomes `\u003c`
  * `>` becomes `\u003e`
  * `=` becomes `\u003d`
  * `&` becomes `\u0026`

### Process & Thread Context
CrowdStrike uses internal 64-bit unique identifiers for processes rather than simple OS PIDs.
* `TargetProcessId` / `ContextProcessId` / `ParentProcessId` / `SourceProcessId`: 14 to 18-digit unique integer string (e.g., `"96415691933129"`).
* `RawProcessId` / `EtwRawProcessId`: OS-level Process ID (e.g., `"9244"`, `"16096"`).
* `ContextThreadId` / `SourceThreadId` / `RawThreadId`: Unique internal or OS thread ID.
* `CommandLine`: Exact execution string including quotes, arguments, and switches.
* `ImageFileName`: Full kernel/device binary path (e.g., `\\Device\\HarddiskVolume2\\Windows\\System32\\cmd.exe`).
* `ParentBaseFileName`: Binary name of parent process (e.g., `explorer.exe`, `cscript.exe`).
* `IntegrityLevel`: Windows token integrity level string (`"4096"` = Low, `"8192"` = Medium, `"12288"` = High, `"16384"` = SYSTEM).
* `TokenType`: Token elevation/impersonation type (`"1"` = Primary, `"2"` = Impersonation).

---

### Identity & Authentication
* `UserName`: User account name (e.g., `"jdoe"`, `"ADMINISTRATOR"`, `"svc_backup"`, `"SYSTEM"`, machine accounts like `"LT13749$"`).
* `UserPrincipal`: Kerberos UPN (e.g., `"jdoe@corp.acme.com"`).
* `LogonDomain`: Windows NetBIOS domain or machine name (e.g., `"ACME"`, `"WORKGROUP"`).
* `UserSid`: Security Identifier (`"S-1-5-18"`, `"S-1-5-21-..."`).
* `AuthenticationId`: LUID / Logon Session ID as integer string (`"999"` for SYSTEM, `"997"` for LocalService, `"996"` for NetworkService, random integers for user sessions).
* `LogonType`: Windows logon types (`"2"` = Interactive, `"3"` = Network, `"4"` = Batch, `"5"` = Service, `"7"` = Unlock, `"10"` = RemoteInteractive/RDP).
* `AuthenticationPackage`: `"Kerberos"`, `"NTLM"`, `"Negotiate"`.
* `UserIsAdmin`: Boolean string (`"1"` or `"0"`).
* `Status` / `SubStatus`: NTSTATUS error codes for failed logons (`"3221225572"` = `0xC0000064` / User doesn't exist; `"3221225578"` = `0xC000006A` / Bad password; `"3221225581"` = `0xC000006D` / Logon failure).

---

### Hashes & File Attributes
* `SHA256HashData`: 64 lowercase hex characters.
* `MD5HashData`: 32 lowercase hex characters.
* `SHA1HashData`: 40 lowercase hex characters (frequently `"0000000000000000000000000000000000000000"` if not computed).
* `Size`: File size in bytes as string.
* `TargetFileName`: Full path of affected file.

---

### Network & DNS Fields
* `LocalAddressIP4` / `RemoteAddressIP4`: IPv4 strings.
* `LocalAddressIP6` / `RemoteAddressIP6`: IPv6 strings.
* `LocalPort` / `RemotePort`: Port numbers as strings (`"80"`, `"443"`, `"5985"`, `"135"`).
* `Protocol`: IANA protocol number as string (`"6"` = TCP, `"17"` = UDP, `"1"` = ICMP, `"58"` = ICMPv6).
* `ConnectionDirection`: `"0"` = Outbound, `"1"` = Inbound, `"2"` = Listening.
* `DomainName`: FQDN requested in DNS queries.
* `RequestType`: DNS RR type (`"1"` = A, `"28"` = AAAA).

## 4. Timestamp & Dynamic Time Templating

CrowdStrike FDR uses two primary timestamp representations simultaneously:

1. **Ingestion Time (`timestamp`)**: 13-digit Unix Epoch Milliseconds.
2. **Event Occurrence / Context Times (`ContextTimeStamp`, `ProcessStartTime`, `LogonTime`, `LogoffTime`)**: Unix Epoch Seconds with millisecond/microsecond decimal precision.

### Templating Instructions
When generating dynamic logs, compute the timestamps using the following standard template tags:

* For `timestamp` (Epoch Milliseconds):
  `"timestamp":"##$Epoch-0d0h0m0s$##000"` (or dynamically appended milliseconds).
* For `ContextTimeStamp` / `ProcessStartTime`:
  `"ContextTimeStamp":"##$Epoch-0d0h0m0s$##.##$Digit100-999$##"`
* For offsets (e.g., process start vs end or logon vs logoff):
  * Start: `"ProcessStartTime":"##$Epoch-0d0h10m0s$##.124"`
  * Ingestion: `"timestamp":"##$Epoch-0d0h10m0s$##540"`
  * Termination: `"ContextTimeStamp":"##$Epoch-0d0h1m0s$##.890"`

## 6. Key Constraints & Common Pitfalls

1. **Quote All Values**: Never output raw numeric literals or booleans. `{"IntegrityLevel": 16384}` will fail schema parsers expecting `"IntegrityLevel": "16384"`.
2. **Schema Version Suffixes**: The `name` field must match `event_simpleName` with the version suffix (e.g., `event_simpleName: "ProcessRollup2"` $\rightarrow$ `name: "ProcessRollup2V17"`; `event_simpleName: "UserLogon"` $\rightarrow$ `name: "UserLogonV8"`). For Mac, it frequently includes `Mac` (e.g., `DnsRequestMacV1`).
3. **Internal vs. OS PIDs**:
   * Do NOT use standard 4-digit or 5-digit OS PIDs in `TargetProcessId`, `ContextProcessId`, or `ParentProcessId`. Use synthetic 14–18 digit integers (e.g., `"96415693097233"`).
   * Use standard OS PIDs exclusively for `RawProcessId` and `EtwRawProcessId`.
4. **NT / Native Paths**:
   * File access/write events (`PeFileWritten`, `ImageFileName`, `TargetFileName`) use NT namespace device paths: `\\Device\\HarddiskVolume[0-9]\\...`.
   * CLI strings (`CommandLine`) typically use standard DOS drive paths: `C:\\Windows\\system32\\...`.
5. **Correlation Consistency**: When generating a multi-event scenario (e.g., process launch $\rightarrow$ script drop $\rightarrow$ network connect):
   * `aid` and `cid` must remain identical across events from the same host.
   * `TargetProcessId` from `ProcessRollup2` must match `ContextProcessId` in the subsequent `NewScriptWritten` and `NetworkConnectIP4` events.
   * `ProcessStartTime` $\le$ `ContextTimeStamp` $\le$ `timestamp`.
