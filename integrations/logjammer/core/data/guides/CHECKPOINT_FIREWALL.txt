# CHECKPOINT_FIREWALL Log Generation Playbook

---

## 1. Overview & Log Purpose

Check Point Security Gateways, Security Management Servers (SMS/MDS), and Next-Generation Firewalls (NGFW) running Gaia OS produce high-fidelity event streams. These logs capture layer 3/4 packet filtering, network address translation (NAT), Next-Gen Software Blade activity (IPS/SmartDefense, Application Control, URL Filtering, Threat Emulation, Anti-Bot/Anti-Malware, Identity Awareness), Remote Access/IPsec VPN (Connectra/VPN-1), and underlying Gaia OS administration (sshd, WebUI/httpd2, clish/xpand).

In enterprise networks, Check Point uses **Log Exporter** (introduced in R80.10) or standard Syslog daemons to forward events to SIEMs (Splunk, Microsoft Sentinel, Elastic, QRadar) in multiple output formats.

---

## 2. Format Specification

Check Point logs exist in four primary delivery wire formats depending on the Log Exporter configuration:

### Format A: RFC 5424 Syslog with Structured Data (`Fields@1.3.6.1.4.1.2620`)
* **Standard**: RFC 5424 Syslog with Check Point Enterprise OID `1.3.6.1.4.1.2620`.
* **Pattern**: `<PRI>VERSION ISO8601_TIMESTAMP HOSTNAME APP_NAME PROC_ID MSG_ID [Fields@1.3.6.1.4.1.2620 Key="Value" Key="Value" ...]`
* **Delimiters & Quoting**: Space-separated `Key="Value"` inside brackets `[...]`. Quotes inside values must be escaped.

### Format B: RFC 5424 / Check Point Semicolon-Delimited KV
* **Standard**: RFC 5424 Syslog Header + Semicolon-delimited bracket payload.
* **Pattern**: `<PRI>1 ISO8601_TIMESTAMP HOSTNAME CheckPoint PID - [key:"value"; key:"value"; ...]`
* **Delimiters & Quoting**: Pairs separated by `; `, formatted as `key:"value";`. Trailing space before closing bracket ` ]`.

### Format C: Pipe-Delimited Key-Value (Splunk/Standard Forwarding)
* **Standard**: Key-value pairs separated by literal pipe `|`.
* **Pattern**: `time=EPOCH|hostname=Gaia|product=Firewall|action=Accept|src=10.0.0.1|dst=10.0.0.2|...|`
* **Delimiters & Quoting**: Fields delimited by `|`. Keys and values are unquoted or quoted when spaces exist. Semicolons used in special fields like `methods:=` and `scheme:=`.

### Format D: Common Event Format (CEF)
* **Standard**: ArcSight CEF RFC with Syslog header.
* **Pattern**: `<PRI>CEF:0|Check Point|<Product_Blade>|Check Point|Log|<Event_Name>|<Severity>|act=Accept rt=EPOCH_OR_DATE spt=12345 dpt=443 ...`
* **Delimiters & Quoting**: Prefix delimited by `|`; extension composed of space-separated `key=value` pairs.

### Format E: Underlying Gaia OS Daemon Syslog (RFC 3164)
* **Standard**: BSD Syslog for OS-level authentication and service events.
* **Pattern**: `MMM DD HH:MM:SS HOSTNAME PROCESS[PID]: MESSAGE`

### 3.5 Check Point Internal Identifiers

* `loguid` / `UUid`: Unique event hex quad: `"{0x6112edc5,0x13,0x9c0f145,0xccaff1fd}"` or `"{0x0,0x0,0x0,0x0}"` (for aggregate/drop events).
* `flags`: Hex or decimal bitmask indicating logging options: `"411908"`, `"393216"`, `"49152"`, `"19716"`.
* `snid`: Session network ID hex string: `"aece089b"`, `"355a0173"`, `"b738ce69"`.
* `sequencenum`: Monotonically increasing sequence number per gateway log instance: `"1451"`, `"2241"`, `"373"`.
* `version`: Check Point log format version: `"1"`, `"5"`.

## 4. Timestamp & Dynamic Time Templating

Check Point logs embed up to three timestamp instances: the Syslog arrival header, the ISO-8601 generation header, and the internal epoch/date fields inside the structured body.

### Template Tag Reference

| Timestamp Type | Target Format | AI Generation Tag |
| :--- | :--- | :--- |
| **Syslog RFC 3164** | `MMM DD HH:MM:SS` (e.g., `Jul  9 02:10:09`) | `##$SyslogTime-0d0h0m0s$##` |
| **ISO-8601 UTC** | `YYYY-MM-DDTHH:MM:SSZ` (e.g., `2023-11-20T07:47:29Z`) | `##$TimeStamp-0d0h0m0s$##` |
| **ISO-8601 Timezone** | `YYYY-MM-DDTHH:MM:SS[+-]HH:MM` | `##$TimeStampIsoTZ-0d0h0m0s$##` |
| **Epoch Seconds** | Integer seconds (e.g., `1625809605`) | `##$Epoch-0d0h0m0s$##` |
| **Epoch Milliseconds** | Integer milliseconds (e.g., `1625811007000`) | `##$EpochMs-0d0h0m0s$##` |
| **CEF Date Format** | `YYYY-MM-DD HH:MM:SS` (e.g., `2023-04-24 05:32:56`) | `##$TimeStampCef-0d0h0m0s$##` |

## 6. Key Constraints & Pitfalls

### Mandatory Parser Fields
Check Point SIEM parsers (Splunk Add-on for Check Point, Microsoft Sentinel Check Point ASA connector, Logstash) will fail or misclassify if the following keys are omitted:
1. `product`: Must match exact Software Blade strings (e.g., `VPN-1 & FireWall-1`, `SmartDefense`, `Application Control`, `Identity Awareness`, `Connectra`).
2. `action` / `Action` / `act`: Must contain one of the canonical action verbs (`Accept`, `Drop`, `Reject`, `Block`, `Detect`, `Decrypt`, `update`, `Log In`, `Log Out`). Note that capitalization depends on format style (`Action="drop"` in OID format vs `action:"Drop";` in semicolon format vs `act=Drop` in CEF).
3. `loguid` / `UUid`: Must follow the 4-element hex tuple pattern `{0x0,0x0,0x0,0x0}` or `{0x5f2d6462,0x2c,0x26c7320a,0xc0000001}`.
4. `__policy_id_tag`: In Format B and C, the closing bracket must be escaped with a backslash if before a bracket delimiter: `policy_name=Standard\]"`.

### Syntax & Escaping Specifics
* **Semicolon Format (Format B)**: Every key-value must end with a semicolon `key:"value";`. Semicolons within string values (e.g., policy names or DNs) must not break the `key:"value";` structure.
* **Special Equals Syntax**: In VPN negotiations and certain internal engine logs, assignment contains colons: `methods:="AES-256 + SHA1"`, `scheme:="IKEv2"`, `IKE:="Child SA exchange..."`.
* **Multi-Layer Representation in R80+**: In R80+ Unified Policies, match conditions cascade across multiple layers. In bracket or JSON formats, repeated keys (`layer_name`, `layer_uuid`, `match_id`, `rule_action`) or array/table structures (`UP_match_table="TABLE_START" ...`) appear. When generating single-rule events, supply matching single `layer_name`, `layer_uuid`, `rule_name`, and `rule_uid`.
* **Zero Values**: Drops without NAT must have `0.0.0.0` or `0` for translated addresses and ports (`xlatesrc="0.0.0.0"`, `xlatesport="0"`). Drops triggered on interface without state may have `loguid="{0x0,0x0,0x0,0x0}"`.
