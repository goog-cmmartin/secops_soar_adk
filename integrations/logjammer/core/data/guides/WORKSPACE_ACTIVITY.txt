# AI Generation Playbook: Google Workspace Activity Logs (`WORKSPACE_ACTIVITY`)

---

## 1. Overview & Log Purpose

### What Produces This Log?
The `WORKSPACE_ACTIVITY` log stream represents audit and reporting events generated by **Google Workspace (formerly G Suite) Admin SDK Reports API** (`admin#reports#activity`). 

### Activities Recorded
These logs capture activity across Google Workspace core applications, administrative panels, and managed client endpoints. Activities include:
- **Authentication & Security (`login`, `saml`)**: Interactive web logins, password failures, SAML SSO assertions, 2-Step Verification (2SV/MFA) challenges, suspicious login alerts, and password/recovery email modifications.
- **Enterprise Group Management (`groups`, `groups_enterprise`)**: Role assignments (owner, manager, member), ACL/permission updates, member additions/removals, and message moderation.
- **Chrome Enterprise Telemetry (`chrome`)**: Endpoint Safe Browsing events, unsafe phishing/malware site visits, device user mapping, and extension actions.
- **Collaboration & Drive Apps (`data_studio`, `keep`, `calendar`, `gplus`)**: Asset creation/viewing, note sharing, calendar invite manipulation, timezone edits, and file/post ACL alterations.
- **Mobile Device Management (`mobile`)**: Device sync audits, MDM device registration, OS platform inventory, and compliance states.

### SIEM & Security Value
- Detection of **credential stuffing**, **brute-force**, and **impossible travel** attacks.
- Tracking **privilege escalation** (e.g., adding unauthorized users to privileged Google Groups).
- Hunting for **data exfiltration** (e.g., modifying asset visibility from `PRIVATE` to `PUBLIC` or sharing sensitive calendars externally).
- Monitoring endpoint phishing attempts intercepted by **Chrome Enterprise Safe Browsing**.

## 2. Format Specification

| Attribute | Specification |
| :--- | :--- |
| **Classification** | Single-line JSON (Newline-Delimited JSON / NDJSON) |
| **Character Encoding** | UTF-8 |
| **Delimiters & Quotes** | Strict standard JSON quoting (double quotes for strings, keys, and escaped inner strings). |
| **Escaping Rules** | Inner double-quotes in `etag` are escaped as `\"` or `\\\"`. Message IDs in parameters use escaped angle brackets (`\u003c` and `\u003e`). |

## 3. Schema Breakdown & Fields

> [!CAUTION]
> **CRITICAL CHRONICLE / SECOPS PARSER INVARIANT:**
> The Chronicle `WORKSPACE_ACTIVITY` parser (v27.0) **requires** the `events` array structure.
> **DO NOT** place `"type"`, `"name"`, or `"parameters"` at the top level of the JSON document! If placed at the root level, Chronicle will fail to categorize the activity and will normalize the entire record as `GENERIC_EVENT`.
> - **WRONG (Causes GENERIC_EVENT):**
>   `{"kind":"admin#reports#activity", "type":"login", "name":"login_success", "parameters":[...]}`
> - **CORRECT (Normalizes to USER_LOGIN, etc.):**
>   `{"kind":"admin#reports#activity", "events":[{"type":"login", "name":"login_success", "parameters":[...]}]}`

### Top-Level Object Schema

| Field Name | Type | Required? | Description / Allowed Values |
| :--- | :--- | :--- | :--- |
| `kind` | String | **Yes** | Fixed constant: `"admin#reports#activity"`. |
| `id` | Object | **Yes** | Composite identifier object containing event metadata. |
| `etag` | String | **Yes** | Opaque API entity tag token, quoted (e.g., `"\"JCPRxFaiNR.../Zk_h3ikUI...\""`). |
| `actor` | Object | **Yes** | Identity of the user or system invoking the action. |
| `ipAddress` | String | Optional | IPv4 address (`198.51.100.24`) or IPv6 address (`2401:49aa:1f3f:0:59fb:e0a9:a92e:0`). Null/omitted for internal system triggers. |
| `ownerDomain` | String | Optional | Primary domain of the Workspace customer (e.g., `company.com`). |
| `events` | Array | **Yes** | Array of event objects (typically 1 to 5 event objects per entry). |

---

### Nested Object Schemas

#### 1. `id` Object
```json
{
  "time": "2026-03-30T12:42:42.020Z",
  "uniqueQualifier": "1654049432447411495",
  "applicationName": "login",
  "customerId": "C02umwv6u"
}
```
- `time` *(String, Required)*: ISO 8601 UTC timestamp with millisecond precision.
- `uniqueQualifier` *(String, Required)*: String representation of a signed 64-bit integer (e.g., `"-7107041607711625798"`, `"1654049432447411495"`, or `"0"`).
- `applicationName` *(String, Required)*: Identifies the Google Workspace subsystem. Valid values:
  - `"login"`, `"saml"`, `"groups"`, `"groups_enterprise"`, `"calendar"`, `"chrome"`, `"keep"`, `"data_studio"`, `"mobile"`, `"gplus"`, `"drive"`, `"admin"`, `"token"`, `"context_aware_access"`.
- `customerId` *(String, Required)*: Unique tenant ID (e.g., `"C02umwv6u"`, `"gA3if7Bj6Y5B9"`).

#### 2. `actor` Object
```json
{
  "callerType": "USER",
  "email": "alex.chen@corp.example.com",
  "profileId": "106217923299022556308"
}
```
- `callerType` *(String, Optional)*: `"USER"` or `"KEY"`.
- `email` *(String, Conditional)*: Email address of the user or calendar resource ID (`c_1885...@resource.calendar.google.com`).
- `profileId` *(String, Conditional)*: 21-digit numeric Google Directory ID.
- `key` *(String, Conditional)*: Present when `callerType` is `"KEY"` (e.g., `"Google"`).

#### 3. `events[]` Array Element
```json
{
  "type": "login",
  "name": "login_failure",
  "parameters": [ ... ]
}
```
- `type` *(String, Required)*: Event category name.
- `name` *(String, Required)*: Specific event/verb.
- `parameters` *(Array, Optional)*: List of parameter objects.

---

### Parameter Data Types (`parameters[]`)
Every element in `parameters[]` consists of a `name` key and **exactly one** typed value field:

1. **String Value**: `{"name": "PARAM_NAME", "value": "string_content"}`
2. **Integer Value**: `{"name": "PARAM_NAME", "intValue": "1627401023860"}` *(Passed as a stringified integer)*
3. **Boolean Value**: `{"name": "PARAM_NAME", "boolValue": false}` *(Literal JSON boolean)*
4. **Multi-Value (Array of Strings)**: `{"name": "PARAM_NAME", "multiValue": ["manager", "owner"]}`

## 4. Timestamp & Dynamic Time Templating

### Formatting Standard
- **Primary Timestamp (`id.time`)**: ISO 8601 UTC with 3 millisecond digits, followed by `Z`.
  - Format: `YYYY-MM-DDTHH:MM:SS.sssZ`
  - Generation Tag: `##$TimeStamp-0d2h15m0s$##` (Evaluates to e.g., `2026-03-30T14:22:15.123Z`)
- **Embedded Epoch Milliseconds (`parameters[].intValue`)**:
  - Found in `TIMESTAMP` (Chrome) and `LAST_SYNC_AUDIT_DATE` (Mobile).
  - Generation Tag: `##$EpochMS-0d2h15m0s$##` or `##$Epoch-0d2h15m0s$##000` (Evaluates to e.g., `1774880535123`)

## 6. Key Constraints & Generation Pitfalls

1. **Mandatory `events` Envelope (No Flat Event Fields)**:
   - `events` is **always** an array of JSON objects containing `{"type": "...", "name": "...", "parameters": [...]}`.
   - **NEVER** output `type`, `name`, or `parameters` at the root JSON level. If you output them at root level, Google SecOps parses the event as `GENERIC_EVENT` instead of `USER_LOGIN` / `USER_RESOURCE_CREATION`.
2. **Parameter Typing Integrity**:
   - **Never** put raw text into `boolValue` or `intValue`.
   - `boolValue` must be `true` or `false` (literal JSON boolean, not `"true"` or `"false"` string).
   - `intValue` must be passed as a **string containing numbers** (e.g., `"1627401023860"`), **not** a bare JSON number.
   - `multiValue` must always be a JSON array of strings: `["manager"]`, `["owner", "editor"]`.
   - `value` is for standard single strings: `"PRIVATE"`, `"WARNED"`.
2. **Array Structure Consistency**:
   - `events` is **always** an array of JSON objects, even when representing a single event.
   - `parameters` is **always** an array of parameter objects.
3. **Identifier Syntax**:
   - `profileId` is a 21-digit string (e.g., `108288222646119478560`).
   - `customerId` begins with `C` or alphanumeric strings (e.g., `C02umwv6u`, `gA3if7Bj6Y5B9`).
   - `uniqueQualifier` can be `"0"`, a short numeric string, or a 19-digit positive/negative 64-bit integer string.
4. **ETag Escaping**:
   - The `etag` value contains quotation marks. When rendered in JSON, ensure valid escaping (`"etag": "\"JCPRxFaiNR1...\""`).
5. **No Trailing Commas**:
   - The JSON object must strictly follow RFC 8259 with no trailing commas in `events` or `parameters` arrays.
