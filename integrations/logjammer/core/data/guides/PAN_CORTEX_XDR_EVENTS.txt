# Detection Engineering Playbook: PAN Cortex XDR Events (`PAN_CORTEX_XDR_EVENTS`)

---

## 1. Overview & Log Purpose

**Palo Alto Networks Cortex XDR** (formerly Traps / Cortex EDR Agent) is an enterprise endpoint detection and response (EDR) and Extended Detection and Response (XDR) platform. Cortex XDR agents continuously monitor and record operating system activity across Windows, macOS, and Linux endpoints.

### Primary Log Types Captured:
1. **Raw Endpoint Telemetry (Events)**: High-fidelity telemetry recording causal process activity, file system modifications, registry edits, network connections, module/driver loads, and user session logons.
2. **Alerts & Incidents**: Detections generated by on-agent heuristic engines (Local Analysis), behavioral rules (BIOCs - Behavioral Indicators of Compromise), or cloud-based analytics (Analytics BIOCs).

These logs are consumed by SIEM/XDR data lakes for threat hunting, automated incident investigation (Causality / Storyline reconstruction), detection engineering, and compliance auditing.

---

## 2. Format Specification

| Attribute | Specification |
| :--- | :--- |
| **Data Format** | JSON (Single-line NDJSON / JSON objects) |
| **Field Naming** | `snake_case` (e.g., `os_actor_process_image_path`, `action_file_sha256`) |
| **String Quoting** | Double quotes (`"..."`) for strings. Null values represented as JSON `null` or omitted depending on agent version. |
| **Windows Path Escaping** | Double backslashes (`\\`) must escape every filesystem path separator (e.g., `"C:\\Windows\\System32\\cmd.exe"`). |
| **Nested Stringified JSON** | Certain complex objects (such as `action_process_token`, `action_module_file_info`, `action_process_fds`) are encoded as **escaped JSON strings** within string values. |
| **Binary ID Tracking** | Process causality, instance IDs, connection IDs, and event IDs are 24-character Base64-encoded binary handles (e.g., `"AdwqP2P1bYEAAACcAAAAAA=="`). |

## 3. Schema Breakdown & Fields

Cortex XDR logs follow a structured taxonomy split into **Common Agent Metadata**, **Actor Process (Parent/Initiator)**, **Action Details (Target/Result)**, and **Alert Attributes**.

### 3.1. Event Classification Identifiers

| Field Name | Type | Description | Values / Examples |
| :--- | :--- | :--- | :--- |
| `event_type` | Integer | High-level telemetry subsystem category | `1`: Process<br>`2`: Network<br>`3`: File<br>`4`: Registry<br>`6`: Module/Driver Load<br>`7`: User Logon/Session |
| `event_sub_type`| Integer | Specific operation performed | Process: `1` (Create), `2` (Terminate)<br>Network: `4` (TCP Connect), `11` (Socket Statistics/Stream)<br>File: `1` (Create), `2` (Open), `3` (Rename), `5` (Delete), `6` (Write/Modify)<br>Registry: `1` (Create Key), `2` (Open/Query), `5` (Set Value), `6` (Mount Hive)<br>Module: `1` (Load DLL/Sys/CPL)<br>User: `1` (Logon/Session Initialized) |
| `event_version` | Integer | Internal schema version number | Typically `25`, `26`, or `29` |
| `event_id` | String | Base64 unique identifier for the event record | `"AAABmWekoNNtIDExABK5aQ=="` |
| `uuid` | String | Event UUID (mirrors `event_id` on process events) | `"AAABmWekoNNtIDExABK5aQ=="` |

### 3.3. OS Actor Process (Initiating Entity)

The `os_actor_*` fields define the process, thread, and user context that triggered the event.

| Field Name | Type | Description | Example Values |
| :--- | :--- | :--- | :--- |
| `os_actor_process_instance_id` | String | Base64 unique handle for the actor process instance | `"AdwqP2P1bYEAAACcAAAAAA=="` |
| `os_actor_thread_thread_id` | Integer | Thread ID inside the actor process | `11944`, `23408` |
| `os_actor_process_os_pid` | Integer | Operating System Process Identifier (PID) | `4` (System), `1128`, `12648` |
| `os_actor_process_image_name` | String | File name of the binary executing the action | `"svchost.exe"`, `"explorer.exe"`, `"powershell.exe"`, `"sshd"` |
| `os_actor_process_image_path` | String | Full path to the executable file | `"C:\\Windows\\System32\\svchost.exe"`, `"/usr/sbin/sshd"` |
| `os_actor_process_command_line` | String | Full CLI command-line parameters | `"C:\\Windows\\System32\\svchost.exe -k netsvcs -p"` |
| `os_actor_process_image_md5` | String | MD5 hash of actor binary (32 hex chars) | `"b7f884c1b74a263f746ee12a5f7c9f6a"` |
| `os_actor_process_image_sha256` | String | SHA256 hash of actor binary (64 hex chars) | `"add683a6910abbbf0e28b557fad0ba998166394932ae2aca069d9aa19ea8fe88"` |
| `os_actor_process_signature_status` | Integer | Binary signature validation status | `1`: Signed & Valid<br>`2`: Invalid Signature<br>`3`: Unsigned<br>`6`: Embedded Driver Verified |
| `os_actor_process_logon_id` | String | Windows LUID logon session ID or POSIX UID | `"1003"`, `"160982021"`, `"18446744073709551615"` |
| `os_actor_primary_username` | String | User executing the parent actor process | `"NT AUTHORITY\\SYSTEM"`, `"DOMAIN\\user1"`, `"root"` |
| `os_actor_primary_user_sid` | String | User Security Identifier (SID) or POSIX UID | `"S-1-5-18"`, `"S-1-5-21-379941586-1207898258-1757479407-89517"`, `"0"` |

### 3.4. Action Subsystem Fields (Dynamic by Event Type)

#### Process Events (`event_type: 1`)
*   `action_process_os_pid` (Int): Created PID (e.g., `1912`).
*   `action_process_instance_id` (String): Base64 ID for the child process.
*   `action_process_image_path` (String): Target binary path (`"C:\\Windows\\System32\\cmd.exe"`).
*   `action_process_image_name` (String): Target binary name (`"cmd.exe"`).
*   `action_process_image_command_line` (String): Executed parameters.
*   `action_process_image_md5` / `action_process_image_sha256` (String): Binary cryptographic hashes.
*   `action_process_username` (String): Account context of child process (`"NT AUTHORITY\\SYSTEM"`).
*   `action_process_user_sid` (String): SID of the child process.
*   `action_process_integrity_level` (Int): Token integrity (`8192`: Medium, `12288`: High, `16384`: System).
*   `action_process_pe_load_info` (Object): `{ "image_base": "140701612638208", "image_size": "1036288", "entry_point_rva": 315280 }`.
*   `action_process_token` (Escaped String): Stringified JSON of token metadata: `{\"user_id\":\"S-1-5-18\",\"logon_id\":160995543,\"integrity_level\":16384}`.
*   `action_process_termination_code` (Int): Process exit code (`0`, `1`, `127`).

#### Network Events (`event_type: 2`)
*   `action_local_ip` (String): Host IP address (`"10.10.10.50"` or `"::ffff:10.10.10.50"`).
*   `action_local_port` (Int): Ephemeral or listening port (`54977`, `445`).
*   `action_remote_ip` (String): Remote destination IP.
*   `action_remote_port` (Int): Remote port (`443`, `445`, `80`, `53`, `22`).
*   `action_network_protocol` (Int): `6` (TCP), `17` (UDP), `1` (ICMP).
*   `action_socket_type` (Int): `1` (Stream/TCP), `2` (Datagram/UDP).
*   `action_network_is_server` (Boolean): `false` for outbound connection, `true` for listening socket.
*   `action_network_connection_id` (String): Base64 connection tracking handle.
*   `action_total_upload` / `action_total_download` (Int): Byte count transfer volumes.

#### File Events (`event_type: 3`)
*   `action_file_path` (String): Full absolute destination path.
*   `action_file_name` (String): Name of the file accessed/modified.
*   `action_file_previous_file_path` (String): Populated during **Rename** (`sub_type: 3`).
*   `action_file_previous_file_name` (String): Populated during **Rename** (`sub_type: 3`).
*   `action_file_size` (Int): File size in bytes.
*   `action_file_md5` / `action_file_sha256` (String): Hash of file payload.
*   `action_file_type` (Int): File category enum (`0`: Generic Data, `2`: Script/PS1, `18`: Temporary File).
*   `action_file_last_writer_actor` (String): Process instance ID of the last write modifier.

#### Registry Events (`event_type: 4`)
*   `action_registry_key_name` (String): Target registry key (`"HKEY_LOCAL_MACHINE\\SOFTWARE\\Microsoft\\Windows\\CurrentVersion\\Run"`).
*   `action_registry_value_name` (String): Value modified (`"StartWorkerOnServiceStart"`, `""` for Default).
*   `action_registry_value_type` (Int): `0` (REG_SZ), `4` (REG_DWORD), `7` (REG_MULTI_SZ).
*   `action_registry_return_val` (Int): NTSTATUS code (`0` = `STATUS_SUCCESS`).

#### Module Load Events (`event_type: 6`)
*   `action_module_path` (String): Path to loaded library (`"C:\\Windows\\System32\\ntdll.dll"`, `"/lib/x86_64-linux-gnu/libc.so.6"`).
*   `action_module_base_address` (String): Memory load address (`"140701612638208"`).
*   `action_module_image_size` (Int): Allocated image size in memory (bytes).
*   `action_module_signature_status` (Int): Signature verification state (`1`: Valid, `3`: Unsigned).
*   `action_module_file_info` (Escaped String): Stringified JSON containing internal metadata (Vendor, Copyright, Entropy, Product Version).

#### User Session Events (`event_type: 7`)
*   `action_username` (String): Authenticated username.
*   `action_user_status` (Int): `1` (Active/Logon), `2` (Logoff), `3` (Locked).
*   `action_user_is_local_session` (Boolean): `true` for physical/console logon, `false` for RDP/SSH.
*   `action_user_session_id` (Int): Windows Terminal Services session ID or Unix session ID.

### 3.5. Cortex XDR Alert Schema (Threat Detections)

When Cortex generates an alert (e.g., Local Analysis, BIOC, or Analytics), the log schema switches to an **Alert Record Structure**:

| Field Name | Type | Description |
| :--- | :--- | :--- |
| `alert_id` | String | Unique numerical Alert ID (`"2568038"`). |
| `external_id` | String | UUID representing the unified detection instance. |
| `severity` | String | Severity rating: `"low"`, `"medium"`, `"high"`, `"critical"`. |
| `category` | String | Threat classification: `"Malware"`, `"Exploitation"`, `"Lateral Movement"`, `"Credential Access"`. |
| `name` | String | Detection name: `"Local Analysis Malware"`, `"Suspicious PowerShell Execution"`. |
| `matching_status`| String | Rule engine state: `"MATCHED"`, `"RESOLVED"`. |
| `resolution_status` | String | Ticket status: `"STATUS_010_NEW"`, `"STATUS_090_RESOLVED_TRUE_POSITIVE"`. |
| `action` | String | Mitigation action taken: `"BLOCKED"`, `"TERMINATED"`, `"QUARANTINED"`, `"SCANNED"`. |
| `mitre_technique_id_and_name` | String | MITRE ATT&CK reference (e.g., `"T1059.001: PowerShell"`). |
| `tags` | String | Comma-separated organizational and agent tagging metadata. |

## 4. Timestamp & Dynamic Time Templating

### Format:
Cortex XDR uses **Unix Epoch Milliseconds** (13-digit integer, e.g., `1758380467643` representing `2025-09-20 15:01:07.643 UTC`).

### Templating Tags:
When generating synthetic data, all timestamps must be generated using dynamic millisecond epoch tags:
- `##$Epoch-0d0h0m0s$##` (Current event time in Epoch ms)
- `##$Epoch-0d0h0m10s$##` (10 seconds ago in Epoch ms)
- `##$Epoch-0d1h15m0s$##` (1 hour 15 minutes ago in Epoch ms)

*Note: For correlated actions, ensure causality ordering:*
`os_actor_process_creation_time` < `action_network_creation_time` < `event_timestamp`

## 6. Key Constraints & Pitfalls

### Mandatory Fields (Parsers Fail If Missing):
- `event_type` and `event_sub_type` (for raw EDR telemetry).
- `event_timestamp` (must be 13-digit Unix Epoch Milliseconds).
- `agent_id`, `agent_hostname`, and `agent_os_type`.
- `os_actor_process_image_path` and `os_actor_process_os_pid`.
- For Alerts: `alert_id`, `severity`, `category`, `name`, `action`, and `detection_timestamp`.

### Common Generation Errors to Avoid:
1. **Unescaped Nested JSON**: Fields like `action_process_token`, `action_module_file_info`, and `action_process_fds` are **escaped strings containing JSON**, not direct JSON child objects. 
   - *Incorrect*: `"action_process_token": {"user_id": "S-1-5-18"}`
   - *Correct*: `"action_process_token": "{\"user_id\":\"S-1-5-18\"}"`
2. **Invalid OS Type Values**: Mixing string and integer formats. In raw events, `agent_os_type` is an **integer** (`1` = Windows, `2` = macOS, `4` = Linux). In Alert schemas, `agent_os_type` is a string (`"Windows"`, `"Linux"`).
3. **Improper File Rename Action**: When `event_type: 3` and `event_sub_type: 3` (Rename), both `action_file_path` and `action_file_previous_file_path` **must** be populated.
4. **Incorrect Backslash Escaping in File and Registry Paths**: Windows paths must contain literal double backslashes in JSON representation (`"C:\\Windows\\System32"`). Failure to escape results in invalid JSON parse failures in SIEM connectors.
