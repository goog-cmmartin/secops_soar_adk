# AI Generation Guide (Playbook) — `NIX_SYSTEM`

---

## 1. Overview & Log Purpose

The `NIX_SYSTEM` log type aggregates operating system, kernel, subsystem, security auditing, and core service logs across Unix and Linux distributions (e.g., RHEL, CentOS, Debian, Ubuntu, Amazon Linux, SLES, Oracle Linux). 

### Activities Recorded
* **Authentication & Authorization**: SSH logins (`sshd`), PAM transactions (`pam_unix`, `pam_sss`, `pam_winbind`), console/terminal access (`su`, `sudo`, `login`), and privilege escalation attempts.
* **Audit Framework (`auditd` / `audispd`)**: Linux audit records covering system calls (`SYSCALL`), command execution (`EXECVE`, `USER_CMD`), SELinux/AppArmor mandatory access control decisions (`AVC`), user/group provisioning (`ADD_USER`, `ADD_GROUP`, `USER_MGMT`), and process termination anomalies (`ANOM_ABEND`).
* **Kernel & Low-Level Hardware (`kernel`)**: Boot messages, memory initialization, CPU topology, PCIe buses, device drivers, netfilter/iptables packet alerts, and martian IP source alerts.
* **System Daemons & Session Managers**: `systemd`, `systemd-logind`, `cron`/`crond`, `NetworkManager`, `rsyslogd`, `fstrim`.
* **Standard Network Daemons & Local Services**: Postfix/Sendmail (MTA), vsftpd (FTP), OpenVPN Access Server, Apache/Nginx web server runtime and error logs.
* **Cloud & SIEM Ingestion Envelopes**: Syslog forwarded directly, encapsulated in cloud agent payloads (Google Cloud Operations/Stackdriver, Azure Log Analytics/Sentinel), or wrapped by SIEM forwarders.

## 2. Format Specification

`NIX_SYSTEM` logs follow four primary representations depending on source subsystem and ingestion pipeline:

```
+-----------------------------------------------------------------------------+
|                               NIX_SYSTEM Formats                            |
+-----------------------------------------------------------------------------+
| 1. RFC 3164 Syslog (BSD)   : <PRI>MMM [D|DD] HH:MM:SS Host Tag[PID]: Msg    |
| 2. RFC 5424 Syslog (IETF)  : <PRI>1 YYYY-MM-DDTHH:MM:SS.s+TZ Host App Proc -|
| 3. Raw Linux Audit Format  : type=TYPE msg=audit(Epoch.msec:ID): k=v ...    |
| 4. Cloud Ingestion Envelopes: JSON wrapper around syslog/audit payload      |
+-----------------------------------------------------------------------------+
```

### A. Syslog RFC 3164 (BSD Syslog)
* **Pattern**: `<PRI>MMM [D|DD] HH:MM:SS <Host> <Tag>[<PID>]: <Message>`
* **PRI**: Optional priority integer enclosed in angle brackets: `PRI = (Facility * 8) + Severity`.
* **Timestamp**: Short month name, day of month (single-digit days are left-padded with a space, e.g., `"Apr  7"` vs `"Apr 28"`), and 24-hour time `HH:MM:SS`.
* **Tag / Process**: Process name, optionally followed by `[PID]:` (e.g., `sshd[23573]:`, `kernel:`, `sudo:`).

### B. Syslog RFC 5424 (IETF Syslog)
* **Pattern**: `<PRI>1 YYYY-MM-DDTHH:MM:SS.ssssss+ZZ:ZZ <Host> <AppName> <PID> <MsgID> <StructuredData> <Message>`
* Example: `<86>1 2024-06-13T16:01:32.747733+01:00 web-srv01 su 1234 - - pam_unix(su-l:session): session opened for user root`

### C. Linux Audit Subsystem (`auditd` / `audispd`)
* **Raw Audit Pattern**: `type=<TYPE> msg=audit(<Epoch_Seconds>.<Milliseconds>:<Event_ID>): <Key>=<Value> ...`
* **Syslog-Wrapped Audit**: `<PRI>MMM DD HH:MM:SS <Host> audispd[<PID>]: node=<Host> type=<TYPE> msg=audit(...): ... UID="<user>" AUID="<user>",HOST=<IP>`
* **Quoting & Delimiters**: Space-delimited key-value pairs (`key=value`, `key="value"`, `key='value'`).
* **Hex Encoding**: Arguments containing spaces, quotes, or unprintable characters are hex-encoded without quotes (e.g., `a2=2F7573722F62696E2F676574636F6E66` or `cmd=6466202D505469`).

### D. Cloud Ingestion JSON Envelopes
* **Google Cloud Logging (`syslog`)**: JSON payload containing `insertId`, `timestamp` (ISO 8601 UTC), `resource.labels`, and `jsonPayload.message` (holding the raw syslog line).
* **Azure Monitor / Sentinel (`Syslog`)**: Flat JSON object containing `TimeGenerated`, `HostName`, `HostIP`, `ProcessName`, `ProcessID`, `Facility`, `SeverityLevel`, and `SyslogMessage`.

### Core Subsystem Schemas

#### 1. PAM & Authentication Logs (`sshd`, `su`, `sudo`, `systemd-logind`)

```
+-----------------------------------------------------------------------------------------------+
| Field Name      | Type    | Description / Allowed Values                                      |
+-----------------------------------------------------------------------------------------------+
| Hostname        | String  | Server hostname, FQDN, or IPv4 (e.g., `prod-app01`, `localhost`)   |
| Process         | String  | `sshd`, `su`, `sudo`, `systemd-logind`, `CRON`, `useradd`         |
| PID             | Integer | Process ID (e.g., `23573`, `119931`)                              |
| PAM Module      | String  | `pam_unix`, `pam_sss`, `pam_winbind`, `pam_tally2`                |
| PAM Context     | String  | `sshd:auth`, `su:session`, `cron:session`, `su-l:session`          |
| User            | String  | Target account name (e.g., `root`, `deploy`, `svc_app`, `oracle`)  |
| Remote Host     | IP/FQDN | Client IP or hostname (`rhost=198.51.100.1`)                      |
| Result Action   | String  | `authentication failure`, `session opened`, `session closed`      |
+-----------------------------------------------------------------------------------------------+
```

**Common Patterns**:
* **SSH Success**: `sshd[<PID>]: Accepted (password|publickey) for <user> from <IP> port <port> ssh2`
* **SSH Failure**: `sshd[<PID>]: Failed password for (invalid user )?<user> from <IP> port <port> ssh2`
* **PAM Failure**: `sshd[<PID>]: pam_unix(sshd:auth): authentication failure; logname= uid=0 euid=0 tty=ssh ruser= rhost=<IP> user=<user>`
* **Sudo Execution**: `sudo[<PID>]: <invoking_user> : TTY=<tty> ; PWD=<path> ; USER=<target_user> ; COMMAND=<command>`

---

#### 2. Linux Audit System (`auditd`)

```
+-----------------------------------------------------------------------------------------------+
| Field Name      | Type    | Description / Formatting Rules                                    |
+-----------------------------------------------------------------------------------------------+
| type            | String  | Record Type (`SYSCALL`, `EXECVE`, `USER_AUTH`, `USER_LOGIN`, etc.)|
| msg=audit(...)  | Timestamp| Epoch time with millisecond precision and event serial counter:  |
|                 |         | `msg=audit(1651565389.241:46):`                                   |
| pid             | Integer | Process ID executing the action                                   |
| ppid            | Integer | Parent Process ID                                                 |
| uid             | Integer | Effective UID (e.g., `0` for root, `1000`+ for regular users)     |
| auid (loginuid) | Integer | Audit Login UID (original login UID; `4294967295` or `-1` = unset)|
| ses             | Integer | Session ID (`4294967295` or `-1` = unset / daemon session)        |
| exe             | String  | Absolute binary path (`"/usr/sbin/sshd"`, `"/bin/su"`)            |
| comm            | String  | Command name string (`"sshd"`, `"bash"`, `"ls"`)                  |
| terminal        | String  | TTY device (`pts/0`, `/dev/pts/1`, `ssh`, `cron`, `?`)            |
| res             | String  | Result (`success`, `failed`, `1`, `0`)                            |
| subj            | String  | SELinux/AppArmor context (`unconfined_u:unconfined_r:unconfined_t`)|
+-----------------------------------------------------------------------------------------------+
```

**Prominent Audit Record Types**:
* `USER_AUTH`, `USER_LOGIN`, `USER_START`, `USER_END`: PAM lifecycle tracking.
* `USER_CHAUTHTOK`: Password change events via `passwd` or `usermod`.
* `ADD_USER`, `ADD_GROUP`, `DEL_GROUP`, `USER_MGMT`: User and group account provisioning.
* `SYSCALL`: Syscall interception details (`arch`, `syscall`, `success`, `exit`, `items`).
* `EXECVE`: Command-line arguments: `argc=N a0="..." a1="..." a2="..."`.
* `CWD` / `PATH`: Working directory and file access paths associated with syscalls.
* `AVC` / `USER_AVC`: Mandatory Access Control denials (`denied { getattr } for pid=...`).

---

#### 3. Linux Kernel Messages (`kernel`)

* **Uptime Prefix**: `[ <seconds_since_boot>.<microseconds> ]`
* **Martian Source Alert**: `IPv4: martian source <dest_ip> from <src_ip>, on dev <interface>`
* **AppArmor/SELinux Alert**: `audit: type=1400 audit(<Epoch>.<msec>:<ID>): apparmor="<ACTION>" operation="<OP>" profile="<PROFILE>" name="<PATH>" pid=<PID>`
* **Driver / Hardware Events**: `pci`, `scsi`, `EDAC`, `smpboot`, `clocksource`, `bridge`.

## 4. Timestamp & Dynamic Time Templating

The `NIX_SYSTEM` log type uses distinct timestamp conventions across subsystems. When generating synthetic scenarios, use the specified time templating tags.

```
+-----------------------------------------------------------------------------------------------+
| Subsystem / Format        | Timestamp Syntax                 | Generator Template Tag         |
+-----------------------------------------------------------------------------------------------+
| Syslog RFC 3164 (BSD)     | MMM [D|DD] HH:MM:SS              | ##$SyslogTime-0d0h0m0s$##      |
| Syslog RFC 5424 (ISO 8601)| YYYY-MM-DDTHH:MM:SS.ssssss+ZZ:ZZ | ##$TimeStamp-0d0h0m0s$##       |
| Auditd Header Timestamp   | Epoch.msec (e.g., 1651565389.241)| ##$Epoch-0d0h0m0s$##.<msec>    |
| Apache Access Log         | [DD/MMM/YYYY:HH:MM:SS +ZZZZ]     | [##$ApacheTime-0d0h0m0s$##]    |
| Apache Error Log          | [Day MMM DD HH:MM:SS.uuuuuu YYYY]| [##$ApacheErrTime-0d0h0m0s$##] |
| Cloud Ingestion JSON (UTC)| YYYY-MM-DDTHH:MM:SS.sssssssssZ   | ##$TimeStamp-0d0h0m0s$##       |
+-----------------------------------------------------------------------------------------------+
```

### Relative Time Offset Formatting
* For an event 15 minutes in the past: `##$SyslogTime-0d0h15m0s$##`
* For an audit log 2 hours in the past: `msg=audit(##$Epoch-0d2h0m0s$##.482:1042)`
* For RFC 5424 timestamps: `##$TimeStamp-0d0h0m0s$##` (expands to `2026-03-30T14:22:18.123456+00:00`)

## 6. Key Constraints & Pitfalls

### Mandatory Parsing Rules
1. **RFC 3164 Spacing**: Single-digit day numbers must have two spaces between Month and Day (e.g., `"May  2"` vs `"May 22"`). Omitting the extra space causes timestamp parser failures in SIEM ingestion engines.
2. **Audit AUID vs UID**:
   * `auid=4294967295` (or `auid=-1` / `auid=unset`) indicates a system process, cron job, or daemon initialized prior to any interactive login.
   * `auid=1000+` represents the authentic login identity of the human user, even if they later executed `su` or `sudo` to become `uid=0 (root)`.
3. **Audit Hex Encoding**: Any command containing spaces or special characters executed via `EXECVE` or `USER_CMD` can be rendered in uppercase hex representation (e.g., `cmd=2F62696E2F6C73202D6C61` for `/bin/ls -la`). Parsers expect valid hex strings without quotation marks when encoded.
4. **PID Formatting**:
   * Standard syslog tags place the PID directly inside brackets immediately following the process name: `sshd[23573]:`.
   * Kernel messages do **not** use a process PID tag; they use `kernel:` followed by the bracketed float uptime: `kernel: [ 5079.912215]`.
5. **JSON String Escaping**: In JSON wrapper envelopes (GCP / Azure / SIEM forwarders), inner quotes and backslashes in syslog or audit lines must be escaped (`\"` or `\\`).
6. **Audit Multiline Sequences**: Correlated audit events (such as `SYSCALL`, `EXECVE`, `CWD`, and `PATH`) share the exact same timestamp and sequence id `msg=audit(Epoch.msec:ID):` to allow SIEMs to reconstruct the complete execution chain. Always use identical IDs for related event records.
