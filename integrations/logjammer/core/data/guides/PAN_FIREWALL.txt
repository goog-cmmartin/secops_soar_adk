# Palo Alto Networks PAN-OS Firewall (PAN_FIREWALL) Log Generation Playbook

## 1. Overview & Log Purpose

Palo Alto Networks Next-Generation Firewalls (NGFW) and Panorama management platforms produce logs for network security, session tracking, threat prevention, system operations, decryption analysis, and endpoint remote access (GlobalProtect). 

### Primary Log Categories & Activities Recorded:
* **TRAFFIC**: Network sessions, start/end states, bytes/packets transferred, NAT translation, rules matched, session end reasons (e.g., `aged-out`, `tcp-fin`, `policy-deny`).
* **THREAT**: Intrusion prevention (vulnerabilities), anti-spyware, antivirus, DNS security, file blocking, URL filtering, WildFire cloud sandbox analysis, and data filtering.
* **SYSTEM**: Chassis/hardware events, software updates, DHCP assignments, high-availability (HA) transitions, configuration commits, and administrative login/authentication events.
* **CONFIG**: Changes to firewall policies, objects, virtual routers, commit actions, and administrative settings.
* **USERID**: User-to-IP mappings, domain authentication tracking, GlobalProtect and XML API user mapping.
* **GLOBALPROTECT**: Gateway/portal authentications, client connect/disconnect, Host Information Profile (HIP) checks, client OS versions, and quarantine states.
* **DECRYPTION**: SSL/TLS decryption inspection details, cipher suites, certificate validation status, and fatal alerts.
* **CORRELATION / AUDIT / GTP**: Automated IOC correlation engine triggers, CLI audit logs, and telecom GTP inspection.

## 2. Format Specifications

PAN-OS logs are transmitted primarily over Syslog in three common encapsulations: **Native CSV (Standard PAN-OS Syslog)**, **CEF (Common Event Format)**, and **LEEF (Log Event Extended Format)**. Structured wrappers (JSON / Cortex Data Lake / NXLog) also carry these payloads.

### Format Variations Breakdown

#### Variant A: Standard PAN-OS CSV over BSD Syslog (RFC 3164)
```text
<PRI>MMM DD HH:MM:SS HOSTNAME 1,YYYY/MM/DD HH:MM:SS,SERIAL,LOG_TYPE,SUBTYPE,CONFIG_VER,TIME_GEN,...
```
* **Syslog Header**: `<PRI>` priority code, 3-letter month, day (space-padded if single digit `Nov  9`), time `HH:MM:SS`, firewall hostname/IP.
* **Delimiters**: Comma-separated values (`,`).
* **Quoting**: Fields containing commas, spaces, or quotes (such as URLs, user agents, threat names, CLI commands, email subjects) are enclosed in double quotes (`"..."`). Internal double quotes are escaped as `""`. Empty fields are left blank between commas (`,,`).

#### Variant B: Standard PAN-OS CSV over Syslog (RFC 5424)
```text
<PRI>1 YYYY-MM-DDTHH:MM:SS+ZZ:ZZ HOSTNAME APP-NAME PROCID MSGID SD 1,YYYY/MM/DD HH:MM:SS,SERIAL,LOG_TYPE,...
```
* **Syslog Header**: RFC 5424 structure with structured data placeholders `- - - -`.

#### Variant C: Common Event Format (CEF)
```text
<PRI>MMM DD HH:MM:SS HOSTNAME CEF:0|Palo Alto Networks|PAN-OS|VERSION|SUBTYPE|TYPE|SEVERITY|key=value key2=value2 ...
```
* **Header**: Pipe-delimited (`|`) with standard 7 CEF header fields.
* **Extension**: Key-value pairs separated by spaces. Values containing spaces or special characters are wrapped in double quotes or escaped.

#### Variant D: Log Event Extended Format (LEEF 1.0 / 2.0)
```text
<PRI>MMM DD HH:MM:SS HOSTNAME LEEF:2.0|Palo Alto Networks|PAN-OS Syslog Integration|VERSION|EVENT_ID|x7C|cat=TYPE|key=value|key2=value2|...
```
* **Header & Extension**: Delimited by pipe characters (`|`) or the delimiter defined in the header (e.g. `x7C`).

#### Variant E: Structured JSON (Cortex Data Lake / API Forwarder)
```json
{
  "source": "Palo Alto Networks FLS LF",
  "host": "FW-NAME",
  "time": "1730265996460",
  "event": {
    "LogType": "TRAFFIC",
    "Subtype": "end",
    "SourceAddress": "10.0.1.5",
    "DestinationAddress": "198.51.100.4"
  }
}
```

## 3. Schema Breakdown & Fields

### A. Common CSV Header (Positions 1 to 7)
All PAN-OS CSV log records share the identical first 7 positional fields:

| Pos | Field Name | Data Type | Description / Valid Values | Example |
| :--- | :--- | :--- | :--- | :--- |
| **1** | `FUTURE_USE` | Integer | Format revision identifier (almost always `1`) | `1` |
| **2** | `Receive Time` | Timestamp | Time log was logged/received on management plane (`YYYY/MM/DD HH:MM:SS`) | `2024/05/15 16:12:42` |
| **3** | `Serial Number` | String | 12-14 digit hardware/VM serial number | `013101009958`, `007051000184334` |
| **4** | `Type` | Enum | `TRAFFIC`, `THREAT`, `SYSTEM`, `CONFIG`, `USERID`, `GLOBALPROTECT`, `CORRELATION`, `DECRYPTION`, `GTP`, `AUTH` | `TRAFFIC` |
| **5** | `Subtype` | Enum | Dependent on Log Type (see subtype breakdown below) | `end`, `vulnerability`, `auth-fail` |
| **6** | `Config Version` | String/Hex | Internal configuration version code or release | `2561`, `2562`, `2817`, `2305`, `0` |
| **7** | `Time Generated`| Timestamp | Time session/event occurred on dataplane (`YYYY/MM/DD HH:MM:SS`) | `2024/05/15 16:12:42` |

## 4. Timestamp & Dynamic Time Templating

PAN-OS uses multiple synchronized timestamp formats across the syslog header, message body, and metadata extensions. Synthetic log generators must use the designated time tags to ensure dynamic consistency.

### Required Formats:
1. **Syslog Header Timestamp (RFC 3164)**: `MMM DD HH:MM:SS` (Space-padded day for 1-9: `Nov  9`, `Jan 22`).
   * Template Tag: `##$SyslogTime-0d0h0m0s$##`
2. **RFC 5424 Header Timestamp**: `YYYY-MM-DDTHH:MM:SS.sss+ZZ:ZZ` or `YYYY-MM-DDTHH:MM:SSZ`.
   * Template Tag: `##$TimeStamp-0d0h0m0s$##`
3. **PAN-OS Native CSV Body Timestamps**: `YYYY/MM/DD HH:MM:SS` (used for Receive Time, Time Generated, Session Start Time).
   * Template Tag: `##$TimeStamp-0d0h0m0s:YYYY/MM/DD HH:mm:ss$##`
4. **PAN-OS High-Resolution / ISO Timestamp**: `YYYY-MM-DDTHH:MM:SS.sss+ZZ:ZZ` or `YYYY-MM-DDTHH:MM:SS.sssZ`.
   * Template Tag: `##$TimeStamp-0d0h0m0s:YYYY-MM-DDTHH:mm:ss.SSSZZ$##`
5. **CEF / LEEF Header / devTime**: `MMM DD YYYY HH:MM:SS GMT` or `YYYY/MM/DD HH:MM:SS`.
   * Template Tag: `##$TimeStamp-0d0h0m0s:MMM dd YYYY HH:mm:ss GMT$##`
6. **Epoch Timestamp (Seconds or Milliseconds)**:
   * Template Tag: `##$Epoch-0d0h0m0s$##` (seconds) or `##$EpochMS-0d0h0m0s$##` (milliseconds)

## 6. Key Constraints & Pitfalls

### Mandatory Parsing Rules
1. **Positional Integrity in CSV**:
   * PAN-OS CSV parsers rely on **exact comma index counts** (often up to 100+ fields depending on PAN-OS version).
   * **Never truncate trailing commas** if fields are unused; preserve exact empty delimiters (e.g., `,,,,,,,,,,,,,,,,,,,,,,,,,,,,,,,,,,,`).
2. **Double Quoting Rules**:
   * If a string field contains a comma (`,`), double quote (`"`), newline, or leading/trailing space, wrap the entire field in double quotes (`"..."`).
   * Escape inner quotes with two double quotes (`""`). Example: `"Sub: Message from ""John Doe"""`.
3. **Session Metric Consistency**:
   * In `TRAFFIC` end logs: `Bytes Total = Bytes Sent + Bytes Received` and `Packets Total = Packets Sent + Packets Received`.
   * If `Action = drop` or `Action = deny` at start, `Bytes Received` and `Packets Received` are typically `0`.
4. **Hexadecimal Flag Formats**:
   * Flags and Action Flags must always be represented in hexadecimal prefixed by `0x` (e.g., `0x0`, `0x19`, `0x400019`, `0x8000000000000000`, `0x2000000000000000`).
5. **Port & Protocol Alignment**:
   * When `proto=icmp`, Source and Destination ports should be `0` (or the ICMP Type/Code).
   * When NAT is not applied, NAT Source IP and NAT Destination IP are either `0.0.0.0`, identical to original IPs, or left blank, while NAT ports are `0`.
6. **Subtype & Type Cohesion**:
   * Do not mix subtypes across types. `vulnerability`, `virus`, `spyware`, `url`, `file`, `wildfire` belong exclusively to `THREAT`. `start`, `end`, `drop`, `deny` belong exclusively to `TRAFFIC`.
