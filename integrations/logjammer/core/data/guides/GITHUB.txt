# GITHUB Log Generation Playbook

## 1. Overview & Log Purpose
GitHub logs capture security, administrative, access, and operational activities across GitHub Enterprise Cloud (GHEC) and GitHub Enterprise Server (GHES). These logs record audit trail events, Git transport operations (clone, fetch, push), API usage, webhook configurations, authentication events, CI/CD Actions workflows, and appliance-level reverse proxy/daemon telemetry.

### Primary Use Cases for Detection Engineering:
* **Credential & Token Abuse**: Compromised Personal Access Tokens (PATs), anomalous OAuth scope usage, brute-force authentication failures, or SSH key unauthorized usage.
* **Supply Chain & Insider Threats**: Unauthorized repository access/cloning, tampering with GitHub Actions workflows/secrets, malicious webhook additions, repository visibility alteration (private to public), and unauthorized organization/team privilege escalation.
* **Data Exfiltration**: High-volume repository cloning/fetching via automated bots, unauthorized deployment keys, or non-corporate source IP addresses.

## 2. Format Specifications

GitHub logs generally appear in one of three primary formats:

### Format A: GitHub Audit Log / Event Stream (JSON)
* **Structure**: Single-line (NDJSON) or pretty-printed standard JSON document.
* **Encoding**: UTF-8.
* **Quoting & Types**: Standard JSON. Keys are enclosed in double quotes. Booleans are `true`/`false`, numbers are unquoted, null values are `null`.

### Format B: GitHub Enterprise Server (GHES) Syslog (RFC 3164 / BSD Syslog)
* **Structure**: `<PRI>MMM DD HH:MM:SS <hostname> <subsystem>[PID]: <message>`
* **Subsystems / Tags**:
  * `github_audit`: JSON audit payload within Syslog.
  * `github_auth`: Authentication logger format (`D, [YYYY-MM-DDTHH:MM:SS.ffffff #PID] LEVEL -- : key="value"`).
  * `github_unicorn`: Unicorn Rails application key-value pairs (`key=value` or `key="value"`).
  * `github_gitauth`: Git access control daemon log (`k=v` format).
  * `github_access` & `alambic_assets`: NGINX web access log (Combined Log Format variation with response time trailer).
  * `haproxy`: HAProxy connection log.
  * `authzd`, `babeld`, `gitrpcd`, `hookshot-go`: Go daemon structured key-value log lines (`ts=... level=... msg="..."`).

### Format C: GitHub Webhooks (JSON)
* **Structure**: Rich nested JSON payload containing top-level action verbs and nested entity models (`workflow_run`, `repository`, `sender`, `organization`, `enterprise`).

### C. GitHub Enterprise Server (GHES) Syslog Subsystems

#### 1. `github_auth`
* **Format**: Ruby logger format.
* **Fields**: `now="ISO8601"`, `ip=<IP>`, `request_id=<UUID/Hex>`, `repo=<Org/Repo.git>`, `action=<read|write>`, `protocol=<http|ssh>`, `message="<Auth status message>"`, `at=<success|failure>`, `from=<git|web|api>`, `login=<username>`, `hashed_token="<Base64>"`, `token_type=<oauth_access|password|personal_access_token>`, `failure_reason=<external_auth_token_required|bad_credentials|nil>`.

#### 2. `github_unicorn`
* **Format**: Key-value pairs.
* **Fields**: `app=github`, `auth_fingerprint="<type>:<id>:<ip>"`, `controller="<Api::*>"`, `path_info="<URI>"`, `auth=<oauth|token|anon|basic>`, `current_user=<username>`, `oauth_scopes="<scopes>"`, `x_real_ip=<IP>`, `status=<HTTP Status>`, `elapsed=<Float>`, `user_agent="<UA>"`.

#### 3. `github_access`
* **Format**: `<Host/IP> <user_ident> <auth_user> [<HTTP-Date>] "<METHOD> <URI> <PROTO>" <status> <bytes> "<Referer>" "<User-Agent>" "<Remote_IP>" <resp_time> <backend_time> .`

#### 4. `authzd`
* **Format**: Structured key-value output.
* **Fields**: `time="ISO8601"`, `level=INFO`, `msg="authorization request decision"`, `actor.id=<ID>`, `subject.type=Repository`, `repository.owner.type=Organization`, `decision=<ALLOW|DENY>`, `matched_policies=[<policy-name>]`, `duration_ms=<Int>`.

#### 5. `babeld`
* **Format**: Structured key-value Git transport proxy log.
* **Fields**: `ts="ISO8601"`, `proto=<http|ssh>`, `ip=<IP>`, `repo=<Org/Repo>`, `cmd=<git-upload-pack|git-receive-pack>`, `msg="<op done|http op done: (status)>"`, `http_status=<Status>`, `fp_sha256="<Key-Fingerprint>"`.

## 4. Timestamp & Dynamic Time Templating

GitHub logs utilize three major timestamp variations depending on log emission type:

| Format Type | Syntax Pattern | Template Macro | Example Output |
| :--- | :--- | :--- | :--- |
| **Audit Log Epoch (ms)** | 13-digit Unix Milliseconds | `##$Epoch-0d0h0m0s$##000` or `##$Epoch-0d0h10m0s$##235` | `1695387645130` |
| **Syslog Header** | `MMM DD HH:MM:SS` (RFC 3164) | `##$SyslogTime-0d0h0m0s$##` | `Mar 28 23:16:16` |
| **ISO 8601 (UTC)** | `YYYY-MM-DDTHH:MM:SSZ` | `##$TimeStamp-0d0h0m0s$##` | `2023-09-27T23:59:02Z` |
| **ISO 8601 (Sub-second)**| `YYYY-MM-DDTHH:MM:SS.ffffffZ`| `##$TimeStamp-0d0h0m0s$##` | `2023-03-28T23:16:14.751740633Z` |
| **Nginx / Combined** | `[DD/MMM/YYYY:HH:MM:SS +0000]` | `[##$HTTPDate-0d0h0m0s$##]` | `[09/May/2023:12:34:23 +0000]` |

### Rules for Synthetic Generation:
1. When generating JSON audit logs, set both `"created_at"` and `"@timestamp"` to the same 13-digit millisecond value.
2. For GHES Syslog streams, the syslog header timestamp must match the internal message timestamp (e.g., `now="..."` or `time="..."`) within a margin of 0–2 seconds.

## 6. Key Constraints & Pitfalls

### Parser & Field Alignment
1. **Timestamp Consistency**: JSON logs emitted by GitHub Enterprise Audit Stream require `created_at` and `@timestamp` as 13-digit Unix Epoch milliseconds. Emitting 10-digit Epoch seconds causes index failure in ELK/Splunk/OpenSearch GitHub ingest pipelines.
2. **Mandatory Action Syntax**: `action` must follow the format `<category>.<event>` (e.g. `repo.create`, `git.clone`, `workflows.cancel_workflow_run`). If generating webhook actions, root `action` may be a single verb (e.g. `completed`, `created`), but the nested context object must exist.
3. **Quoting and Escaping**:
   * For GraphQL or GraphQL JSON fields in `query_string`, all interior quotes must be properly JSON-escaped (`\"`).
   * In GHES Syslog lines (`github_unicorn`, `authzd`), values containing spaces or commas MUST be wrapped in double quotes (e.g., `user_agent="git/2.30.2"`, `matched_policies=[policy1]`).
4. **Token Obfuscation**: Never output raw plaintext tokens in `hashed_token`. It must always appear as a 44-character Base64 string ending with `=`.
5. **Syslog Facility/Severity Prefixes**: GHES Syslogs include RFC 3164 PRI headers such as `<14>` (User.Info), `<11>` (User.Error), `<85>` (Auth.Notice), `<142>` (Local1.Info), or `<190>` (Local7.Info). Ensure valid `<PRI>` tags are prefixed when generating GHES appliance logs.
