# AI Generation Playbook: Office 365 Unified Audit Log (OFFICE_365)

## 1. Overview & Log Purpose
The `OFFICE_365` log source represents events generated by Microsoft 365 services and ingested via the **Office 365 Management Activity API** (often referred to as the Unified Audit Log - UAL). 

This log source captures user, administrative, and system activities across the entire Microsoft 365 cloud ecosystem, including:
- **SharePoint Online & OneDrive for Business**: File access, uploads, downloads, modifications, deletions, sync client activity, permissions/sharing modifications, and built-in malware detection.
- **Azure Active Directory / Entra ID (`AzureActiveDirectory`)**: User, group, device, application, and directory lifecycle events, credential resets, and administrative configuration changes.
- **Microsoft Defender for Office 365 (`ThreatIntelligence`)**: Inbound/outbound email threat detections (phishing, malware, spoofing), authentication verdicts (SPF, DKIM, DMARC, Composite Auth), and delivery routing decisions.
- **Project Online (`Project`)**: Project checkouts, access, and updates.
- **Exchange Online & Teams**: Mailbox modifications, access delegation, and collaboration events.

---

## 2. Format Specification
- **Classification**: Single-line JSON / NDJSON (Newline Delimited JSON).
- **Key Naming Convention**: Strictly **PascalCase** (e.g., `CreationTime`, `RecordType`, `Operation`, `UserId`, `ClientIP`, `OrganizationId`).
- **Encodings & Character Escapes**:
  - Standard JSON string escaping.
  - Characters `<` and `>` are often escaped as `\u003c` and `\u003e`.
  - Ampersands `&` are often escaped as `\u0026`.
  - Nested XML snippets in fields such as `EventData` are stored as raw or escaped XML strings (e.g., `"<Type>Edit</Type>"`).
  - Nested JSON structures within `ModifiedProperties.NewValue` or `ExtendedProperties.Value` may be serialized as JSON strings or raw JSON objects depending on the workload.

## 3. Schema Breakdown & Fields

### A. Common Envelope Fields (Present across all workloads)
| Field | Type | Description / Constraints | Example Values |
| :--- | :--- | :--- | :--- |
| `Id` | String (GUID) | Unique identifier for the audit record. | `"0b28b3d1-cae6-4d17-307b-08d7abd2d56d"` |
| `RecordType` | Integer | Numeric identifier indicating the audit schema workload. | `4` (SharePoint), `6` (SharePointFileOperation), `8` (AzureActiveDirectory), `14` (SharePointSharing), `28` (ThreatIntelligence), `35` (Project) |
| `CreationTime` | String | ISO 8601 UTC timestamp without timezone offset (`YYYY-MM-DDTHH:MM:SS`). | `"2023-04-16T23:59:55"` |
| `Operation` | String | The specific action or event name. | `"FileDownloaded"`, `"Delete user."`, `"TIMailData"` |
| `OrganizationId` | String (GUID) | Azure AD Tenant GUID. | `"ae4df1f7-611e-444f-897e-f964e1205171"` |

| `ClientIP` | String | Originating IPv4/IPv6 address. Set to `""` for background/system jobs. | `"198.51.100.45"`, `""` |
| `CorrelationId` | String (GUID) | Operation correlation GUID. | `"b320339f-0014-a000-747f-bb5acebee518"` |

| Field | Type | Description / Structure |

## 4. Timestamp & Dynamic Time Templating

The standard timestamp format across all Office 365 UAL records is **ISO 8601 UTC** with no offset representation:
`YYYY-MM-DDTHH:MM:SS` (e.g., `2024-03-20T14:32:10`).

When authoring scenarios, dynamic generation engines must inject relative time templates:
- Standard UAL Timestamp: `##$TimeStamp-0d0h0m0s$##` -> Output: `2024-03-20T14:32:10`
- Timestamp Offset (e.g., 2 hours ago): `##$TimeStamp-0d2h0m0s$##` -> Output: `2024-03-20T12:32:10`
- Message Delivery / Secondary Timestamps (`MessageTime`): `##$TimeStamp-0d0h2m0s$##`
- Epoch Seconds (if required by custom consumers): `##$Epoch-0d0h0m0s$##`

## 6. Key Constraints & Pitfalls

1. **Strict PascalCase Requirements**:
   - Field names MUST use PascalCase (`UserId`, `ClientIP`, `RecordType`, `CreationTime`). Lowercase or camelCase field names (`userId`, `clientIp`) will cause SIEM ingestion and parsing rules to silently fail.
2. **Trailing Periods in Azure Active Directory Operations**:
   - Operations in `AzureActiveDirectory` (`RecordType: 8`) almost universally end with a trailing period (e.g., `"Delete user."`, `"Update group."`, `"Change user password."`). SharePoint and Threat Intelligence operations do NOT use trailing periods (`"FileDownloaded"`, `"TIMailData"`).
3. **Empty Values vs. Missing Keys**:
   - System tasks, automated syncs, and internal backend events preserve fields like `ClientIP` but set their values to empty strings `""` instead of `null` or omitting the key.
4. **UserKey Discrepancies Across Workloads**:
   - `SharePoint`/`OneDrive`: Format is commonly claims-prefixed: `i:0h.f|membership|user@domain.com`.
   - `AzureActiveDirectory`: Usually plain UPN (`user@domain.com`) or `"Not Available"`.
   - `SharePoint\system`: Windows SID format `"S-1-0-0"`.
   - `ThreatIntelligence`: Constant string `"ThreatIntel"`.
5. **XML and Character Escapes**:
   - In `ThreatIntelligence` and `SharePoint` events, HTML entities like `<` and `>` in message headers or email addresses MUST be escaped as `\u003c` and `\u003e`.
   - Embedded XML in `EventData` should be kept as flat escaped XML strings without raw unescaped newlines inside JSON values.
