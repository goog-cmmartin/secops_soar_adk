# Proofpoint on Demand (POD) / PPS Message Event Log Generation Guide

This guide provides the complete specification, schema layout, field distributions, and templating rules necessary to generate synthetic **Proofpoint on Demand (POD)** and **Proofpoint Protection Server (PPS)** message tracking/filtering event logs.

---

## 1. Overview & Log Purpose

Proofpoint on Demand (POD) and Proofpoint Protection Server (PPS) process all inbound, outbound, and internal corporate email traffic. Each log line records the end-to-end telemetry and security evaluation of a single SMTP transaction. 

### Activities Recorded
- **Inbound/Outbound Message Filtering**: SMTP connection metadata, envelope addresses, and RFC 5322 header metadata.
- **Threat Engine Telemetry**: Antivirus (`av`), Spam & Bulk analysis (`spam`), Zero-Hour protection (`zerohour`), and Proofpoint Dynamic Reputation (`pdr`).
- **Email Authentication Checks**: SPF verification (`spf`), DKIM signature checks (`dkimv`), and DMARC enforcement and alignment (`dmarc`).
- **URL Defense & Attachment Analysis**: Detection, classification, and URL rewriting (`urldefense`), along with MIME part inspection, hashing (MD5/SHA256), and file type detection (`msgParts`).
- **Policy Enforcement & Routing**: Disposition decisions (`continue`, `discard`, `quarantine`, `accept`, `reject`), policy rule matches, header manipulation, and quarantining.

---

## 2. Format Specification

| Attribute | Specification |
| :--- | :--- |
| **Format Classification** | Structured **JSON** (JSON Lines / Single-line JSON per message event). |
| **Character Encoding** | UTF-8 (Header values may contain encoded-word strings like `=?UTF-8?B?...?=`). |
| **Delimiters & Quotes** | Standard JSON syntax. All strings double-quoted, numbers and booleans unquoted. |
| **Line Ending** | `\n` (LF) or `\r\n` (CRLF) for syslog streaming/file ingestion. |

---

## 3. Schema Breakdown & Fields

The log is a single root JSON object containing nested blocks: `ts`, `guid`, `pps`, `connection`, `envelope`, `msg`, `filter`, `msgParts`, and `metadata`.

```
Root
├── ts (String: ISO-8601 Timestamp)
├── guid (String: Unique message GUID)
├── pps (Object: Cluster and agent info)
├── connection (Object: Inbound SMTP connection details)
├── envelope (Object: SMTP envelope sender/recipients)
├── msg (Object: Extracted & normalized RFC 5322 headers)
├── filter (Object: Routing, actions, scoring, and module results)
├── msgParts (Array of Objects: MIME body/attachment telemetry)
└── metadata (Object: Origin and cluster metadata)
```

---

### 3.1. Top-Level Fields

| Field Name | Type | Description | Realistic Examples |
| :--- | :--- | :--- | :--- |
| `ts` | String | ISO 8601 timestamp with fractional seconds and timezone offset. | `"2023-11-15T14:22:18.469140-0500"` |
| `guid` | String | Unique Proofpoint Message ID (alphanumeric, hyphens, underscores). | `"JklGK_bpAzWWL8z3EsfU71d9Bk3RxTMI"`, `"UsjFMYOP3Rw1cY9zr9nkKYVTjyfXG-QG"` |
| `pps` | Object | Proofpoint node info. Contains `cid`, `version`, `agent`. | `{"cid": "acme_hosted", "version": "8.18.6.12", "agent": "m0081515.ppops.net"}` |
| `metadata` | Object | Origin information wrapper matching `pps`. | `{"origin": {"data": {"cid": "acme_hosted", "version": "8.18.6.12", "agent": "m0081515.ppops.net"}}}` |

---

### 3.2. `connection` Object

Details the connecting client and inbound TLS configuration:

| Field Name | Type | Description | Realistic Values |
| :--- | :--- | :--- | :--- |
| `ip` | String | Remote connecting IP address. | IPv4 (`"198.51.100.25"`) or IPv6 (`"2001:db8::1"`) |
| `host` | String | Reverse DNS hostname of the connecting IP. | `"mail-out.sender.com"`, `"fakehost.com"`, `"localhost"` |
| `helo` | String | SMTP HELO/EHLO parameter supplied by sender. | `"mx1.senderdomain.com"`, `"o3.cloudmail.wageworks.com"` |
| `sid` | String | SMTP session ID. | `"31uurabsbm"`, `"313u2wr2nk"` |
| `country` | String | Two-letter ISO country code of connecting IP. | `"us"`, `"eu"`, `"gb"`, `"de"`, `"**"` (internal/unknown) |
| `protocol` | String | Connection protocol. | `"smtp:smtp"`, `"smtp:esmtp"` |
| `resolveStatus` | String | DNS reverse lookup status. | `"ok"`, `"failed"`, `"nxdomain"` |
| `tls.inbound` | Object | Inbound TLS parameters (`version`, `cipher`, `cipherBits`). | `{"version": "TLSv1.2", "cipher": "ECDHE-RSA-AES256-GCM-SHA384", "cipherBits": 256}` |

---

### 3.3. `envelope` Object

The SMTP envelope (`MAIL FROM` and `RCPT TO`):

| Field Name | Type | Description | Realistic Values |
| :--- | :--- | :--- | :--- |
| `from` | String | Envelope sender address (`MAIL FROM`). | `"sender@external.com"`, `"bounces+123@marketing.com"`, `""` |
| `fromHashed` | String | Anonymized sender (`<md5(local_part)>@domain`). | `"b4b88d0c51946283a3706ed659096935@external.com"` |
| `rcpts` | Array[Str] | Array of envelope recipient addresses. | `["alice@company.com"]`, `["bob@company.com", "carol@company.com"]` |
| `rcptsHashed` | Array[Str] | Array of anonymized recipient addresses. | `["61bab701546e8f1cfafff3eeb25f8b3b@company.com"]` |

---

### 3.4. `msg` Object

Message structure and RFC 5322 header information:

- **`sizeBytes`** *(Integer)*: Total payload size in bytes (e.g., `4124`, `63280`).
- **`lang`** *(String)*: Detected language (e.g., `"en"`, `"pt"`, `"es"`, `"und"`).
- **`header`**: Raw extracted email headers (all fields are arrays of strings).
  - `message-id`: `["<1593128107394103160@mail.domain.com>"]`
  - `from`: `["\"Display Name\" <sender@domain.com>"]`
  - `to`: `["recipient@company.com"]`
  - `reply-to`: `["reply@domain.com"]`
  - `cc`: `["colleague@company.com"]`
  - `subject`: `["Inquiry Regarding Invoice #48102"]`
  - `x-mailer`: `["Outlook 16.0"]`, `["CALLEO V1.0"]`
  - `x-originating-ip`: `["[10.201.38.240]"]`
  - `fromHashed`, `toHashed`, `ccHashed`, `reply-toHashed`: MD5 hashed local-part arrays.
- **`normalizedHeader`**: Header values stripped of enclosing angle brackets (`<...>`) and display quotes.
- **`parsedAddresses`**: Structured dictionary containing normalized email addresses and MD5-hashed equivalents for `from`, `to`, and `cc`.

---

### 3.5. `filter` Object

Core policy, disposition, module analysis, and routing results:

#### Filter Status & Metadata
- **`qid`** *(String)*: Proofpoint sendmail queue ID (e.g., `"05PNWjCV024472"`, `"313u2wr2nk-1"`).
- **`startTime`** *(String)*: ISO 8601 filter start timestamp matching root `ts`.
- **`durationSecs`** *(Float)*: Processing time in seconds (e.g., `0.103299`, `0.842105`).
- **`routeDirection`** *(String)*: `"inbound"`, `"outbound"`, or `"internal"`.
- **`routes`** *(Array[String])*: Matched route profiles:
  - `default_inbound`, `default_outbound`, `allow_relay`, `firewallsafe`, `fruat`, `pp_spoofsafe`, `internalnet`, `nt_spoofsafe`.
- **`disposition`** *(String)*: Final disposition of the message:
  - `"continue"`: Allowed / passed through to recipient (may include modified headers).
  - `"discard"`: Dropped/quarantined with no delivery.
  - `"quarantine"`: Moved to quarantine folder.
  - `"reject"`: SMTP 5xx reject during session.
  - `"accept"`: Explicit internal system accept/relay.
- **`isMsgEncrypted`** *(Boolean)*: `true` if message body is encrypted/S-MIME, else `false`.
- **`isMsgReinjected`** *(Boolean)*: `true` if reinjected via policy routing, else `false`.
- **`quarantine`** *(Object)*: Quarantine routing details:
  - `folder`: `""`, `"Bulk"`, `"Spam"`, `"prerewrite_format"`, `"Phish"`.
  - `rule`: `""`, `"defaultinbound_bulk"`, `"capture_prerewrite"`, `"phish_quarantine"`.
- **`verified`** *(Object)*: `{"rcpts": ["user@company.com"], "rcptsHashed": ["<md5>@company.com"]}`.
- **`suborgs`** *(Object)*: Sub-organization mapping (e.g., `{"sender": "0", "rcpts": ["0"]}`).

---

#### Filter Actions Array (`filter.actions`)
Ordered execution array of policy decisions applied during evaluation. Each action object contains:
- `module`: `"access"`, `"pdr"`, `"spf"`, `"dkim"`, `"dmarc"`, `"av"`, `"spam"`, `"urldefense"`.
- `action`: `"continue"`, `"add-header"`, `"set-header"`, `"annotate-text"`, `"quarantine"`, `"discard"`, `"accept"`, `"set-spam-classifier"`, `"audit"`.
- `rule`: Rule identifier (e.g., `"pass"`, `"clean"`, `"xsourceip_header"`, `"EXTTagBody"`, `"defaultinbound_notspam"`, `"defaultinbound_bulk"`, `"system"`).
- `isFinal` *(Optional Boolean)*: `true` if this action terminated the message pipeline.

---

#### Filter Modules Object (`filter.modules`)
Detailed sub-engine evaluations:

##### 1. `spam` (Spam & ML Classifier Engine)
```json
"spam": {
  "version": {
    "engine": "8.12.0-2004280000",
    "definitions": "main-2311150137"
  },
  "triggeredClassifier": "bulk",  // Optional: present if classified as bulk, spam, phish, malware
  "langs": ["en", "es"],
  "scores": {
    "engine": 0,
    "overall": 0,
    "classifiers": {
      "spam": 0,        // 0 - 100
      "phish": 0,       // 0 - 100
      "malware": 0,     // 0 - 100
      "bulk": 100,      // 0 - 100
      "adult": 0,       // 0 - 100
      "impostor": 0,    // 0 - 100 (BEC score)
      "lowpriority": 0, // 0 - 100
      "suspect": 2,     // 0 - 100
      "mlx": 0,         // Machine learning overall score
      "mlxlog": 999,    // ML log score
      "cot": -2147483648 // Chain of Trust score (-2147483648 is default unset)
    }
  }
}
```

##### 2. `av` (Antivirus Engine)
- Present when scanned. Evaluates virus definitions. Actions map to `rule: "clean"` or `rule: "virus"`.

##### 3. `spf` (Sender Policy Framework)
- `domain`: Sender SPF domain (e.g., `"cloudmail.wageworks.com"`).
- `result`: `"pass"`, `"neutral"`, `"softfail"`, `"fail"`, `"none"`, `"permerror"`.

##### 4. `dkimv` (DKIM Verification Array)
- Array of objects: `[{"selector": "s1", "domain": "domain.com", "result": "pass"}]`.

##### 5. `dmarc` (DMARC Policy & Alignment)
- `srvid`: Protected domain (e.g., `"company.com"`).
- `filterdResult`: `"pass"`, `"fail"`, `"none"`, `"reject"`, `"quarantine"`.
- `authResults`: SPF and DKIM authentication traces.
- `alignment`: SPF and DKIM identity alignment results (`"strict"`, `"relaxed"`, `"fail"`).

##### 6. `urldefense` (Targeted Attack Protection / URL Defense)
- `version`: `{"engine": "15"}`
- `counts`: `{"total": 3, "unique": 3, "rewritten": 3, "noRewriteIsEmail": 0}`

##### 7. `zerohour` (Zero-Day Outbreak Detection)
- `score`: `"unknown"`, `"safe"`, `"suspicious"`.

##### 8. `pdr` (Proofpoint Dynamic Reputation)
- `v2`: `{"response": "pass"}` or `{"response": "reject"}`.

### 3.6. `msgParts` Array

Contains an object for every MIME body part and file attachment:

| Field Name | Type | Description | Examples |
| :--- | :--- | :--- | :--- |
| `structureId` | String | MIME hierarchical structure index. | `"0"`, `"1"`, `"1.1"` |
| `disposition` | String | Content disposition. | `"inline"`, `"attachment"` |
| `labeledName` | String | Filename as stated in MIME header. | `"text.html"`, `"invoice_Nov.pdf"`, `"payload.iso"` |
| `detectedName` | String | Filename detected by parser. | `"text.html"`, `"invoice_Nov.pdf"`, `"payload.iso"` |
| `labeledExt` | String | File extension from header. | `"html"`, `"pdf"`, `"xlsx"`, `"exe"`, `"txt"` |
| `detectedExt` | String | True detected file extension. | `"HTML"`, `"PDF"`, `"XLSX"`, `"EXE"`, `"TXT"` |
| `labeledMime` | String | Declared MIME type. | `"text/html"`, `"application/pdf"` |
| `detectedMime` | String | True detected MIME type. | `"text/html"`, `"application/pdf"` |
| `labeledCharset` | String | Charset declared. | `"UTF-8"`, `"ISO-8859-1"`, `"us-ascii"` |
| `detectedCharset` | String | Detected charset. | `"UTF-8"`, `"ISO-8859-1"`, `"us-ascii"` |
| `sizeDecodedBytes`| Integer | Decoded byte size. | `7322`, `451200` |
| `detectedSizeBytes`| Integer | Detected byte size. | `7322`, `451200` |
| `md5` | String | 32-character hex MD5 hash. | `"e736d3a19b1fadd8e9464eeaa8fba17b"` |
| `sha256` | String | 64-character hex SHA-256 hash. | `"d09491093ae43bad058933d37357d609829c064c89b829445f12c92d597a6810"` |
| `dataBase64` | String | Base64-encoded scalar ref pointer. | `"U0NBTEFSKDB4N2YyNzRkYjU0Y2E4KQ=="` |
| `textExtracted` | String | Base64-encoded scalar ref pointer. | `"U0NBTEFSKDB4N2YyNjU5MDMyZDk4KQ=="` |
| `isArchive` | Boolean | True if zip, tar, 7z, iso, gz. | `false`, `true` |
| `isProtected` | Boolean | True if password-protected. | `false`, `true` |
| `isCorrupted` | Boolean | True if file structure is damaged. | `false`, `true` |
| `isDeleted` | Boolean | True if part stripped by AV. | `false`, `true` |
| `isVirtual` | Boolean | Internal Proofpoint part representation. | `false`, `true` |
| `isTimedOut` | Boolean | True if sandbox analysis timed out. | `false`, `true` |
| `urls` | Array[Obj] | URLs extracted from this MIME part. | See structure below. |
| `metadata` | Object | HTML/Document meta tags. | `{"title": "Invoice", "generator": "MS Word"}` |

#### URL Defense Sub-Object (`msgParts[].urls[]`)
```json
{
  "url": "https://urldefense.com/v3/__http://phishing-site.com__;!!M9Lb!...",
  "src": ["urldefense"],
  "isRewritten": true,
  "notRewrittenReason": "isEmail"  // Present only when isRewritten is false (e.g., mailto links)
}
```

## 4. Timestamp & Dynamic Time Templating

Proofpoint event logs use ISO 8601 formatting with 6 decimal subsecond digits and a non-colon numeric timezone offset:
`YYYY-MM-DDTHH:MM:SS.ffffff±HHMM` (e.g., `2023-10-24T08:14:02.124589-0400`).

Both `ts` (root) and `filter.startTime` **must** match identically.

### Relative Time Template Tags
When generating dynamic scenarios, replace static timestamps with relative time tags:
- `##$TimeStamp-0d0h0m0s$##` -> Current event time (e.g., `2023-11-15T18:35:09.469140-0500`)
- `##$TimeStamp-0d1h15m0s$##` -> 1 hour, 15 minutes prior to scenario execution.
- `##$TimeStamp-0d0h0m30s$##` -> 30 seconds prior.

## 6. Key Constraints & Common Pitfalls

### Critical Schema Dependencies (Avoid Parsing Failures)
1. **JSON Escaping**: RFC 5322 header strings containing quotes or backslashes (e.g., `"from": ["\"Display Name\" <user@domain.com>"]`) must have nested double quotes escaped (`\"`).
2. **Hashed Identifier Pattern**: In Proofpoint POD logs, anonymized fields (`fromHashed`, `rcptsHashed`, `toHashed`, `ccHashed`) retain the original recipient domain:
   $$\text{<32-character hex MD5>} + \text{"@"} + \text{domain.com}$$
3. **Array Consistency in Headers**: All items inside `msg.header`, `msg.normalizedHeader`, and `msg.parsedAddresses` (e.g., `to`, `from`, `cc`, `subject`, `message-id`) must be arrays of strings, not bare strings, even when containing only one entry.
4. **Matching Timestamps**: The root `ts` string and `filter.startTime` must match identically.
5. **Disposition & Action Hierarchy**:
   - If `filter.disposition` is `"discard"`, at least one action inside `filter.actions` must specify `"action": "discard"` with `"isFinal": true`.
   - If quarantined, `filter.quarantine` must populate both `folder` and `rule` with corresponding non-empty strings.
6. **Classifier Score Defaults**: The `spam.scores.classifiers.cot` (Chain of Trust) classifier defaults to the 32-bit signed integer minimum `-2147483648` when not triggered. `mlxlog` is typically `999` or `991`.
7. **Perl Scalar Base64 References**: `dataBase64` and `textExtracted` in POD logs represent internal memory pointers (e.g., `SCALAR(0x7f273ed1eca8)` encoded into base64 as `"U0NBTEFSKDB4N2YyNzNlZDFlY2E4KQ=="`). Maintain this formatting for authentic parser emulation.
