# Comprehensive AI Generation Guide: Wiz Cloud Security Platform (`WIZ_IO`)

## 1. Overview & Log Purpose

The `WIZ_IO` log type represents security telemetry, audit trails, and configuration findings generated by the **Wiz Cloud Security Platform (Wiz.io)**. Wiz scans cloud environments (AWS, Azure, GCP, OCI, Kubernetes) using an agentless Security Graph model alongside the Wiz Runtime Sensor.

In production environments, telemetry labeled under `WIZ_IO` encompasses three primary sub-schemas emitted via Wiz API exports, Amazon S3 / Azure Blob audit exports, or Webhook/Automation Rule integrations:

1. **Wiz Audit Logs (Control Plane & API Activity)**: Tracks administrative and programmatic actions on the Wiz management tenant, including user interactive logins, service account authentication, token refreshes, report generation, API queries, and UI state updates.
2. **Wiz Security Findings / Issues (Graph Toxic Combinations & Posture Findings)**: Detailed security issues detected by the Wiz Security Graph, such as publicly exposed workloads with critical vulnerabilities, excessive IAM privileges, and compliance benchmark failures.
3. **Wiz Webhook / Automation Action Notifications**: Event-driven notification payloads dispatched to SIEMs (Splunk, Microsoft Sentinel), ticketing systems (Jira, ServiceNow), or SOAR platforms when an issue is created, modified, or resolved.
4. *(Contextual Correlation Note)*: Upstream Identity Provider (IdP) logs (e.g., Okta SSO events targeting the Wiz Dashboard) are frequently bundled or co-routed in ingestion pipelines under this label to provide full authentication traceability.

---

## 2. Format Specification

| Attribute | Specification |
| :--- | :--- |
| **Structure** | Standard JSON (RFC 8259). |
| **Delivery Model** | Single-line Newline Delimited JSON (NDJSON) per event. |
| **Character Encoding** | UTF-8. |
| **Delimiters & Quotes** | Double quotes (`"`) around keys and string values. Raw newlines inside markdown fields (such as `description` or `resolutionRecommendation`) must be escaped as `\n`. |
| **Null Representation** | Explicit JSON `null` for non-applicable or empty fields (e.g., `"serviceAccount": null`, `"user": null`, `"dueAt": null`). |

## 3. Schema Breakdown & Fields

Because `WIZ_IO` events belong to three main operational variants, generators must select the appropriate schema structure based on the desired event type.

---

### Sub-Schema A: Wiz Audit Log (API, Auth, & Administrative Events)

Tracks interaction with the Wiz tenant and GraphQL API.

#### Top-Level Fields

| Field Name | Type | Description / Constraints |
| :--- | :--- | :--- |
| `id` | String (UUIDv4) | Unique event identifier (e.g., `51e8c110-0b0e-4c20-88f9-76da40ee52ab`). |
| `requestId` | String (UUIDv4) | Unique trace ID for the API request; matches `id` for direct authentication events. |
| `action` | String | Action verb: `Login`, `TokenRefresh`, `Report`, `UpdateUIUserPreferences`, `CreateUser`, `DeleteUser`, `RunQuery`, `UpdateIntegration`. |
| `status` | String | Execution outcome: `SUCCESS`, `FAILURE`. |
| `timestamp` | String (ISO 8601 UTC) | Microsecond timestamp: `YYYY-MM-DDTHH:mm:ss.SSSSSSZ`. |
| `userAgent` | String \| null | Client user-agent string (e.g., `Mozilla/5.0...`, `python-urllib3/2.0.7`, or `null`). |
| `sourceIP` | String \| null | IPv4/IPv6 client address or `null` if internal. |
| `serviceAccount` | Object \| null | Populated when an API service account acts; `null` for human user events. |
| `user` | Object \| null | Populated when an SSO/human user acts; `null` for machine actions. |
| `actionParameters`| Object | Dynamic dictionary containing parameters specific to the `action`. |

#### Nested Objects

* **`user`**:
  * `id`: String (e.g., user email or internal ID: `wxy-abc@whirlpool.com`).
  * `name`: String (e.g., user email address).
* **`serviceAccount`**:
  * `id`: String (50+ alphanumeric string, e.g., `j32bupvedvdcfek3vzv4qpiqyid22grc7r3v3o4n26kjq2i2yemhg`).
  * `name`: String (e.g., `Cribl_SA`, `Silk Integration Production`, `Splunk_Ingest`).
* **`actionParameters` (Common Variations)**:
  * *For `Login` / `TokenRefresh`*:
    * `clientID`: String (OAuth/Cognito client identifier).
    * `name`: String (Display name or service account name).
    * `role`: String enum (`GLOBAL_ADMIN`, `GLOBAL_READER`, `PROJECT_ADMIN`, `PROJECT_READER`, `SECURITY_ANALYST`, or `""`).
    * `scopes`: Array of strings (e.g., `["read:issues", "read:vulnerabilities", "admin:audit"]` or `["read:all", "write:all", "admin:all"]`).
    * `products`: Array of strings (`["*"]` or list of product UUIDs).
    * `groups`: Array of strings or `null`.
    * `userpoolID`: String (e.g., `eu-central-1_o7tMA7z6W`, `us-east-2_xOqhEQUyJ`).
    * `userID`: String (same as user/SA ID).
    * `userEmail`: String (user email or empty for service accounts).

---

### Sub-Schema B: Wiz Security Issue / Finding (Toxic Combinations & Posture)

Exported findings representing graph correlations (cloud misconfigurations + vulnerabilities + identities + network exposure).

#### Top-Level Fields

| Field Name | Type | Description |
| :--- | :--- | :--- |
| `id` | String (UUIDv4) | Unique ID of the security issue. |
| `type` | String | Finding classification: `TOXIC_COMBINATION`, `VULNERABILITY`, `CLOUD_CONFIGURATION`, `DATA_SENSITIVITY`. |
| `severity` | String | Finding severity: `CRITICAL`, `HIGH`, `MEDIUM`, `LOW`, `INFORMATIONAL`. |
| `status` | String | Lifecycle state: `OPEN`, `RESOLVED`, `IN_PROGRESS`, `REJECTED`. |
| `createdAt` | String (ISO 8601 UTC) | Timestamp finding was first detected: `YYYY-MM-DDTHH:mm:ss.SSSSZ`. |
| `updatedAt` | String (ISO 8601 UTC) | Timestamp finding was last re-scanned/updated. |
| `statusChangedAt`| String (ISO 8601 UTC) | Timestamp of last status change. |
| `dueAt` | String (ISO 8601 UTC) \| null | SLA deadline timestamp or `null`. |
| `resolvedAt` | String (ISO 8601 UTC) \| null | Remediation timestamp or `null`. |
| `project` | Object \| null | Wiz project scope (or `null` if global). |
| `notes` | Array | Analyst notes (typically empty array `[]`). |
| `serviceTickets`| Array \| null | Linked Jira/ServiceNow tickets or `null`. |
| `control` | Object | Full metadata on the violated security rule. |
| `sourceRule` | Object | Identifier and name of the underlying rule. Contains `id` and `name`. |
| `entitySnapshot`| Object | Comprehensive snapshot of the affected cloud resource. |

#### Nested Objects

* **`control`**:
  * `id`: String (Wiz control ID, e.g., `wc-id-1397`, `abc123`).
  * `name`: String (Descriptive title of the control).
  * `description`: Escaped markdown explaining the threat vector.
  * `resolutionRecommendation`: Escaped markdown with remediation steps.
  * `securitySubCategories`: Array of framework mappings containing `{ "title": "...", "category": { "name": "...", "framework": { "name": "..." } } }`. Common frameworks: `CIS Controls v8`, `NIST SP 800-53 Revision 5`, `MITRE ATT&CK Matrix`, `ISO/IEC 27001-2022`, `NIS2 Directive (Article 21)`, `Digital Operational Resilience Act (DORA)`.
* **`entitySnapshot`**:
  * `id`: String (UUID or CSP-generated ID).
  * `type`: Asset type (`CONTAINER`, `COMPUTE_INSTANCE_GROUP`, `VIRTUAL_MACHINE`, `SERVICE_ACCOUNT`, `BUCKET`, `SERVERLESS`).
  * `nativeType`: Cloud native resource descriptor (`hostedContainer`, `spotinstSyntheticInstanceGroup`, `ServiceAccount`, `ec2:instance`).
  * `name`: Resource name or tag.
  * `status`: Resource operational status (`Active`, `Running`, or `null`).
  * `cloudPlatform`: Hosting cloud (`AWS`, `Azure`, `GCP`, `OCI`, `Kubernetes`).
  * `providerId`: CSP identifier/ARN (e.g., `arn:aws:iam::...` or full external path).
  * `region`: Cloud region (`us-east-1`, `eu-west-1`, etc.).
  * `subscriptionExternalId`: Cloud account/subscription ID (AWS Account ID, Azure Subscription UUID, OCI Tenancy OCID).
  * `subscriptionName`: Logical name of the account/subscription.
  * `tags`: Key-value map of cloud/container metadata tags.
  * `externalId`: Native infrastructure reference ID.

---

### Sub-Schema C: Wiz Webhook / Automation Action Notification

Fired by Wiz Automation Rules when issues transition states.

#### Top-Level Fields

* **`trigger`**:
  * `source`: Source string: `"DETECTIONS"` (for security detections / runtime findings) or `"ISSUE"` (for posture/configuration findings). Note: Chronicle's parser maps `metadata.product_event_type = trigger.source`. Curated detection rules (e.g. `wiz_io: MEDIUM Detection`) explicitly require `trigger.source = "DETECTIONS"`.
  * `type`: Trigger event: `"Created"`, `"Updated"`, `"Resolved"`.
  * `ruleId`: UUIDv4 string of the Automation Rule.
  * `ruleName`: String (e.g., `"Send High/Critical to SIEM"`, `"my-rule"`).
  * `updatedFields`: Human-readable diff string summarizing the mutation (e.g., `" status field was changed from OPEN to RESOLVED,  resolutionReason field was changed from null to OBJECT_DELETED, "`).
  * `changedBy`: String (typically `"Wiz"` or a user email).
* **`issue`**:
  * `id`: UUIDv4 string of the Wiz Issue.
  * `status`: `"OPEN"` or `"RESOLVED"`.
  * `severity`: `"CRITICAL"`, `"HIGH"`, `"MEDIUM"`, `"LOW"`, `"INFORMATIONAL"`.
  * `created`: ISO 8601 UTC timestamp (`YYYY-MM-DDTHH:mm:ss.SSSSSSZ`).
  * `projects`: String or array of Wiz project IDs.
* **`resource`**:
  * `id`: CSP resource ID / ARN / URI.
  * `name`: Cloud resource name.
  * `type`: Resource category (e.g., `oci#vcn`, `compute.virtualmachines`, `s3#bucket`).
  * `cloudPlatform`: `"AWS"`, `"Azure"`, `"GCP"`, `"OCI"`, `"Kubernetes"`.
  * `subscriptionId`: Account / Project / Subscription ID.
  * `subscriptionName`: Name of the cloud account.
  * `region`: Cloud region (e.g., `"us-ashburn-1"`).
  * `status`: `"Active"`, `""`, etc.
  * `cloudProviderURL`: Direct link to the CSP management console.
* **`control`**:
  * `id`: Wiz Control ID (`wc-id-2787`, UUIDv4, etc.).
  * `name`: String control title.
  * `description`: Control overview.
  * `severity`: Severity string (`"HIGH"`, etc.).
  * `IssueURL`: Deep link back to the Wiz Portal: `https://app.wiz.io/issues#~(issue~'<UUID>')`.
  * `risks`: Array of specific risk tags (e.g., `["EXPOSURE", "DATA_LEAK"]`).

## 4. Timestamp & Dynamic Time Templating

Wiz timestamps are strictly formatted in UTC with trailing `Z` and fractional seconds:
- **Audit Logs**: 6 decimal places (microsecond precision): `YYYY-MM-DDTHH:mm:ss.SSSSSSZ`
- **Issue & Webhook Logs**: 4 to 6 decimal places: `YYYY-MM-DDTHH:mm:ss.SSSSZ` or `YYYY-MM-DDTHH:mm:ss.SSSSSSZ`

### Dynamic Relative Time Tags
When generating logs, never use static dates. Use dynamic time tags:

| Format Required | Placeholder Syntax | Output Interpretation |
| :--- | :--- | :--- |
| ISO 8601 (Microsecond UTC) | `##$TimeStamp-0d0h10m0s$##` | Evaluates to `2024-03-24T14:22:01.123456Z` |
| ISO 8601 (Finding Created) | `##$TimeStamp-3d2h0m0s$##` | Evaluates to relative time 3 days, 2 hours ago |
| ISO 8601 (Finding Updated) | `##$TimeStamp-0d1h15m0s$##` | Evaluates to relative time 1 hour, 15 min ago |
| ISO 8601 (Future SLA Due Date) | `##$TimeStamp+30d0h0m0s$##`| Evaluates to relative future date 30 days out |

## 6. Key Constraints & Common Pitfalls

1. **Strict Mutual Exclusivity between `user` and `serviceAccount`**:
   - In Audit logs (`action: Login`, `Report`, etc.), if a service account acts, `"serviceAccount": {"id": "...", "name": "..."}` is populated and `"user": null`.
   - If a human user acts, `"user": {"id": "...", "name": "..."}` is populated and `"serviceAccount": null`.
   - Failing to set the opposing entity to `null` causes JSON schema validation errors in ingest parsers.
2. **Escaped Markdown Formatting in Control Fields**:
   - Fields such as `control.description` and `control.resolutionRecommendation` contain multi-line markdown strings. All inner linebreaks must be escaped as literal `\n`, never actual physical returns. Physical returns break NDJSON parsers.
   - Internal quotes within markdown (e.g., `"least privilege"`) must be escaped as `\"`.
3. **Trigger Updates Formatting in Webhook Payloads**:
   - The field `trigger.updatedFields` is a concatenated human-readable diff string terminated by spaces and commas:
     `" status field was changed from <OLD> to <NEW>,  <fieldName> field was changed from <OLD> to <NEW>, "`
4. **Wiz Severity & Status Values**:
   - Severities are strictly upper-case: `"CRITICAL"`, `"HIGH"`, `"MEDIUM"`, `"LOW"`, `"INFORMATIONAL"`.
   - Audit status is `"SUCCESS"` or `"FAILURE"`.
   - Issue status is `"OPEN"`, `"IN_PROGRESS"`, `"RESOLVED"`, or `"REJECTED"`.
5. **No Mixed Encodings**:
   - Do not wrap the JSON object in Syslog headers (e.g., `<13>1 2024-...`) unless an explicit intermediate Syslog forwarder layer is requested. Native Wiz exports are raw, pure JSON documents.
