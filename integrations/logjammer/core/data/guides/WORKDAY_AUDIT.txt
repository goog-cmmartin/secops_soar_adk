# Workday Audit Log (`WORKDAY_AUDIT`) Generation Playbook

## 1. Overview & Log Purpose
`WORKDAY_AUDIT` logs capture authentication, user activity, access delegation, and administrative proxy events within the **Workday Enterprise Management Cloud**. These logs originate from Workday's Report-as-a-Service (RaaS) Signon Audit exports and SIEM integration pipelines (e.g., Splunk Add-on for Workday, AWS S3 export plugins, or Kafka streams). 

Key activities recorded include:
- Interactive user sign-ins via SSO/SAML, Biometric (Mobile), DID (Decentralized Identity), or Direct Credentials.
- Authentication failures, lockouts, and access denials.
- User proxy/impersonation events (e.g., Help Desk or HR Administrators assuming worker accounts).
- Tenant owner / system administrator direct access sessions.
- Session termination, client environment details, and TLS negotiation metadata.

---

## 2. Format Specification
- **Classification**: Comma-Separated Values (CSV) / Delimited Flat File.
- **Record Delimiter**: Standard newline (`\n` or `\r\n`).
- **Field Delimiter**: Comma (`,`).
- **Quoting Rules**: **Strict Full Quoting**. Every single column—including empty strings, numeric values, and boolean flags—**must** be enclosed in double quotes (`"`).
- **Fixed Column Count**: Exactly **18 columns** per record.

| Index | Field Name | Data Type | Required | Description & Valid Values |
|:---:|:---|:---:|:---:|:---|
| **0** | `tenant_environment` | String | Yes | Workday tenant name or environment identifier. Examples: `"PROD"`, `"SBX"`, `"DEV"`, `"UAT"`, `"IMPL"`, or custom tenant aliases like `"example1"`. |
| **1** | `session_signature` | String | Yes | Unique composite key constructed as: `"<Session Actor>: <YYYY MM DD HH MM SS mmm -ZZZZ>"`. |

| **7** | `session_end_time` | Timestamp | Optional | ISO 8601 sign-off timestamp (`YYYY-MM-DDTHH:MM:SS±HH:MM`) if the session has concluded; otherwise empty string (`""`). |

| **9** | `is_system_account` | Enum (String) | Yes | Flag indicating tenant admin/system-level account access. Values: `"Y"`, `"N"`. |

## 4. Timestamp & Dynamic Time Templating

Workday audit logs utilize two distinct timestamp formats within a single event line:

1. **Composite Session Signature Timestamp (Field Index 1)**: Space-separated year, month, day, hour, minute, second, 3-digit millisecond, and 4-digit timezone offset (`YYYY MM DD HH MM SS mmm -ZZZZ`).
   - Template: `##$TimeStamp-<offset>|%Y %m %d %H %M %S %3f %z|<timezone_offset>$##`
   - Example (`-08:00`): `##$TimeStamp-0d0h10m0s|%Y %m %d %H %M %S %3f %z|-08:00$##` -> `2026 08 24 11 15 00 123 -0800`

2. **Event & Session End Timestamps (Field Indices 3 and 7)**: ISO 8601 format with colon-delimited timezone offset (`YYYY-MM-DDTHH:MM:SS±HH:MM`).
   - Template: `##$TimeStamp-<offset>|%Y-%m-%dT%H:%M:%S%:z|<timezone_offset>$##`
   - Example (`-08:00`): `##$TimeStamp-0d0h10m0s|%Y-%m-%dT%H:%M:%S%:z|-08:00$##` -> `2026-08-24T11:15:00-08:00`

## 6. Key Constraints & Pitfalls

1. **Exact 18-Column Array**:
   - Parsers depend on exact column indexing. Omitting an empty field (e.g., omitting `""` for `session_end_time` or `failure_reason`) will shift columns and break field mapping.
2. **Double Quotes Everywhere**:
   - Every column must be wrapped in `""`. Raw unquoted values like `PROD` or `1` will cause ingestion errors on strict CSV collectors.
3. **Actor vs. Target Worker Consistency**:
   - When generating standard user logins, `session_actor` contains `"<ID> / <Name>"` and `target_worker_name` contains `"<Name>"`.
   - When generating proxy events, `session_actor` follows `"<Admin> on behalf of <Target>"` and `target_worker_name` contains the target's display name.
   - For system accounts (e.g., `wd-tenantowner`), both `target_worker_name` and `organization_name` must be empty strings `""`.
4. **Timestamp Synchronization**:
   - The time components (Year, Month, Day, Hour, Minute, Second) in Field 1 and Field 3 **must match** identically within the same log line. Field 1 adds milliseconds (`%3f`) and uses space separation with `%z` (`-0800`), while Field 3 uses standard ISO 8601 with `%:z` (`-08:00`).
