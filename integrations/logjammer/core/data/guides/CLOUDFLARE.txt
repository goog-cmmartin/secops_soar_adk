# Cloudflare Log Generation Playbook

## 1. Overview & Log Purpose
Cloudflare acts as a global reverse proxy, content delivery network (CDN), web application firewall (WAF), Zero Trust Secure Web Gateway (SWG), and cloud access security broker (CASB). 

Cloudflare logs provide telemetry across edge processing, threat mitigation, identity access, DNS filtering, network tunneling, and administrative operations:
* **HTTP Requests (Edge Logpush)**: Inbound web traffic passing through Cloudflare edge nodes, capturing client metadata, SSL negotiation, origin routing, cache status, WAF triggers, bot scores, and custom firewall rules.
* **Zero Trust Gateway (DNS, HTTP, Network/L4)**: Egress traffic inspection and policy enforcement for managed enterprise endpoints and WARP clients.
* **Cloudflare Access**: Identity-aware proxy authentication, authorization decisions, application launches, and session validation.
* **Audit Logs**: Administrative changes executed within the Cloudflare dashboard or via API (zone updates, certificate deployments, firewall rule adjustments).
* **CASB & Posture Findings**: Security posture discoveries, permission escalations, and 3rd-party SaaS configuration posture violations.
* **Cloud Platform Wrappers**: Cloudflare Logpush piped into cloud-native logging infrastructures (e.g., Google Cloud Logging wrapping `jsonPayload`).

---

## 2. Format Specification
* **Data Format**: Single-line JSON (NDJSON / JSON Lines).
* **Delimiters**: Comma-delimited key-value pairs enclosed in curly braces `{}`.
* **String Quoting**: Standard JSON double quotes (`"key": "value"`).
* **Path / URI Escaping**: Standard forward slashes `/` or escaped forward slashes `\/` (commonly emitted in standard Logpush outputs).
* **Array Fields**: Multi-value match elements (such as `FirewallMatchesActions`, `FirewallMatchesRuleIDs`, `FirewallMatchesSources`, `QueryCategoryIDs`, `DownloadedFileNames`) must be JSON arrays: `["allow"]` or `[26, 81]`.
* **Nested Structures**: Complex metadata (e.g., `RequestHeaders`, `Metadata`, `NewValue`, `OldValue`, `AssetMetadata`) are nested JSON sub-objects.

### B. Zero Trust Gateway Logs (DNS, HTTP, Network/L4)

#### 1. Gateway DNS
* **`Datetime`**: ISO 8601 UTC timestamp.
* **`ColoID`**: Numeric edge PoP ID (e.g., `26`, `493`).
* **`SrcIP` / `SrcPort`**: Client source IP and port.
* **`DstIP` / `DstPort`**: Resolver destination IP (`172.64.36.1`, `1.1.1.1`) and port (`53`, `853`).
* **`Protocol`**: `udp`, `tcp`, `tls`, `https`.
* **`QueryName` / `QueryNameReversed`**: Queried FQDN (`beacons.gcp.gvt2.com`) and reverse notation (`com.gvt2.gcp.beacons`).
* **`QueryType`**: Numeric DNS Record Type (`1` = A, `28` = AAAA, `5` = CNAME, `15` = MX).
* **`ResolverDecision`**: Decision outcome (`allowedOnNoPolicyMatch`, `blockedByRule`, `override`).
* **`QueryCategoryIDs`**: Array of matched content/threat categories (e.g., `[26, 81]`).
* **`DeviceID` / `UserID` / `Email`**: Zero Trust client identifiers.

#### 2. Gateway HTTP / Proxy
* **`AccountID`**: 32-char hex string.
* **`Action`**: `allow`, `block`, `bypass`, `isolate`.
* **`URL` / `HTTPHost` / `HTTPMethod`**: Inspected target URL and HTTP attributes.
* **`PolicyID`**: UUID string (`f3c1701a-36b2-4210-ac1b-5f47c4a397fa`).
* **`DeviceID` / `DeviceName` / `UserID` / `Email`**: Client endpoint and identity tracking.
* **`BlockedFileHash` / `BlockedFileName` / `BlockedFileSize`**: Malware/DLP attributes.

#### 3. Gateway L4 / Network Sessions
* **`Transport` / `Protocol`**: `tcp`, `udp`, `icmp`, `TCP`, `UDP`, `ICMP`.
* **`SourceIP` / `SourcePort`**: Outbound client source.
* **`DestinationIP` / `DestinationPort`**: Remote destination server endpoint.
* **`SNI`**: Server Name Indication (`wss-primary.slack.com`, `help.teams.cloudflare.com`).
* **`Action`**: `allowedByRule`, `allowedOnNoRuleMatch`, `blockedByRule`.
* **`BytesSent` / `BytesReceived`**: Traffic accounting metrics.
* **`SessionStartTime` / `SessionEndTime`**: ISO 8601 session duration markers.
* **`ConnectionCloseReason`**: `CLIENT_CLOSED`, `SERVER_CLOSED`, `RULE_BLOCKED`, `TIMEOUT`.

---

### C. Cloudflare Access (Identity & Login)
* **`Action`**: `login`, `logout`, `verify`.
* **`Allowed`**: Boolean (`true`, `false`).
* **`AppDomain`**: Protected application FQDN (e.g., `preligens.cloudflareaccess.com/warp`).
* **`AppUUID`**: UUID of Access Application.
* **`Connection`**: Identity provider type (`saml`, `oidc`, `google`, `okta`, `azureAD`).
* **`Email` / `UserUID`**: Authenticated corporate user identity.
* **`IPAddress` / `Country`**: Source connection properties.
* **`CreatedAt`**: ISO 8601 timestamp.

---

### D. Audit Logs (Administrative Operations)
* **`ActionType`**: Action string (`gateway_create`, `delete_requested`, `zone_create`, `dns_record_update`).
* **`ActionResult`**: Boolean (`true`, `false`).
* **`ActorEmail` / `ActorID` / `ActorIP` / `ActorType`**: Identity performing the action (`user`, `system`, `api_token`).
* **`Interface`**: `API`, `UI`.
* **`ResourceType`**: Cloudflare object affected (`gateway.rule`, `certificate_pack`, `dns_record`, `firewall_rule`).
* **`ResourceID`**: Identifier of the modified resource.
* **`NewValue` / `OldValue`**: Nested JSON objects representing state changes.
* **`When`**: ISO 8601 UTC timestamp.

## 4. Timestamp & Dynamic Time Templating

Cloudflare logs primarily use **ISO 8601 UTC string format (`YYYY-MM-DDTHH:MM:SSZ`)**, with occasional nano-precision timestamps or Unix epoch timestamps.

When generating synthetic scenarios, use the following replacement variables:
* Standard UTC ISO 8601: `##$TimeStamp-0d0h0m0s$##` (Evaluates to: `YYYY-MM-DDTHH:MM:SSZ`)
* Fractional Seconds UTC: `##$TimeStampIso8601_Nano-0d0h0m0s$##` (Evaluates to: `YYYY-MM-DDTHH:MM:SS.NNNNNNNNNZ`)
* Unix Epoch Seconds: `##$Epoch-0d0h0m0s$##`
* Unix Epoch Nanoseconds: `##$EpochNano-0d0h0m0s$##`

### Temporal Consistency Rules:
1. `EdgeStartTimestamp` must be equal to or slightly precede `EdgeEndTimestamp` (typically `0` to `5` seconds difference).
2. For Gateway sessions, `SessionStartTime` must precede `SessionEndTime`.
3. GCP log wrapper `timestamp` matches `jsonPayload.EdgeStartTimestamp`, while `receiveTimestamp` is `1` to `300` seconds in the future.

## 6. Key Constraints & Pitfalls

1. **Strict JSON Types**:
   - `EdgeResponseStatus`, `ClientRequestBytes`, `EdgeResponseBytes`, `ClientSrcPort`, `OriginResponseStatus` **MUST** be numeric integers, not strings.
   - `FirewallMatchesActions`, `FirewallMatchesRuleIDs`, and `FirewallMatchesSources` **MUST** be JSON arrays (e.g. `[]` or `["allow"]`). Never serialize them as comma-separated strings inside a single string key.
2. **Blocked vs. Served Status Alignment**:
   - If `FirewallMatchesActions` contains `"block"` or `"drop"`, `EdgeResponseStatus` must reflect a blocked status code (typically `403`), and `OriginIP` / `OriginResponseStatus` should typically be empty (`""`) and `0`.
3. **Empty Value Representation**:
   - Cloudflare logs emit explicit empty strings `""` for unpopulated string fields, `0` for unpopulated integers, and `{}` / `[]` for empty complex objects. Do not use JSON `null` unless simulating API object payloads like `OldValue` / `NewValue`.
4. **Hex String Formats**:
   - `RayID` is a 16-character hexadecimal string (`^[0-9a-f]{16}$`).
   - `PolicyID`, `DeviceID`, `UserID` in Zero Trust records are 36-character standard UUID strings.
5. **Escape Sequences in URIs & User Agents**:
   - Ensure special characters in `ClientRequestURI`, `ClientRequestUserAgent`, and `WAFMatchedVar` (e.g., quotes `"`, backslashes `\`, control characters) are correctly escaped to prevent invalid JSON payloads.
