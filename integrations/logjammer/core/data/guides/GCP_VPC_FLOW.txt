# AI Generation Guide: GCP VPC Flow Logs (`GCP_VPC_FLOW`)

## 1. Overview & Log Purpose

Google Cloud Platform (GCP) Virtual Private Cloud (VPC) Flow Logs record network traffic flows sent from or received by Compute Engine Virtual Machine (VM) instances, Google Kubernetes Engine (GKE) nodes, and managed services within a VPC network. 

VPC Flow Logs sample network traffic at the virtual network interface (vNIC) layer. These logs provide visibility into:
- **Intra-VPC & Inter-VPC Traffic**: Communication between internal instances, GKE pods, and services.
- **Egress & Ingress Traffic**: Traffic entering or exiting the VPC via External IPs, Cloud NAT, Cloud VPN, Cloud Interconnect, or Google Cloud Load Balancers (GCLB).
- **Google Services Traffic**: Traffic to and from Google APIs and Private Google Access endpoints.
- **Security Use Cases**: Detection of network reconnaissance/port scanning, command and control (C2) beaconing, lateral movement, unauthorized external egress / data exfiltration, protocol anomalies, and cryptomining traffic.

---

## 2. Format Specification

- **Envelope Format**: Google Cloud Logging `LogEntry` structure serialized as a single-line JSON object (`RFC 8259`).
- **Log Name**: `projects/<project_id>/logs/compute.googleapis.com%2Fvpc_flows` (URL-encoded log identifier).
- **Resource Type**: `gce_subnetwork` (monitored resource representing the GCP subnetwork where logging is enabled).
- **Quoting & Typing Rules**:
  - Top-level metadata keys (`insertId`, `logName`, `timestamp`, `receiveTimestamp`) and string metrics (`bytes_sent`, `packets_sent`, `rtt_msec`) are strictly **quoted strings**.
  - `connection.protocol`, `connection.src_port`, and `connection.dest_port` are **integers** (or occasionally serialized as numeric floats like `6.0` depending on ingestion parsers).
  - Conditional objects (e.g., `src_location`, `dest_location`, `src_gke_details`, `load_balancing`) are omitted or populated based on flow context.

---

## 3. Schema Breakdown & Fields

### 3.1. Top-Level GCP `LogEntry` Metadata Envelope

| Field | Type | Description | Realistic Values / Format |
|---|---|---|---|
| `insertId` | String | Unique log entry identifier (used for deduplication). | Random alphanumeric string, 14–16 chars (e.g., `1wjp1y9f8vc6y6`, `16sctcmepgsuz`). |
| `logName` | String | Fully qualified resource path for VPC flow logs. | `projects/<project-id>/logs/compute.googleapis.com%2Fvpc_flows` |
| `timestamp` | String | Time the log event was generated by the VPC logging agent. | ISO 8601 with fractional seconds (e.g., `2024-03-07T17:45:19.278328082Z`). |
| `receiveTimestamp`| String | Time the log was received by the Cloud Logging ingest system. | ISO 8601 UTC (typically 0–5 seconds after `timestamp`). |
| `resource.type` | String | Monitored resource type. | Always `"gce_subnetwork"`. |
| `resource.labels` | Object | Resource identification labels. | Sub-keys: `project_id`, `location` (region/zone), `subnetwork_id` (numeric string), `subnetwork_name`. |
| `jsonPayload` | Object | VPC flow payload containing network details. | See Section 3.2. |

---

### 3.2. `jsonPayload` Core Fields

#### Aggregation Metrics & Timestamps
- `start_time` (String / ISO 8601 UTC): Start of the sampling interval for this 5-tuple aggregation.
- `end_time` (String / ISO 8601 UTC): End of the sampling interval (typically 5 to 30 seconds after `start_time`).
- `bytes_sent` (String): Total bytes transmitted in this aggregated window (e.g., `"0"`, `"8792"`, `"67897602"`).
- `packets_sent` (String): Total packets transmitted in this aggregated window (e.g., `"2"`, `"56"`, `"76800"`).
- `reporter` (String): Indicates which endpoint reported the flow:
  - `"SRC"`: Flow reported by the sending VM/node interface.
  - `"DEST"`: Flow reported by the receiving VM/node interface.
- `rtt_msec` (String, Optional): TCP round-trip time in milliseconds (e.g., `"6"`, `"20"`). Only present for TCP traffic with valid RTT measurements.

#### Connection Object (`connection`)
- `src_ip` (String): Source IPv4 address (RFC 1918 private IP or public IP).
- `dest_ip` (String): Destination IPv4 address.
- `protocol` (Integer): IANA IP protocol number:
  - `6`: TCP
  - `17`: UDP
  - `1`: ICMP
  - `50`: ESP (IPsec)
  - `58`: ICMPv6
- `src_port` (Integer, Conditional): Source transport port (1–65535). Omitted for ICMP/ESP.
- `dest_port` (Integer, Conditional): Destination transport port (1–65535). Omitted for ICMP/ESP.

---

### 3.3. Contextual Sub-Objects in `jsonPayload`

#### 1. Instance Metadata (`src_instance` / `dest_instance`)
Populated when the source or destination is a Compute Engine VM or GKE Node within GCP:
- `project_id` (String): GCP project owning the VM.
- `region` (String): GCP region (e.g., `us-central1`, `europe-west4`, `asia-east1`).
- `zone` (String): GCP zone (e.g., `us-central1-a`, `europe-west4-b`).
- `vm_name` (String): Instance name (e.g., `web-frontend-01`, `gke-cluster-node-9881920c-fnkw`).
- `managed_instance_group` (Object, Optional): `{ "name": "...", "zone": "..." }`.

#### 2. VPC Metadata (`src_vpc` / `dest_vpc`)
- `project_id` (String): GCP project owning the VPC network.
- `vpc_name` (String): VPC network name (e.g., `default`, `prod-vpc`, `vpc-internal`).
- `subnetwork_name` (String): Subnet name (e.g., `default`, `subnet-k8s-us-central1`).
- `subnetwork_region` (String, Optional): Subnet region.

#### 3. GeoIP / External Location Metadata (`src_location` / `dest_location`)
Populated when interacting with public Internet IP addresses:
- `asn` (Integer): Autonomous System Number (e.g., `15169`, `13335`, `4134`).
- `country` (String): ISO 3-letter lowercase country code (e.g., `usa`, `chn`, `deu`, `jpn`, `gbr`).
- `continent` (String): Continent name (e.g., `America`, `Asia`, `Europe`).
- `region` (String, Optional): State/Province/Region name (e.g., `California`, `Lombardy`, `Zhejiang`).
- `city` (String, Optional): City name (e.g., `Mountain View`, `Milan`, `Hangzhou`, `Naha`).

#### 4. GKE / Kubernetes Metadata (`src_gke_details` / `dest_gke_details`)
Populated when traffic involves GKE Workload Pods:
- `cluster.cluster_name` (String): GKE Cluster name.
- `cluster.cluster_location` (String): GKE Cluster zone or region.
- `pod.pod_name` (String): Kubernetes pod name (e.g., `frontend-7d84878b9b-9s2jl`).
- `pod.pod_namespace` (String): Namespace (e.g., `default`, `kube-system`, `production`).
- `pod.workload.name` (String, Optional): Workload controller name.
- `pod.workload.type` (String, Optional): `DEPLOYMENT`, `STATEFUL_SET`, `DAEMON_SET`, `JOB`.
- `service` (Array of Objects, Optional): `[{"service_name": "...", "service_namespace": "..."}]`.

#### 5. Google Service Context (`src_google_service` / `dest_google_service`)
- `type` (String): Typically `"GOOGLE_API"` when accessing GCP APIs via Private Google Access.

#### 6. Load Balancing Metadata (`load_balancing`)
- `backend_group_name` (String): Name/Hash of target pool or instance group.
- `backend_group_type` (String): `TARGET_POOL`, `INSTANCE_GROUP`, `NEG`.
- `forwarding_rule_name` (String): Forwarding rule resource name.
- `forwarding_rule_project_id` (String): Project hosting the load balancer.
- `reporter` (String): `BACKEND` or `PROXY`.
- `scheme` (String): `EXTERNAL`, `INTERNAL`, `INTERNAL_MANAGED`.
- `type` (String): e.g., `PASSTHROUGH_NETWORK_LOAD_BALANCER`, `APPLICATION_LOAD_BALANCER`.

## 4. Timestamp & Dynamic Time Templating

VPC Flow Logs utilize UTC ISO 8601 timestamps formatted to microsecond or nanosecond precision:
`YYYY-MM-DDTHH:MM:SS.NNNNNNNNNZ`

### Flow Log Timing Model:
- **`start_time`**: Beginning of flow sampling window (e.g., `T - 15s`).
- **`end_time`**: End of flow sampling window (e.g., `T - 0s`).
- **`timestamp`** & **`receiveTimestamp`**: Log export / ingestion time (typically `T + 1s` to `T + 5s` relative to `end_time`).

### Relative Time Template Tags:
Use the standard macro format `##$TimeStamp-<offset>$##` to represent timestamps dynamically:

- Flow Window Start: `##$TimeStamp-0d0h0m25s$##`
- Flow Window End: `##$TimeStamp-0d0h0m10s$##`
- Ingestion Timestamp: `##$TimeStamp-0d0h0m05s$##`

## 6. Key Constraints & Common Generation Pitfalls

1. **Strict String Typing for Metric Integers**:
   - `bytes_sent`, `packets_sent`, and `rtt_msec` **must be quoted strings** containing integer digits (`"bytes_sent": "93394"`), NOT native JSON numbers (`93394`). Failing to quote these fields violates Google Cloud Logging's VPC Flow schema and breaks strict parsers.
2. **Numeric Protocol and Port Types**:
   - `connection.protocol`, `connection.src_port`, and `connection.dest_port` are integers (e.g., `"protocol": 6`), NOT strings (`"6"`).
3. **Port Absence for Non-Transport Protocols**:
   - Do NOT include `src_port` or `dest_port` when `protocol` is `1` (ICMP) or `50` (ESP/IPsec).
4. **Location vs Instance Exclusivity**:
   - If `src_ip` is an internal private IP within the VPC, include `src_instance` / `src_vpc` and omit `src_location`.
   - If `src_ip` is an external public Internet IP, omit `src_instance` / `src_vpc` and include `src_location` (GeoIP metadata).
   - The same mutual exclusivity applies to `dest_ip` vs (`dest_instance`/`dest_vpc`) vs `dest_location`.
5. **Exact `logName` Encoding**:
   - The forward slash before `vpc_flows` is URL-encoded: `compute.googleapis.com%2Fvpc_flows`. Do NOT use `compute.googleapis.com/vpc_flows`.
6. **Valid `reporter` Values**:
   - `reporter` must strictly be either `"SRC"` or `"DEST"`.
7. **Single-Line Formatting**:
   - Logs must be serialized as compact, unformatted, single-line JSON objects per line without line breaks inside the payload.
