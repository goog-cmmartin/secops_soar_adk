# CyberArk Log Generation Playbook

## 1. Overview & Log Purpose

CyberArk Privileged Access Security (PAS) and Endpoint Privilege Manager (EPM) solutions record privileged access management, credential rotations, session activity, administrative operations, and endpoint privilege elevations.

### Primary Systems & Subcomponents
* **CyberArk Digital Vault (EPV)**: Core repository managing privileged accounts, safe permissions, policy rules, and cryptographic operations.
* **Central Policy Manager (CPM)**: Automated engine performing password verification, rotation, and reconciliation.
* **Privileged Session Manager (PSM / PSMP)**: Proxy service recording and isolating interactive privileged sessions (RDP, SSH, Web), monitoring keystrokes, and tracking application window titles.
* **Password Vault Web Access (PVWA)**: Web-based administrative and end-user access console.
* **Endpoint Privilege Manager (EPM)**: Host-based agent controlling application execution, administrative delegation, and privilege elevation.

---

## 2. Format Specification

CyberArk logs exist primarily in two main formats across enterprise environments:

### Format A: Syslog Wrapped Common Event Format (CEF) — *Standard & Dominant*
Used by Digital Vault, CPM, PSM, and PVWA syslog outbound feeds.

* **Syslog Envelopes**:
  * **RFC 5424 Format**: `<PRI>1 YYYY-MM-DDTHH:MM:SSZ <HOST> CEF:0|Cyber-Ark|Vault|<Version>|<DeviceEventClassID>|<Name>|<Severity>|<Extension>`
  * **RFC 3164 Format**: `<PRI>MMM DD HH:MM:SS <HOST/IP> CEF:0|Cyber-Ark|Vault|<Version>|<DeviceEventClassID>|<Name>|<Severity>|<Extension>`
  * *Note*: Some legacy configurations emit `CEF: 0|` (with a space) or omit the `<PRI>` syslog prefix entirely.
* **CEF Header Delimiters**: Pipe `|` separated into 7 fixed segments.
* **CEF Extension Delimiters**: Space-separated `key=value` pairs.
* **Quoting & Escaping**:
  * Values containing `=` must escape it as `\=`.
  * Values containing `\` or `|` must be escaped with `\\` or `\|`.
  * Custom label keys (e.g., `cs1Label="Safe Name"` or `cs1Label=Safe Name`) can appear with or without double quotes depending on the vault translator version.
  * Empty keys are emitted explicitly without a space before the next key (e.g., `dhost= duser= externalId= `).

### Format B: Endpoint Privilege Manager (EPM) JSON
Used by EPM API extractions and agent SIEM streaming.

* **Classification**: Minified Single-line JSON.
* **Encoding**: UTF-8.
* **Delimiters**: Standard JSON syntax (commas separating key-value pairs).

### Format C: Secondary / Legacy Formats *(Reference Only)*
* **Native Vault Syslog**: `<PRI>1 YYYY-MM-DDTHH:MM:SSZ <HOST> %CYBERARK: MessageID="51";Version="14.2.0001";Message="Retrieve File";Issuer="...";...`
* **LEEF Format**: `YYYY-MM-DDTHH:MM:SSZ <HOST> LEEF:1.0|Cyber-Ark|Vault|<Version>|<ID>|sev=6\tAction=...\t...`

## 4. Timestamp & Dynamic Time Templating

CyberArk implementations output timestamps based on the configured log destination protocol:

1. **RFC 5424 ISO 8601 (Syslog Header)**: `YYYY-MM-DDTHH:MM:SSZ`
   * Dynamic Tag: `##$TimeStamp-0d0h0m0s$##` (Evaluated format: `2026-03-10T12:50:18Z`)
2. **RFC 3164 BSD Syslog (Syslog Header)**: `MMM DD HH:MM:SS` (Single-digit days use a leading space)
   * Dynamic Tag: `##$SyslogTime-0d0h0m0s$##` (Evaluated format: `Mar 10 04:54:09` or `Mar  5 20:33:56`)
3. **EPM JSON Timestamps**: `YYYY-MM-DDTHH:MM:SS.sss`
   * Dynamic Tag: `##$TimeStamp-0d0h0m0s$##` (Evaluated format: `2026-03-19T13:09:07.653`)

## 6. Key Constraints & Pitfalls

### Critical Formatting Rules
1. **CEF Pipe Structure**: There must be exactly **7 pipe separators** dividing the 8 header sections (`CEF:0` through `Severity`). Truncating or adding pipes corrupts SIEM parser field mappings.
2. **Key-Value Padding for Empty Fields**: CyberArk CEF emits all extension keys even when empty (e.g., `dhost= duser= externalId= `). **Do not omit empty keys**; parsers often rely on fixed regex position matching.
3. **Escaping Equals in `msg=` and `cn2=`**: Any literal `=` character inside the message body (such as ticketing details or Windows return codes `winRc=2245`) MUST be escaped as `\=` (e.g., `Ticket ID\=CHG001`).
4. **Custom Extension Pairings**:
   * `cs1Label` defines the description for `cs1` (Default: `Affected User Name`).
   * `cs2Label` defines the description for `cs2` (Default: `Safe Name`).
   * `cs3Label` defines the description for `cs3` (Default: `Device Type`).
   * `cs4Label` defines the description for `cs4` (Default: `Database`).
   * `cs5Label` defines the description for `cs5` (Default: `Other info`).
   * `cn1Label` defines the description for `cn1` (Default: `Request Id`).
   * `cn2Label` defines the description for `cn2` (Default: `Ticket Id`).
   * If generating custom label tags, keep them strictly paired with their respective custom field.
5. **Path Formatting**: Object and file paths in `fname` always start with `Root\` followed by the object name convention: `Root\<DeviceType>-<Safe/Policy>-<TargetAddress>-<AccountName>`.
