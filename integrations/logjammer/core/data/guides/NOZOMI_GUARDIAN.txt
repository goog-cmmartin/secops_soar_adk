# Nozomi Networks Guardian (N2OS) Log Generation Playbook

## 1. Overview & Log Purpose
Nozomi Networks Guardian is an Operational Technology (OT), Internet of Medical Things (IoMT), and Industrial Control System (ICS) cybersecurity and anomaly detection platform running the N2OS operating system. Guardian appliances passively inspect industrial network traffic (SPAN/TAP), perform deep packet inspection (DPI) of industrial protocols (e.g., Modbus, EtherNet/IP, DNP3, OPC UA, BACnet, S7comm), monitor asset inventory, track appliance health, and record administrative actions.

Guardian logs generated via its Syslog/CEF Data Integration Endpoint record four primary activity streams:
1. **AUDIT Logs (`AUDIT:*`)**: Administrative logins, configuration changes, scheduled backup results, session hijacking detection, and host-based intrusion detection system (HIDS/AIDE) file modifications.
2. **SECURITY & SIGNATURE Incidents (`INCIDENT:*`, `SIGN:*`)**: Detected network scans, protocol anomalies, policy violations, known OT exploit signatures, and MITRE ATT&CK for ICS mappings.
3. **NETWORK FLOW Logs (`flow`)**: Layer 2 through Layer 7 connection telemetry summarizing transferred bytes, packet counts, protocol classification, and OT device communications.
4. **HEALTH Logs (`HEALTH`)**: Sensor appliance performance issues, interface oversubscription, link event discards, and diagnostic telemetry.

## 2. Format Specification

### Classification
- **Primary Standard**: Micro Focus ArcSight Common Event Format (CEF:0).
- **Transport Encapsulation**: Transmitted over UDP/TCP/TLS syslog (RFC 3164-compatible header) or delivered as standalone raw CEF lines.

### Layout Anatomy
A standard syslog-encapsulated Nozomi Guardian log consists of two primary components:
```text
<PRI>SyslogHeader CEF:0|Device Vendor|Device Product|Device Version|Device Event Class ID|Name|Severity|Extension
```

```text
|<--- Syslog Header (RFC 3164) --->|<----------------------- CEF Prefix (7 Pipes) ----------------------->|<------- CEF Extension Key-Values ------->|
<134>Oct 04 2024 09:51:57 guardian01 n2osevents[0]: CEF:0|Nozomi Networks|N2OS|24.4.1|AUDIT:SESSIONS:CREATE|User signed in|0|dvchost=guardian01 cs6=3 ...
```

### Delimiters & Quoting Rules
- **Header Delimiter**: Vertical pipe character (`|`). The CEF header strictly contains 7 pipe delimiters separating 8 header fields.
- **Header Escaping**: Any literal pipe (`|`) or backslash (`\`) within header fields (e.g., in the `Name` or `Device Event Class ID` field) must be escaped with a backslash (`\|`, `\\`).
- **Extension Delimiter**: Space-separated `key=value` pairs.
- **Extension Escaping & Equal Signs**: An equal sign (`=`) inside an extension value does not strictly need quotes, but embedded double quotes, backslashes, or control characters must follow CEF standards. Complex `msg` attributes containing JSON/Ruby structures (e.g., `{"N2OS_SMB_PASSWORD"=>"***"}`) or multiple IP chains are formatted as plain strings.
- **Labels**: Custom extension fields (`cs1` to `cs6`, `flexString1` to `flexString4`) require their respective companion label fields (e.g., `cs1Label`, `flexString1Label`).

## 3. Schema Breakdown & Fields

### Syslog Header & Process Identification
| Field | Type | Description | Realistic Values |
| :--- | :--- | :--- | :--- |
| **PRI** | Integer | Facility and Severity enclosed in `< >`. | `<134>` (Facility 16/Local0, Severity 6/Info), `<131>` (Severity 3/Error), `<137>` (Facility 17/Local1, Severity 1/Alert) |
| **Syslog Timestamp** | Timestamp | RFC 3164 timestamp format (`MMM dd yyyy HH:mm:ss` or `MMM dd HH:mm:ss`). | `Oct 28 2024 16:01:45`, `May 28 2025 03:30:06` |
| **Syslog Host** | String | Hostname of the Guardian appliance or central console sending the syslog. | `guardian01`, `guardian-val-grd1`, `cym-lab-nozomi01.ot.labs.example.com` |
| **Process Name & PID** | String | Process identifier generating the event. | `n2osevents[0]:` (Guardian internal event routing daemon) |

## 4. Timestamp & Dynamic Time Templating

Nozomi Guardian CEF logs contain up to two distinct timestamps:
1. **Syslog Header Timestamp**: Standard Syslog format (`MMM dd yyyy HH:mm:ss` or `MMM dd HH:mm:ss` UTC/Local).
2. **CEF `start` Extension Field**: Millisecond Epoch timestamp (13 digits, e.g., `1727882351315`).

### Dynamic Generation Placeholders
When generating dynamic logs, use the following template tags to ensure strict time synchronization across headers and payload extensions:

- `##$TimeStamp-0d0h30m0s|%b %d %Y %H:%M:%S$##` -> Generates the syslog header timestamp with the year (e.g., `Oct 28 2024 16:01:45`). The year is required, or events without a `start=` field are stamped with ingestion time.
- `##$EpochMillis-0d0h30m0s$##` -> Generates Epoch Milliseconds for the `start=` field (e.g., `1730131243083`).
- `##$Epoch-0d1h0m0s$##` -> Generates standard 10-digit Epoch seconds (e.g., `1730131243`).
- `##$TimeStamp-0d2h15m0s$##` -> Generates ISO 8601 timestamps if needed for embedded API traces.

## 6. Key Constraints & Pitfalls

1. **CEF Pipe Balance**: The prefix strictly demands 7 pipe separators (`|`). Even if a field is empty (such as subcategories in `AUDIT::`), both colons and pipes must be retained correctly: `CEF:0|Nozomi Networks|N2OS|<Version>|AUDIT::|<Name>|<Severity>|<Extension>`.
2. **Label Field Coupling**: Any custom field (`cs1`..`cs6`, `flexString1`..`flexString4`) **must** be accompanied by its corresponding label definition (`cs1Label`, `flexString1Label`). Note that in Guardian logs, the position of labels can appear after the value (e.g., `cs1=7.0 ... cs1Label=Risk`).
3. **Dual Schema for `cs6`**: 
   - In Audit and Incident logs, `cs6=3` with `cs6Label=n2os_schema`.
   - In Network Flow logs (`flow`), `cs6` represents bytes transferred (`cs6Label=transferred_bytes cs6=6144`), while `cs4` represents packet count (`cs4Label=transferred_packets cs4=48`).
4. **Millisecond Timestamping (`start`)**: The `start=` timestamp in Nozomi Guardian is a **13-digit Unix Epoch Millisecond** timestamp (e.g., `1730131243083`), not a standard 10-digit epoch second. Parsers relying on millisecond precision will fail or calculate year 1970 if truncated to 10 digits.
5. **Multi-IP `src` Field**: When web requests pass through proxies or reverse load balancers, Nozomi records all hops comma-separated in the `src=` field (e.g., `src=198.51.100.1, 203.0.113.1`). Generators must emulate this multi-IP format for UI audit logs.
6. **No Space Around Equals**: Ensure there are no spaces immediately before or after the `=` sign in the extension key-value pairs (`key=value`, never `key = value`).
