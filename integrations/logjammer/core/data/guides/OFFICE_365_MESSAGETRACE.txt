# AI Log Generation Playbook: Office 365 Message Trace (`OFFICE_365_MESSAGETRACE`)

## 1. Overview & Log Purpose

**OFFICE_365_MESSAGETRACE** captures the lifecycle, routing, security inspection, and delivery disposition of emails processed through Microsoft Exchange Online Protection (EOP) and Microsoft Defender for Office 365 (MDO).

### Core Recorded Activities
* **Email Transit & Delivery**: Inbound, outbound, and internal routing statuses (e.g., `Delivered`, `Expanded`, `Resolved`, `Failed`, `Pending`).
* **Security & Threat Detection**: Antispam verdicts (`FilteredAsSpam`), antiphishing detections, antimalware blocks, and quarantine actions.
* **Metadata & Forensics**: RFC 5322 Internet Message IDs, Exchange Network Message IDs, sender/recipient envelope addresses, client IP addresses, delivery servers, subject lines, message sizes, and authentication results (SPF, DKIM, DMARC, CompAuth).
* **Deep Inspection Telemetry (MDO Advanced Hunting)**: File attachment analysis (hashes, file types) and URL threat analysis (domains, body/attachment location).

---

## 2. Format Specification

Office 365 Message Trace logs are transmitted as JSON objects. Across enterprise environments, logs appear in three main schema variants depending on the extraction mechanism:

| Dialect Variant | Ingestion Mechanism | Format Characteristics |
| :--- | :--- | :--- |
| **Variant A: Classic Message Trace** | PowerShell `Get-MessageTrace` / EOP REST Reporting API / Splunk Add-on for MS Cloud Services | Flat JSON object; contains `Organization`, `MessageTraceId`, `Status`, `SenderAddress`, `RecipientAddress`. |
| **Variant B: MDO Advanced Hunting Stream** | Azure Event Hub / Azure Monitor Diagnostic Settings (Log Analytics) | Wrapped JSON object with top-level fields `time`, `tenantId`, `operationName`, `category` (`AdvancedHunting-EmailEvents`, `AdvancedHunting-EmailAttachmentInfo`, `AdvancedHunting-EmailUrlInfo`), and a nested `properties` dictionary. |
| **Variant C: Microsoft Graph Security API** | MS Graph API (`/security/messageTraces`) | CamelCase JSON format (`messageId`, `receivedDateTime`, `recipientAddress`, `senderAddress`, `fromIP`, `toIP`). |

### Delimiters and Quoting
* **Line Termination**: Single-line newline-delimited JSON (`NDJSON` / `JSONL`).
* **Encoding**: UTF-8.
* **Quoting**: All JSON strings must be double-quoted (`"..."`). Special characters within subject lines, email bodies, or nested JSON structures (e.g., `AuthenticationDetails`) must be escaped properly (`\"`, `\\`, `\n`).

## 3. Schema Breakdown & Fields

### Variant A: Classic Message Trace Schema (Flat JSON)

| Field Name | Type | Description | Sample Values |
| :--- | :--- | :--- | :--- |
| `Organization` | String | Microsoft 365 Tenant identifier or custom domain | `"contoso.onmicrosoft.com"`, `"acme.com"` |
| `MessageId` | String | RFC 5322 Internet Message-ID header (enclosed in `< >`) | `"<LO7P265MB7699@PROD.OUTLOOK.COM>"`, `"<uuid@domain.com>"` |
| `MessageTraceId` | String (UUID/Numeric) | Exchange tracking identifier correlating all hops for an email | `"cc9ea6a5-c2a5-4d19-6eb7-08db322ea3b8"`, `"62581968470047"` |
| `Received` | String | Timestamp when Exchange Online received the email | `"2024-05-23T03:29:37.1400000"`, `"/Date(1716434977140)/"` |
| `SenderAddress` | String | Envelope sender (P1) email address (`<>` for system bounces/NDRs) | `"alice@example.com"`, `"noreply@service.com"`, `"< >"` |
| `RecipientAddress` | String | Envelope recipient (P1) email address | `"bob@contoso.com"`, `"dl-all@contoso.com"` |
| `Subject` | String | Email Subject line header (P2) | `"Invoice #90214"`, `"Weekly Report"` |
| `Status` | String | Final message delivery status | `Delivered`, `Failed`, `Expanded`, `Quarantined`, `FilteredAsSpam`, `Resolved`, `SENDEXTERNAL`, `RECEIVE` |
| `FromIP` | String (IPv4/IPv6) | IP address of connecting sending mail server/client | `"198.51.100.45"`, `"10.12.10.2"` |

| `StartDate` | String (ISO / OData) | Trace search start boundary | `"2024-05-23T03:25:00Z"`, `"/Date(1716434700000)/"` |

### Variant B: Advanced Hunting Schema (`AdvancedHunting-EmailEvents`)

#### Outer Wrapper
* `time`: ISO 8601 Event ingestion timestamp (`YYYY-MM-DDTHH:MM:SS.fffffffZ`).
* `tenantId`: Azure AD / Entra ID Tenant UUID.
* `operationName`: Operation type (typically `"Publish"`).
* `category`: Category name (`"AdvancedHunting-EmailEvents"`, `"AdvancedHunting-EmailAttachmentInfo"`, `"AdvancedHunting-EmailUrlInfo"`).
* `Tenant`: Tenant routing classifier (typically `"DefaultTenant"`).
* `properties`: Nested JSON object containing forensic metadata.

### Variant C: Advanced Hunting Supporting Categories

#### `AdvancedHunting-EmailAttachmentInfo`
Nested inside `properties`:
* `ReportId`, `NetworkMessageId`, `Timestamp`, `RecipientEmailAddress`, `SenderFromAddress`
* `FileName` (e.g., `"Invoice_0912.pdf"`, `"payload.iso"`, `"ATT00004"`)
* `FileType` (e.g., `"pdf"`, `"iso"`, `"png"`, `"exe"`, `"docx"`)
* `SHA256` (64-character lowercase hexadecimal hash)
* `FileSize` (Integer bytes)
* `ThreatTypes`, `ThreatNames`, `DetectionMethods`

#### `AdvancedHunting-EmailUrlInfo`
Nested inside `properties`:
* `ReportId`, `NetworkMessageId`, `Timestamp`
* `Url` (Full URL, e.g., `"https://secure-login.portal-update.com/auth"`)
* `UrlDomain` (e.g., `"portal-update.com"`)
* `UrlLocation` (`"Body"` or `"Attachment"`)

## 4. Timestamp & Dynamic Time Templating

### Supported Formats Across Variants
1. **ISO 8601 UTC with fractional seconds (Standard)**: `2024-05-07T13:28:26.2247938Z`
2. **ISO 8601 UTC without trailing 'Z'**: `2023-03-31T21:26:49.9714743`
3. **ISO 8601 Second Granularity**: `2024-05-07T13:27:08Z`
4. **OData WCF Epoch Milliseconds**: `"/Date(1754369327258)/"`

### Dynamic Time Replacement Tags
When authoring scenarios, embed the following placeholder macros to ensure proper relative time generation:

* `##$TimeStamp-0d0h0m0s$##` -> Current execution time in ISO 8601 (`YYYY-MM-DDTHH:MM:SS.fffffffZ`)
* `##$TimeStamp-0d0h2m0s$##` -> Event timestamp 2 minutes prior (`YYYY-MM-DDTHH:MM:SS.fffffffZ`)
* `##$Epoch-0d0h2m0s$##` -> Event timestamp 2 minutes prior in Unix Epoch Seconds (`1716434977`)
* `##$EpochMS-0d0h2m0s$##` -> Event timestamp 2 minutes prior in Unix Epoch Milliseconds (`1716434977000`)

## 6. Key Constraints & Generation Pitfalls

1. **RFC 5322 Message-ID vs. NetworkMessageId**:
   * `MessageId` (and `InternetMessageId`) represents the client-generated RFC 5322 header and **MUST** be enclosed in angle brackets (e.g., `<unique-id@server.domain>`).
   * `MessageTraceId` and `NetworkMessageId` are Microsoft routing GUIDs and **MUST NOT** include angle brackets (e.g., `cc9ea6a5-c2a5-4d19-6eb7-08db322ea3b8`).

2. **Null Sender Addresses for System Messages**:
   * Bounce messages, Non-Delivery Reports (NDRs), and automated alerts legitimately use empty sender strings or `<>` as the `SenderAddress` / `SenderMailFromAddress`. Do not replace these with dummy emails in NDR scenarios.

3. **Escaped Nested JSON (`AuthenticationDetails`)**:
   * In Variant B, `AuthenticationDetails` is a JSON string embedded inside another JSON object. All inner quotation marks must be escaped (`\"`).
   * Example: `"AuthenticationDetails": "{\"DKIM\":\"pass\",\"DMARC\":\"pass\",\"SPF\":\"pass\"}"`.

4. **Sender From vs. Sender Mail From Discrepancy (Spoofing Scenarios)**:
   * For spoofing/phishing generation, differentiate `SenderMailFromAddress` (P1 envelope / bounce address, e.g., `evil.com`) from `SenderFromAddress` (P2 display header, e.g., `ceo@target.com`). Set `DMARC` and `CompAuth` to `"fail"` in `AuthenticationDetails`.

5. **JSON Null Handling**:
   * Use literal `null` (not `"null"`, `"None"`, or `""`) for missing IPs (`ToIP`), internal sender IDs on inbound external email (`SenderObjectId`), and clean verdicts (`ThreatTypes`, `ThreatNames`).
