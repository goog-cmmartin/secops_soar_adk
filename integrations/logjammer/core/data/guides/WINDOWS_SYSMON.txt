# Windows Sysmon Log Generation Playbook

## 1. Overview & Log Purpose
Microsoft Sysinternals **Sysmon** (System Monitor) is a Windows system service and device driver that monitors and logs system activity to the Windows Event Log. Sysmon provides granular visibility into process creations, network connections, file modifications, registry changes, driver loads, remote thread injections, named pipe activities, DNS queries, and process tampering.

Sysmon logs are universally collected across enterprise environments for endpoint detection and response (EDR), threat hunting, threat detection engineering, and SIEM alerting. 

The primary ingestion pipelines forward these events using log shippers (such as NXLog `im_msvistalog`, Winlogbeat, Splunk Universal Forwarder, or Syslog forwarders) which serialize native Windows Event XML into JSON structures or Syslog-encapsulated JSON.

---

## 2. Format Specification

Sysmon events are commonly encountered in three primary representations:
1. **Flattened JSON (NXLog / `im_msvistalog` Standard)**: The most common SIEM ingestion format. Combines standard Windows Event header fields, a multiline human-readable `Message` string, and dynamically flattened event-specific key-value pairs at the root level.
2. **Nested JSON (`System` & `EventData`)**: Structured representation where Windows metadata is encapsulated inside `System` and payload attributes are within `EventData`.
3. **Syslog-Wrapped JSON (RFC 3164 / RFC 5424)**: Flattened JSON payload preceded by an RFC 3164 Syslog header (`<PRI>TIMESTAMP HOSTNAME TAG[PID]: {JSON}`).
4. **Native Windows Event XML**: Raw XML output direct from the Windows Event channel `Microsoft-Windows-Sysmon/Operational`.

### Delimiters & Escaping Rules
* **JSON Encoding**: Standard UTF-8 JSON. All string values must escape backslashes (`\\`) and double quotes (`\"`).
* **Windows Paths**: Must use double backslashes in JSON strings: `C:\\Windows\\System32\\cmd.exe`.
* **Newlines in Message**: The `Message` field contains literal newline characters (`\n`) separating key-value pairs formatted as `FieldName: Value`.
* **Hashes**: Hash strings are delimited by commas or single-space pairs: `MD5=...,SHA256=...,IMPHASH=...` or `SHA256=...`.
* **GUIDs**: Windows GUIDs are enclosed in braces: `{de2dee9a-f0db-613e-7017-000000001100}`.

## 3. Schema Breakdown & Fields

### 3.1 Standard Metadata / Header Fields

| Field Name | Type | Description | Example / Allowed Values |
| :--- | :--- | :--- | :--- |
| `EventID` / `EventId` | Integer / String | Sysmon Event ID (1–26, 255) | `1`, `3`, `7`, `10`, `22` |
| `EventTime` | Integer / String | Timestamp of the event (Epoch or ISO-8601) | `1611175283`, `"2021-10-28T20:23:05.945196+00:00"` |
| `EventReceivedTime` | Integer / String | Timestamp when log collector processed event | `1611175286` |
| `Hostname` / `Computer` | String | FQDN or NetBIOS name of the host | `"dummy10-1.user12.local"`, `"WIN-SERVER-01"` |
| `SourceName` / `ProviderName` | String | Source logging provider | `"Microsoft-Windows-Sysmon"` |
| `ProviderGuid` | String | Fixed Sysmon Provider GUID | `"{5770385F-C22A-43E0-BF4C-06F5698FFBD9}"` |
| `Channel` | String | Event log channel | `"Microsoft-Windows-Sysmon/Operational"` |
| `Version` | Integer / String | Sysmon schema version for the event | `3`, `4`, `5` |
| `Task` / `TaskValue` | Integer / String | Task ID (typically matches Event ID) | `1`, `3`, `22` |
| `Opcode` / `OpcodeValue` | String / Integer | Event opcode | `"Info"` / `0` |
| `Severity` / `EventType` | String | Event level | `"INFO"`, `"ERROR"`, `"WARNING"` |
| `SeverityValue` / `LevelValue`| Integer | Numeric severity value | `2` (Info), `4` (Error) |
| `RecordNumber` / `EventRecordID`| Integer / String | Incremental record counter | `8846`, `"641205"` |
| `ProcessID` / `ExecutionProcessID`| Integer / String | PID of the logging service (Sysmon service) | `1184`, `3132` |

### 3.2 Event-Specific Schema (EventData Attributes)

#### Event ID 1: Process Creation (`ProcessCreate`)
* `UtcTime`: UTC timestamp string (`YYYY-MM-DD HH:MM:SS.mmm`).
* `ProcessGuid`: Unique process instance GUID.
* `ProcessId`: PID of the spawned process (integer/string).
* `Image`: Full path to executable (`C:\\Windows\\System32\\cmd.exe`).
* `CommandLine`: Exact command string executed.
* `CurrentDirectory`: Working directory of execution.
* `User`: Account context (`DOMAIN\\Username` or `NT AUTHORITY\\SYSTEM`).
* `LogonGuid` / `LogonId`: Logon session GUID and hex ID (`0x3E7`, `0x12163C`).
* `TerminalSessionId`: RDP/interactive session ID (`0`, `1`, `2`).
* `IntegrityLevel`: Token integrity (`Low`, `Medium`, `High`, `System`, `AppContainer`).
* `Hashes`: Cryptographic signatures (`SHA256=...`, `MD5=...`, `IMPHASH=...`).
* `ParentProcessGuid`: Unique GUID of parent process.
* `ParentProcessId`: PID of parent process.
* `ParentImage`: Executable path of the parent process.
* `ParentCommandLine`: Command line of the parent process.
* `ParentUser`: (Optional) Account context of parent process.
* `RuleName`: Config rule tag or `"-"`.

#### Event ID 2: File Creation Time Changed (`FileCreateTime`)
* `ProcessGuid`, `ProcessId`, `Image`: Target modifying process.
* `TargetFilename`: Path of file whose timestamp was manipulated (timestomping).
* `CreationUtcTime`: New creation time.
* `PreviousCreationUtcTime`: Original creation time.

#### Event ID 3: Network Connection Detected (`NetworkConnect`)
* `ProcessGuid`, `ProcessId`, `Image`, `User`: Initiating process.
* `Protocol`: `"tcp"` or `"udp"`.
* `Initiated`: `"true"` (outbound) or `"false"` (inbound).
* `SourceIsIpv6` / `DestinationIsIpv6`: `"false"` or `"true"`.
* `SourceIp`: Source IPv4/IPv6 address.
* `SourceHostname`: Resolving hostname of source.
* `SourcePort`: Source ephemeral or service port (e.g. `49152–65535`).
* `SourcePortName`: Service name or `"-"`.
* `DestinationIp`: Destination IPv4/IPv6 address.
* `DestinationHostname`: Destination host/domain name.
* `DestinationPort`: Destination port (`80`, `443`, `53`, `445`, `22`, etc.).
* `DestinationPortName`: Well-known protocol name (`"http"`, `"https"`, `"domain"`, `"ssh"`).

#### Event ID 5: Process Terminated (`ProcessTerminate`)
* `ProcessGuid`, `ProcessId`, `Image`, `UtcTime`.

#### Event ID 6: Driver Loaded (`DriverLoad`)
* `ImageLoaded`: Kernel driver path (`C:\\Windows\\System32\\drivers\\*.sys`).
* `Hashes`: Driver binary hashes.
* `Signed`: `"true"` or `"false"`.
* `Signature`: Signer name (e.g. `"Microsoft Windows"`).
* `SignatureStatus`: `"Valid"`, `"Invalid"`, `"Revoked"`.

#### Event ID 7: Image Loaded / DLL Injection (`ImageLoad`)
* `ProcessGuid`, `ProcessId`, `Image`: Process loading the module.
* `ImageLoaded`: Full path to loaded DLL/executable.
* `FileVersion`, `Description`, `Product`, `Company`, `OriginalFileName`: PE binary metadata.
* `Hashes`, `Signed`, `Signature`, `SignatureStatus`.

#### Event ID 8: CreateRemoteThread (`CreateRemoteThread`)
* `SourceProcessGuid`, `SourceProcessId`, `SourceImage`: Injecting process.
* `TargetProcessGuid`, `TargetProcessId`, `TargetImage`: Injected target process.
* `NewThreadId`: Thread identifier created in target.
* `StartAddress`: Hexadecimal entry memory address (`0xFFFF86C1786F20D0`).
* `StartModule`, `StartFunction`: Target module/function name or `"-"`.

#### Event ID 10: Process Access (`ProcessAccess`)
* `SourceProcessGUID`, `SourceProcessId`, `SourceThreadId`, `SourceImage`.
* `TargetProcessGUID`, `TargetProcessId`, `TargetImage`.
* `GrantedAccess`: Hexadecimal permission mask (`0x1000`, `0x1F0FFF`, `0x1400` [LSASS access]).
* `CallTrace`: Pipe-delimited call stack modules and offsets (`ntdll.dll+9d2e4|KERNELBASE.dll+32da6|...`).

#### Event ID 11: File Created (`FileCreate`)
* `ProcessGuid`, `ProcessId`, `Image`: Creating process.
* `TargetFilename`: Absolute path of the newly written file.
* `CreationUtcTime`: Timestamp of file creation.

#### Event IDs 12, 13, 14: Registry Events (`RegistryEvent`)
* `EventType`: `"CreateKey"`, `"DeleteKey"`, `"SetValue"`, `"DeleteValue"`, `"RenameKey"`.
* `TargetObject`: Full registry key path (`HKLM\\SOFTWARE\\...`, `HKU\\S-1-5-...`).
* `Details`: (For ID 13) Stored data or `"Binary Data"`, `"DWORD (0x00000001)"`.
* `NewName`: (For ID 14) Target renamed registry path.

#### Event ID 15: File Stream Created / ADS (`FileCreateStreamHash`)
* `TargetFilename`: Path with alternate data stream (`C:\\Users\\admin\\Downloads\\file.zip:Zone.Identifier`).
* `Hash`: Hash of the alternate stream contents.
* `Contents`: Stream text content (e.g. `[ZoneTransfer] ZoneId=3`) or `"-"`.

#### Event IDs 17 & 18: Named Pipe Events (`PipeEvent`)
* `EventType`: `"CreatePipe"` (ID 17) or `"ConnectPipe"` (ID 18).
* `PipeName`: Named pipe path (`\\mojo.6492.10392.14091298499434378615`, `\\lsass`, `\\psexec`).
* `ProcessGuid`, `ProcessId`, `Image`.

#### Event IDs 19, 20, 21: WMI Events (`WmiEvent`)
* `EventType`: `"WmiFilterEvent"`, `"WmiConsumerEvent"`, `"WmiBindingEvent"`.
* `Operation`: `"Created"`, `"Deleted"`.
* `User`: Context executing WMI registration.
* `EventNamespace`, `Name`, `Query`, `Type`, `Destination`, `Consumer`, `Filter`.

#### Event ID 22: DNS Query (`DnsQuery`)
* `QueryName`: Fully qualified domain name requested (`"stas.outbrain.com"`, `"c2.attacker.com"`).
* `QueryStatus`: Numeric DNS status code (`0` for `SUCCESS`, `9003` for `NXDOMAIN`).
* `QueryResults`: Semicolon-delimited answer strings (`"type: 5 cname.domain.com;198.51.100.24;"`).
* `Image`, `ProcessGuid`, `ProcessId`.

#### Event ID 23 & 26: File Delete / File Delete Logged (`FileDelete` / `FileDeleteDetected`)
* `TargetFilename`: Path to deleted file.
* `Hashes`: Cryptographic hash before deletion.
* `IsExecutable`: `"true"` or `"false"`.
* `Archived`: `"true"` or `"false"` (Sysmon file preserve directory).

#### Event ID 25: Process Tampering (`ProcessTampering`)
* `Type`: Tampering technique (`"Image is locked for access"`, `"Process hollowing"`, `"Process herpaderping"`).
* `ProcessGuid`, `ProcessId`, `Image`, `User`.

## 4. Timestamp & Dynamic Time Templating

Sysmon logs generated through forwarders contain multiple timestamp fields that must align:

1. **`EventTime` / `EventReceivedTime`**: Integer Epoch seconds or milliseconds representing collector and reception time.
   * Template Tag: `##$Epoch-0d0h0m0s$##` (Seconds) or `##$EpochMS-0d0h0m0s$##` (Milliseconds).
2. **`UtcTime` / `CreationUtcTime`**: Sub-second UTC timestamps in string format `YYYY-MM-DD HH:MM:SS.mmm`.
   * Template Tag: `##$TimeStamp-0d0h0m0s$##` formatted as `YYYY-MM-DD HH:MM:SS.mmm`.
3. **`TimeCreated` (Nested JSON / XML)**: Milliseconds Epoch or ISO 8601 UTC string (`YYYY-MM-DDTHH:MM:SS.mmmmmm000Z`).
   * Template Tag: `##$TimeStamp-0d0h0m0s$##`.
4. **Syslog Header Timestamp**: Standard BSD Syslog format (`MMM DD HH:MM:SS`).
   * Template Tag: `##$SyslogTime-0d0h0m0s$##`.

### Time Offset Rules
* `UtcTime` within the event payload should typically precede `EventTime` by 0 to 5 seconds.
* `EventReceivedTime` equals or follows `EventTime` by 1 to 3 seconds.
* Parent process timestamps (`ParentProcessGuid`) should reflect execution earlier in the timeline.

## 6. Key Constraints & Common Pitfalls

### Mandatory Fields
* Parsers rely strictly on `EventID` (or `Task`), `SourceName: "Microsoft-Windows-Sysmon"`, `Channel: "Microsoft-Windows-Sysmon/Operational"`, and `UtcTime`.
* Missing `ProcessGuid` or `ProcessId` will break process tree correlation pipelines in EDR and SIEM engines.

### Syntax & Formatting Traps
1. **JSON String Escaping**: Double-escape backslashes in Windows file and registry paths (`C:\\Windows\\...`, `HKLM\\SOFTWARE\\...`). Single backslashes (`\`) will cause JSON parse failures.
2. **Message Alignment**: Ensure the key-value pairs in the formatted `Message` field match the root-level flattened JSON attributes identically (e.g. `ProcessId: 5440` in `Message` must match `"ProcessId": "5440"` in root fields).
3. **Hexadecimal Values**:
   * `LogonId` is prefixed with `0x` (e.g. `0x3E7`, `0x12163C`).
   * `GrantedAccess` in Event 10 must be a 4 to 8 digit hex string (e.g. `0x1000`, `0x1F0FFF`).
   * `StartAddress` in Event 8 must follow 64-bit or 32-bit hex address format (`0x00007FFA31B21000`).
4. **Boolean Strings vs Native Booleans**: In the flattened NXLog JSON format, Sysmon flags like `Initiated`, `SourceIsIpv6`, `Signed`, `IsExecutable`, and `Archived` are string literals (`"true"`, `"false"`), not JSON booleans (`true`, `false`).
5. **RuleName Format**: When empty or default, set `RuleName: "-"`. When mapped to MITRE ATT&CK, use `technique_id=TXXXX,technique_name=TechniqueName`.
