# AI Generation Playbook: AWS CloudTrail Logs (`AWS_CLOUDTRAIL`)

---

## 1. Overview & Log Purpose

**AWS CloudTrail** is the foundational governance, compliance, operational, and security auditing service in Amazon Web Services (AWS). It records actions taken by a user, role, or an AWS service across the AWS infrastructure. 

### Activities Recorded:
* **Management Events**: Control plane operations such as creating/deleting resources, configuring networking (`ec2:DescribeRouteTables`), IAM administration (`iam:CreateUser`, `iam:AddUserToGroup`), and key management (`kms:CreateKey`).
* **Data Events**: High-volume resource operations such as S3 object-level actions (`GetObject`, `PutObject`) or Lambda function invocations.
* **Authentication & Authorization**: AWS Management Console sign-in attempts (`ConsoleLogin`), multi-factor authentication (MFA) validation, SAML federations, and STS temporary credential requests (`sts:AssumeRole`, `sts:AssumeRoleWithWebIdentity`).
* **Security & Failure Events**: Unauthorized API calls (`AccessDenied`), invalid entity updates, enumeration probes, and administrative privilege escalation attempts.

---

## 2. Format Specification

### Classification & Structure
* **Encapsulation Style**:
  * **S3 Batch / Delivery File Format**: Logs written to S3 are stored as a single JSON object containing a top-level `"Records"` array: `{"Records": [ { <event-1> }, { <event-2> } ]}`.
  * **CloudWatch Logs / EventBridge / Ingestion Streams**: Often delivered as discrete, standalone JSON objects (a single event per line).
* **Format**: Pure JSON (RFC 8259).
* **Quoting & Encoding**: UTF-8 encoded. Standard JSON key-value pairs with strict double-quoting (`"`).
* **Nested Stringified JSON**: IAM policies, KMS policies, and certain complex resource metadata within `requestParameters` or `responseElements` are embedded as **escaped stringified JSON** strings.

## 3. Schema Breakdown & Fields

### Core Event Metadata

| Field | Type | Required | Description / Example Values |
| :--- | :--- | :--- | :--- |
| `eventVersion` | String | **Yes** | CloudTrail schema version. Common: `"1.05"`, `"1.08"`, `"1.09"`, `"1.10"`. |
| `eventTime` | String | **Yes** | UTC ISO 8601 timestamp: `YYYY-MM-DDTHH:MM:SSZ`. |
| `eventSource` | String | **Yes** | AWS service domain name (e.g., `iam.amazonaws.com`, `sts.amazonaws.com`, `ec2.amazonaws.com`, `signin.amazonaws.com`, `s3.amazonaws.com`, `kms.amazonaws.com`, `secretsmanager.amazonaws.com`). |
| `eventName` | String | **Yes** | API action name (e.g., `ConsoleLogin`, `AssumeRole`, `CreateUser`, `PutObject`, `AttachRolePolicy`, `DeleteSecurityGroup`). |
| `awsRegion` | String | **Yes** | AWS region name (e.g., `us-east-1`, `us-west-2`, `eu-west-1`, `ap-northeast-1`). Note: IAM and Sign-in events generally default to `us-east-1`. |
| `sourceIPAddress` | String | **Yes** | Client IPv4/IPv6 address (`198.51.100.25`, `2001:db8::1`) or internal AWS service domain (`lambda.amazonaws.com`, `autoscaling.amazonaws.com`, `AWS Internal`). |
| `userAgent` | String | **Yes** | Client identifier (e.g., `aws-cli/2.11.0 Python/3.10 Linux/5.10`, `console.amazonaws.com`, `Boto3/1.26.0`, `aws-sdk-go/1.44.0`, or standard browser User-Agents). For offensive security / pentest scenarios, tools such as `Pacu`, `Cloudfox`, `scoutsuite`, `trufflehog`, or `Prowler` are frequently seen and trigger high-precision detection rules. |
| `eventType` | String | **Yes** | Category of event: `"AwsApiCall"`, `"AwsConsoleSignIn"`, `"AwsServiceEvent"`. |
| `eventCategory` | String | No | Event categorization: `"Management"`, `"Data"`, or `"Insight"`. |
| `readOnly` | Boolean | No | `true` for read actions (`Describe*`, `Get*`, `List*`), `false` for mutating actions (`Create*`, `Delete*`, `Put*`). |
| `managementEvent` | Boolean | No | `true` if the event is a management control plane event. |
| `requestID` | String | **Yes** | Unique UUID generated by the serving AWS service for tracing (e.g., `c1a011a1-1010-11a1-a0aa-d1b767855df6`). |
| `eventID` | String | **Yes** | Unique UUID generated by CloudTrail for this specific log event. |
| `recipientAccountId` | String | **Yes** | 12-digit AWS Account ID that owns the resource or received the call (e.g., `"123456789012"`). |
| `errorCode` | String | No | Present **only** on failure (e.g., `"AccessDenied"`, `"NoSuchEntityException"`, `"InvalidInputException"`, `"UnauthorizedOperation"`). |
| `errorMessage` | String | No | Detailed explanation accompanying the error code. |

### `userIdentity` Object

Identifies the principal requesting the action. Its internal schema changes based on the identity `type`:

```json
"userIdentity": {
  "type": "IAMUser | Root | AssumedRole | SAMLUser | WebIdentityUser | AWSService",
  "principalId": "AIDA... / AROA... / AWS account ID",
  "arn": "arn:aws:iam::123456789012:user/username",
  "accountId": "123456789012",
  "accessKeyId": "AKIA... / ASIA...",
  "userName": "alice",
  "invokedBy": "cloudformation.amazonaws.com",
  "sessionContext": { ... }
}
```

#### Principal ID & Access Key Prefixes:
* **IAM User Principal ID**: `AIDA...` (e.g., `AIDAI4567EXAMPLE12345`)
* **Role Principal ID**: `AROA...` (e.g., `AROA0000000000EXAMPLE`)
* **Assumed Role Principal ID Format**: `AROA...:<session-name>`
* **Permanent Access Key**: `AKIA...` (e.g., `AKIA0000000000EXAMPLE`)
* **Temporary Session Access Key**: `ASIA...` (e.g., `ASIA0000000000EXAMPLE`)

#### `sessionContext` Structure (Common in `AssumedRole` and `Root`):
```json
"sessionContext": {
  "attributes": {
    "mfaAuthenticated": "true" | "false",
    "creationDate": "2023-10-10T12:00:00Z"
  },
  "sessionIssuer": {
    "type": "Role",
    "principalId": "AROA...",
    "arn": "arn:aws:iam::123456789012:role/RoleName",
    "accountId": "123456789012",
    "userName": "RoleName"
  },
  "webIdFederationData": {
    "federatedProvider": "arn:aws:iam::123456789012:oidc-provider/oidc.eks.us-west-2.amazonaws.com/id/...",
    "attributes": {}
  }
}
```

---

### Variable Payload Objects

* `requestParameters`: JSON object carrying input parameters specific to the API call. `null` if the call takes no parameters or was blocked prior to parsing.
* `responseElements`: JSON object carrying returned data. `null` on failed calls, write operations returning HTTP 204, or actions with sensitive outputs.
* `resources`: Array of objects containing targeted AWS resources:
  ```json
  "resources": [
    {
      "ARN": "arn:aws:kms:us-east-1:123456789012:key/c4e1a936-7642-411a-a0aa-11a011a11010",
      "accountId": "123456789012",
      "type": "AWS::KMS::Key"
    }
  ]
  ```
* `additionalEventData`: Contextual metrics such as MFA status, SAML assertions, or Login URLs for `ConsoleLogin`.
* `tlsDetails`: TLS metadata including `tlsVersion` (e.g., `"TLSv1.2"`, `"TLSv1.3"`), `cipherSuite`, and `clientProvidedHostHeader`.

## 4. Timestamp & Dynamic Time Templating

CloudTrail uses **ISO 8601 UTC** format with a trailing `Z` for primary event times:
`YYYY-MM-DDTHH:MM:SSZ`

Inside specific response attributes (e.g., IAM entity creation dates, STS token expirations), CloudTrail historically records dates in the human-readable format: `MMM d, yyyy h:mm:ss a` (e.g., `May 18, 2023 9:11:35 AM`).

### Relative Time Template Tags:
When generating synthetic data, insert dynamic timestamp placeholders:
* Primary event timestamp: `##$TimeStamp-0d0h5m0s$##` -> `2023-10-25T14:30:15Z`
* Prior session context creation: `##$TimeStamp-0d1h0m0s$##` -> `2023-10-25T13:35:15Z`
* Epoch variant (where needed): `##$Epoch-0d0h5m0s$##` -> `1698244215`

## 6. Key Constraints & Pitfalls

1. **Top-Level Record Wrapper**:
   * If simulating S3 CloudTrail logs, wrap elements in the `{"Records": [ ... ]}` JSON root object.
   * If generating for SIEM streaming pipelines (like direct CloudWatch Log streams), output each event JSON on a single line or as a single root-level object.
2. **Nullable Response Elements on Error**:
   * When `errorCode` is populated, `responseElements` **must** be `null` (not `{}`).
3. **Escaped Nested JSON vs. Native Objects**:
   * Policies (IAM JSON documents, KMS policies, S3 bucket policies) inside `requestParameters.policy` are **always string-escaped JSON strings**, not direct JSON objects:
     * *Incorrect*: `"policy": { "Version": "2012-10-17", ... }`
     * *Correct*: `"policy": "{\"Version\":\"2012-10-17\",...}"`
4. **ARN and Account ID Consistency**:
   * AWS Account IDs are strictly **12-digit strings** (e.g., `"123456789012"`). Do not use numbers or strings with leading spaces.
   * Ensure `recipientAccountId`, `userIdentity.accountId`, and any account references inside resource ARNs match unless simulating cross-account access.
5. **Console Sign-in Discrepancies**:
   * `ConsoleLogin` events utilize `eventSource: "signin.amazonaws.com"`, `eventType: "AwsConsoleSignIn"`, and record outcomes in `responseElements.ConsoleLogin` (`"Success"` or `"Failure"`). Standard API actions use `eventType: "AwsApiCall"`.
