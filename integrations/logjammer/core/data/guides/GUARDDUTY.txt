# AWS GuardDuty Finding Log Generation Playbook

## 1. Overview & Log Purpose
Amazon GuardDuty is an intelligent threat detection service that continuously monitors AWS accounts, workloads, and data for malicious activity and unauthorized behavior. GuardDuty analyzes billions of events across multiple AWS data sources—including AWS CloudTrail management and event logs, Amazon VPC Flow Logs, EKS audit logs, DNS logs, and Amazon S3 data events.

When a threat or anomaly is detected, GuardDuty generates a **Finding**. These findings represent actionable security alerts covering tactics such as reconnaissance, credential exfiltration, command and control (C2) communication, denial of service (DoS), cryptocurrency mining, unauthorized API calls, and privilege escalation.

GuardDuty logs can be consumed in two primary JSON wrappers:
1. **Raw GuardDuty Finding JSON**: Directly exported to S3 or fetched via GuardDuty APIs.
2. **AWS EventBridge (formerly CloudWatch Events) Envelope JSON**: Produced when findings are streamed via EventBridge to SIEMs, Kinesis, Lambda, or SQS.

---

## 2. Format Specification

### Classification & Structure
* **Format**: Strictly structured JSON (JavaScript Object Notation).
* **Delivery**: Emitted as single-line (minified) JSON strings per event to SIEM ingestion pipelines, SQS queues, or log shippers (e.g., Fluent Bit, Datadog Agent, Splunk Universal Forwarder).
* **Quoting & Escaping**:
  * Standard JSON rules: all field names and string values must be enclosed in double quotes (`"`).
  * Characters such as backslashes (`\`), double quotes (`"`), and control characters within strings (e.g., in user agents or tags) must be properly escaped (`\\`, `\"`).
  * Nested objects and arrays are heavily utilized. Trailing commas are strictly prohibited.

## 3. Schema Breakdown & Fields

### Top-Level Finding Schema (Common to all Findings)

| Field Name | Type | Description / Constraints | Example Value |
| :--- | :--- | :--- | :--- |
| `schemaVersion` | String | Schema version of the finding (always `"2.0"`). | `"2.0"` |
| `accountId` | String | 12-digit AWS account ID where the activity was detected. | `"123456789012"` |
| `region` | String | AWS Region where the finding was generated. | `"us-east-1"`, `"eu-west-1"` |
| `partition` | String | AWS partition name. | `"aws"`, `"aws-us-gov"`, `"aws-cn"` |
| `id` | String | Unique 32-character hexadecimal finding identifier. | `"3ebce68c9bd2b15518ff7ac27b69f178"` |
| `arn` | String | Full Amazon Resource Name of the finding. Follows pattern: `arn:<partition>:guardduty:<region>:<accountId>:detector/<detectorId>/finding/<id>` | `"arn:aws:guardduty:us-east-1:123456789012:detector/00b7c3aea1d6fa9c66fa179757c17a7b/finding/3ebce68c9bd2b15518ff7ac27b69f178"` |
| `type` | String | Finding type naming convention: `<ThreatPurpose>:<ResourceTypeAffected>/<ThreatFamilyName>[.<ThreatFamilyVariant>]`. | `"Recon:EC2/PortProbeUnprotectedPort"`, `"UnauthorizedAccess:IAMUser/InstanceCredentialExfiltration"` |
| `severity` | Number | Numeric severity score. High: `7.0`–`8.9` (or `8`), Medium: `4.0`–`6.9` (or `5`), Low: `0.1`–`3.9` (or `2`). | `2`, `5`, `8`, `2.0`, `8.0` |
| `createdAt` | String | ISO 8601 timestamp with milliseconds when finding was first created. | `"2023-10-15T14:20:52.517Z"` |
| `updatedAt` | String | ISO 8601 timestamp with milliseconds when finding was last updated. | `"2023-10-15T15:40:49.958Z"` |
| `title` | String | Human-readable short summary of the finding. | `"Unprotected port on EC2 instance i-06df12df279bffe5e is being probed."` |
| `description` | String | Detailed description of the threat, context, and potential impact. | `"EC2 instance has an unprotected port which is being probed by a known malicious host."` |
| `resource` | Object | Details of the AWS resource involved (Instance, AccessKey, S3Bucket, etc.). | *See Resource Schema below* |
| `service` | Object | GuardDuty-specific metadata, action triggers, network connections, and profiling. | *See Service Schema below* |

### The `resource` Object Schema

The structure varies depending on `resource.resourceType`:

#### 1. EC2 Instance (`resourceType`: `"Instance"`)
* `resourceType`: `"Instance"`
* `instanceDetails`:
  * `instanceId`: String (`i-0a8d172a06154b0b6`)
  * `instanceType`: String (`t2.xlarge`, `m5.4xlarge`, `c5.large`)
  * `launchTime`: String (ISO 8601 UTC `2021-03-31T07:06:47Z`)
  * `platform`: String or `null` (`"windows"`, `null` for Linux)
  * `imageId`: String (`ami-02b5cd5aa444bee23`)
  * `imageDescription`: String or `null`
  * `instanceState`: String (`"running"`, `"stopped"`)
  * `availabilityZone`: String (`"us-east-1a"`, `"us-east-1c"`)
  * `iamInstanceProfile`: Object with `arn` and `id`, or `null`
  * `productCodes`: Array of objects `[{"productCodeId": "...", "productCodeType": "marketplace"}]`
  * `tags`: Array of key-value objects `[{"key": "Name", "value": "Prod-Web"}]`
  * `networkInterfaces`: Array of ENI objects containing:
    * `networkInterfaceId` (`eni-0669916c082242270`)
    * `privateDnsName`, `privateIpAddress`
    * `privateIpAddresses`: Array of private IP mappings
    * `publicDnsName`, `publicIp`
    * `subnetId` (`subnet-0012cd14f5fe54a78`), `vpcId` (`vpc-019fd40c78b99a7c8`)
    * `securityGroups`: Array of `[{"groupName": "launch-wizard-2", "groupId": "sg-0f5bcac494c60a5bf"}]`

#### 2. IAM Access Key (`resourceType`: `"AccessKey"`)
* `resourceType`: `"AccessKey"`
* `accessKeyDetails`:
  * `accessKeyId`: String (`ASIA...` for temporary credentials, `AKIA...` for long-term keys)
  * `principalId`: String (`AIDA...` for IAM user, `AROA...:<sessionName>` for AssumedRole, account ID for Root)
  * `userType`: String (`"IAMUser"`, `"AssumedRole"`, `"Root"`, `"FederatedUser"`)
  * `userName`: String (`"AWSReservedSSO_AdministratorAccess"`, `"deploy-bot"`, `"admin-user"`)
* *Optional Associated Resources*: May also contain `instanceDetails` (for credential exfiltration from an EC2 instance) or `s3BucketDetails`.

### The `service` Object Schema

| Field Name | Type | Description |
| :--- | :--- | :--- |
| `serviceName` | String | Always `"guardduty"`. |
| `detectorId` | String | 32-character hexadecimal ID of the detector. |
| `resourceRole` | String | Role of the resource in the finding: `"TARGET"` or `"ACTOR"`. |
| `action` | Object | The specific action that triggered the alert. Contains `actionType` and action-specific sub-objects. |
| `eventFirstSeen` | String | ISO 8601 timestamp (`YYYY-MM-DDTHH:MM:SSZ`) of first event. |
| `eventLastSeen` | String | ISO 8601 timestamp (`YYYY-MM-DDTHH:MM:SSZ`) of last event. |
| `archived` | Boolean | `false` for active findings, `true` for archived findings. |
| `count` | Integer | Total count of aggregated security events for this finding. |
| `additionalInfo` | Object | Finding-specific metadata (threat intel lists, profiled behavior anomalies, scanned ports). |
| `evidence` | Object/Null | Threat intelligence evidence or `null`. |

#### Action Types & Nested Fields (`service.action`):

1. **`actionType`: `"NETWORK_CONNECTION"`**
   * `networkConnectionAction`:
     * `connectionDirection`: `"INBOUND"` or `"OUTBOUND"`
     * `protocol`: `"TCP"`, `"UDP"`
     * `blocked`: Boolean (`true`/`false`)
     * `localPortDetails`: `{"port": 3389, "portName": "RDP"}`
     * `remotePortDetails`: `{"port": 1028, "portName": "Unknown"}`
     * `localIpDetails`: `{"ipAddressV4": "10.0.1.50"}`
     * `remoteIpDetails`: `{"ipAddressV4": "4.5.6.7", "organization": {"asn": "...", "asnOrg": "...", "isp": "...", "org": "..."}, "country": {"countryName": "..."}, "city": {"cityName": "..."}, "geoLocation": {"lat": 0.0, "lon": 0.0}}`

2. **`actionType`: `"AWS_API_CALL"`**
   * `awsApiCallAction`:
     * `api`: API name (e.g., `"DeleteBucketPublicAccessBlock"`, `"DeleteTrail"`, `"UpdateInstanceInformation"`, `"ListTags"`)
     * `serviceName`: Target AWS service (e.g., `"s3.amazonaws.com"`, `"cloudtrail.amazonaws.com"`, `"ssm.amazonaws.com"`)
     * `callerType`: `"Remote IP"`, `"Domain"`, or `"AWS Service"`
     * `remoteIpDetails` or `domainDetails`: Calling entity details
     * `affectedResources`: Key-value map of targeted AWS resources (e.g., `{"AWS::S3::Bucket": "finance-records"}`)

3. **`actionType`: `"PORT_PROBE"`**
   * `portProbeAction`:
     * `blocked`: Boolean (`false`)
     * `portProbeDetails`: Array of probed ports and attacker IP details:
       * `localPortDetails`: `{"port": 22, "portName": "SSH"}`
       * `remoteIpDetails`: Object with GeoIP and ASN details.

4. **`actionType`: `"DNS_REQUEST"`**
   * `dnsRequestAction`:
     * `domain`: Query domain (e.g., `"malicious-c2-domain.com"`, `"pool.minexmr.com"`)
     * `protocol`: `"UDP"`
     * `blocked`: Boolean

## 4. Timestamp & Dynamic Time Templating

GuardDuty uses two distinct timestamp formats across finding fields:
1. **ISO 8601 with Milliseconds (`YYYY-MM-DDTHH:MM:SS.sssZ`)**: Used for `createdAt` and `updatedAt`.
2. **ISO 8601 Standard UTC (`YYYY-MM-DDTHH:MM:SSZ`)**: Used for `eventFirstSeen`, `eventLastSeen`, `launchTime`, and EventBridge envelope `time`.

### Templating Variables Instruction
When synthetically generating logs, use relative dynamic timestamp macros to simulate realistic time intervals. The event history must be chronological:
`launchTime` < `eventFirstSeen` <= `eventLastSeen` <= `createdAt` <= `updatedAt` / `time`

* **`createdAt`**: `##$TimeStamp-0d0h5m0s$##.124Z`
* **`updatedAt`**: `##$TimeStamp-0d0h1m0s$##.891Z`
* **`eventFirstSeen`**: `##$TimeStamp-0d2h0m0s$##Z`
* **`eventLastSeen`**: `##$TimeStamp-0d0h6m0s$##Z`
* **`launchTime`**: `##$TimeStamp-10d0h0m0s$##Z`
* **EventBridge `time`**: `##$TimeStamp-0d0h1m0s$##Z`

## 6. Key Constraints & Pitfalls

1. **Strict Resource and Action Coherence**:
   * If `resource.resourceType` is `"Instance"`, `service.action` is almost always `"NETWORK_CONNECTION"`, `"PORT_PROBE"`, or `"DNS_REQUEST"`.
   * If `resource.resourceType` is `"AccessKey"`, `service.action` must be `"AWS_API_CALL"`.
   * **Exception**: `UnauthorizedAccess:IAMUser/InstanceCredentialExfiltration` uses `resourceType: "AccessKey"`, but contains both `instanceDetails` (the origin instance) and `accessKeyDetails` (the compromised role/key).
2. **Actor vs. Target Semantics**:
   * When an AWS resource is being attacked from the outside (e.g., port probed, brute-forced), `service.resourceRole` is `"TARGET"`.
   * When an internal EC2 instance is compromised and conducting malicious scans or outbound C2, `service.resourceRole` is `"ACTOR"`.
3. **Severity Value Range**:
   * Low: `0.1` – `3.9` (represented commonly as `2` or `2.0`).
   * Medium: `4.0` – `6.9` (represented commonly as `5` or `5.0`).
   * High: `7.0` – `8.9` (represented commonly as `8` or `8.0`).
4. **ARN Consistency**:
   * `arn` field must match: `arn:aws:guardduty:<region>:<accountId>:detector/<detectorId>/finding/<id>`.
   * Detector ID in `arn` must equal `service.detectorId`.
   * ID in `arn` must equal the top-level `id` field.
5. **JSON Structure & Escaping**:
   * GuardDuty output contains deeply nested dictionaries. Avoid syntax errors like unbalanced brackets, missing commas between keys, or raw unescaped quotes inside `tags`, `title`, or `description`.
   * SIEM ingestion pipes expect one complete JSON object per log record without internal line breaks.
