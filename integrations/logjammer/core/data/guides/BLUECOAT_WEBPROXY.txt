# AI Generation Playbook: Blue Coat / Symantec ProxySG (BLUECOAT_WEBPROXY)

---

## 1. Overview & Log Purpose

**Blue Coat / Symantec Edge SWG (ProxySG)** logs capture enterprise forward and reverse web proxy activity, SSL interception/decryption, content analysis, user authentication, and web security policy enforcement.

### Common Recorded Activities
*   **Web Browsing & HTTP/HTTPS Transactions**: Client requests, upstream server responses, MIME types, cache status, transfer volume, and latency.
*   **Secure Web Gateway (SWG) Enforcement**: Policy-based allows, blocks, redirects, malware/threat risk filtering, and WebPulse/Global Intelligence Network (GIN) URL categorization.
*   **Proxy Authentication & Access Challenges**: Kerberos, NTLM, Digest, or Basic authentication handshakes, failures (HTTP `407 Proxy Authentication Required`), and virtual-host authentication redirects (`302`/`307`).
*   **SSL/TLS Handshake & Visibility (SSLV)**: Negotiated SSL/TLS ciphers, protocol versions, server certificate inspection, JA3 fingerprints, and resign/decrypt decisions.
*   **Appliance Internal System Events**: Health checks, upload failures, ICAP daemon events, and proxy process state transitions.

---

## 2. Format Specifications

Blue Coat logs are delivered in multiple formats depending on the SGOS access log configuration, syslog daemon settings, or log collector (SIEM/Chronicle/Splunk) ingestion pipeline:

```
+-------------------------------------------------------------------------------+
| BLUECOAT_WEBPROXY Formats                                                     |
+-------------------------------------------------------------------------------+
| 1. Space-Delimited W3C ELFF (Extended Log File Format) [Standard / Custom]   |
| 2. Syslog RFC 5424 Enclosing W3C ELFF JSON Object Payload                    |
| 3. Syslog RFC 3164 Pipe-Delimited Key-Value (Custom ELFF KV / ArcSight CEF-like)|
| 4. Syslog RFC 3164 SSL Visibility (ssldata) Engine Stream                     |
| 5. SGOS Appliance Event / Error Syslog Message                                |
+-------------------------------------------------------------------------------+
```

### Delimiters and Quoting Rules
*   **Space-Delimited ELFF**: Fields are separated by single ASCII spaces (`0x20`). Strings containing spaces (such as `cs_user_agent`, `cs_categories`, or `app_name`) **must** be enclosed in double quotes (`"`).
*   **Null / Empty Representation**: In standard ELFF and KV pairs, non-existent, unauthenticated, or unrecorded fields use a single hyphen (`-`) or the literal string `None` / `unavailable`.
*   **URL Encoding**: Embedded whitespace or special query parameters inside categories, URIs, content types, and groups are percent-encoded (e.g., `text/plain;%20charset=utf-8`, `Domain%20Users`).
*   **Pipe-Delimited KV**: Formatted as `Header|key1=value1|key2=value2|...`. Keys matching sub-fields use parenthetical syntax (e.g., `rs(Content-Type)`, `cs(User-Agent)`).
*   **JSON Format**: Standard JSON escaping rules apply; nested quotes inside query strings or headers must be escaped (`\"`).

## 3. Schema Breakdown & Fields

### A. W3C / SGOS ELFF Field Prefixes
Blue Coat utilizes standard W3C log prefixes denoting communication endpoints:
*   `c-`: Client
*   `s-`: Proxy Server
*   `r-`: Remote / Origin Server
*   `cs-`: Client-to-Server (Proxy)
*   `sc-`: Server (Proxy)-to-Client
*   `rs-`: Remote-to-Server (Proxy)
*   `sr-`: Server (Proxy)-to-Remote
*   `x-`: Extended / Symantec Proprietary

## 4. Timestamp & Dynamic Time Templating

Blue Coat logs use several timestamp representations depending on the transport format.

### Supported Formats
1. **W3C Standard Date/Time**: Two space-separated columns: `YYYY-MM-DD` and `HH:MM:SS` (e.g., `2023-10-15 12:24:53`).
2. **Squid / Apache Style**: Bracketed format with timezone offset: `[10/Feb/2023:00:43:08 -0500]`.
3. **ISO 8601 UTC (Syslog RFC 5424 / JSON)**: `2023-10-15T12:24:53.413445Z` and `"@timestamp":"2023-10-15T12:24:53.000000Z"`.
4. **Syslog RFC 3164 Standard**: `MMM DD HH:MM:SS` (e.g., `Feb 10 00:24:53` or `Sep 22 12:26:39`).
5. **Epoch Seconds (SSLV ssldata)**: 10-digit UNIX timestamp (e.g., `1697372693`).

### Dynamic Time Macros for Scenario Generators
When generating synthetic log streams, insert relative time template tags to maintain sequential timing across scenarios:

*   `##$TimeStamp-0d0h0m0s$##` -> `2023-10-15T12:24:53.413445Z` (ISO 8601 with fractional seconds)
*   `##$SyslogTime-0d0h0m0s$##` -> `Oct 15 12:24:53` (RFC 3164 standard header)
*   `##$Epoch-0d0h0m0s$##` -> `1697372693` (UNIX epoch seconds)
*   `##$Date-0d0h0m0s$##` -> `2023-10-15` (W3C date)
*   `##$Time-0d0h0m0s$##` -> `12:24:53` (W3C time)
*   `##$DeviceTime-0d0h0m0s$##` -> `[15/10/2023:12:24:53 GMT]` or `[15/Oct/2023:12:24:53 -0400]`

## 6. Key Constraints & Pitfalls

### Critical SIEM Parser Dependencies
1. **Positional Token Alignment in ELFF**: Parsers (such as Chronicle, Splunk Add-on for Symantec Blue Coat ProxySG, and Micro Focus ArcSight) rely on fixed column indexing for space-delimited text. If an optional field is missing, it **must** be populated with a `-` or `""` placeholder. Do not truncate rows prematurely.
2. **Quoted Spaces**: Any field that can contain whitespace (`cs_categories`, `cs_user_agent`, `x_bluecoat_application_name`, `rs_content_type`) **must** be enclosed in quotes. A missing quote will offset parser column counts, corrupting downstream field extraction.
3. **HTTP Status vs. Action Consistency**:
   * If `sc-status` is `407`, `s-action` should be `TCP_DENIED`, and `x-exception-id` should be `authentication_failed`.
   * If `sc-status` is `403`, `s-action` should be `TCP_DENIED`, and `sc-filter-result` should be `DENIED`.
   * If `sc-status` is `200` on a HTTPS CONNECT request, `s-action` should typically be `TCP_TUNNELED` or `TCP_ACCELERATED`.
4. **UUID Format Integrity**: `x-bluecoat-transaction-uuid` values consist of three hyphen-separated hex strings (e.g., `16hex-16hex-16hex` like `86a1afe2142c57c1-000000005053b64e-000000005d26dbef`).
5. **Escape Sequences in JSON Formats**: Ensure URI query parameters, WAF rule dumps, or user-agent strings embedded inside the JSON payload correctly escape double quotes (`\"`) and backslashes (`\\`).
