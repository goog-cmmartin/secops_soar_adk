# OKTA System Log — AI Generation Guide & Field Playbook

## 1. Overview & Log Purpose
Okta System Logs record identity, authentication, authorization, directory synchronization, and administrative events across an organization's Okta Identity Cloud tenant. 

Primary recorded activities include:
- **Authentication & Sessions**: Logins (`user.session.start`), logouts, step-up MFA verifications, MFA push challenges/denials, legacy authentication via Active Directory/RADIUS agents.
- **Single Sign-On (SSO) & OAuth**: Application access requests via SAML 2.0, WS-Federation, OIDC authorization code grants, token issuances.
- **Policy Evaluations**: Sign-on policy, MFA enrollment policy, and password policy decisions (`policy.evaluate_sign_on`).
- **Identity & Access Governance**: Group membership changes, application assignments, user lifecycle state changes (provisioning, deprovisioning, user import/matching).
- **Administrative Actions**: Privilege grants (`user.account.privilege.grant`), API token creation, policy modifications, network zone changes.
- **Threat Intelligence & Security Signals**: Okta ThreatInsight alerts (`security.threat.detected`), impossible travel / new behavior detection, user-reported suspicious activity.

---

## 2. Format Specification
- **Encoding & Wire Format**: Single-line UTF-8 JSON objects (NDJSON / newline-delimited JSON).
- **Delimiters & Quotes**: Standard JSON rules apply. All keys and string values must be enclosed in double quotes (`"`). Internal quotes, backslashes, and control characters must be escaped.
- **Structural Integrity**: Objects can be nested up to 4 levels deep (e.g., `client.geographicalContext.geolocation.lat`). Key order within the JSON object may vary between log collectors, but all core keys must maintain their exact hierarchical structure.

## 3. Schema Breakdown & Fields

### Top-Level Attributes

| Field | Type | Description | Allowed / Realistic Values |
| :--- | :--- | :--- | :--- |
| `uuid` | String | Unique event identifier (UUID v4) | e.g., `"94f7b9ff-535a-54dc-f0db-245e23456c1c"` |
| `published` | String / Integer | Event generation timestamp | ISO 8601 UTC string (`"YYYY-MM-DDTHH:MM:SS.sssZ"`) or Unix Epoch seconds (`1587379735`). |
| `eventType` | String | Dot-notated Okta event taxonomy string | e.g., `user.session.start`, `user.authentication.sso`, `policy.evaluate_sign_on` (See Event Types list) |
| `displayMessage` | String | Human-readable event description | e.g., `"User login to Okta"`, `"Grant user privilege"` |
| `severity` | String | Event severity level | `"INFO"`, `"WARN"`, `"ERROR"`, `"DEBUG"` |
| `version` | String | Okta log schema version | Always `"0"` |
| `legacyEventType` | String / null | Backward-compatible event tag | e.g., `"core.user_auth.login_success"`, `"app.auth.sso"`, or `null` |

---

### Nested Objects

#### `actor`
Represents the entity that initiated the event.
- `id` (String): Okta entity ID (e.g., `"00u1h1jzn5YF01nyN417"`), alphanumeric string, system ID (e.g., `"opl1tjun5qEGhDpsV9p3"`), or IPv4/IPv6 address.
- `type` (String): `"User"`, `"SystemPrincipal"`, `"PublicClientApp"`, `"IP address"`, `"AppInstance"`.
- `alternateId` (String): Primary user email (e.g., `"alex.a@example.com"`), `"system@okta.com"`, application name, or `"unknown"`.
- `displayName` (String / null): Display name of the user/system or `null`.
- `detailEntry` (Object / null): Additional metadata, usually `null`.

#### `outcome`
The result of the action or policy evaluation.
- `result` (String / null): `"SUCCESS"`, `"FAILURE"`, `"CHALLENGE"`, `"ALLOW"`, `"DENY"`, `"UNKNOWN"`, `"SKIPPED"`, or `null`.
- `reason` (String / null): Explanatory reason (e.g., `null`, `"INVALID_PASSWORD"`, `"Sign-on policy evaluation resulted in CHALLENGE"`, `"User rejected Okta push verify"`, `"Password Spray"`).

#### `client`
Information about the client device, browser, and network origin.
- `device` (String / null): `"Computer"`, `"Mobile"`, `"Tablet"`, `"Unknown"`, or `null`.
- `id` (String / null): Client application ID or `null`.
- `ipAddress` (String / null): Public IPv4/IPv6 address of the originating client.
- `zone` (String / null): Configured Okta Network Zone name (e.g., `"Zone 01"`, `"Corporate_VPN"`, `"null"`, or `null`).
- `userAgent` (Object / null):
  - `rawUserAgent` (String): Full User-Agent string.
  - `os` (String): e.g., `"Windows 10"`, `"Mac OS X"`, `"iOS"`, `"Android"`, `"Linux"`, `"UNKNOWN"`.
  - `browser` (String): e.g., `"CHROME"`, `"FIREFOX"`, `"SAFARI"`, `"EDGE"`, `"UNKNOWN"`.
- `geographicalContext` (Object / null):
  - `city` (String / null): e.g., `"Sydney"`, `"Atlanta"`, `"London"`, `null`.
  - `state` (String / null): e.g., `"New South Wales"`, `"Georgia"`, `null`.
  - `country` (String / null): e.g., `"Australia"`, `"United States"`, `"Germany"`.
  - `postalCode` (String / null): e.g., `"2000"`, `"30305"`, `null`.
  - `geolocation` (Object / null): `{"lat": -33.8591, "lon": 151.2002}`.

#### `authenticationContext`
Details regarding the authentication mechanism and state.
- `authenticationStep` (Integer): Step index in multi-step flow (`0`, `1`, `2`).
- `externalSessionId` (String / null): Okta session identifier (e.g., `"711OOh4OM2iK3j1slkuUdkcfG"` or `null`).
- `interface` (String / null): Interaction interface (e.g., `"AD APP Instance"`, `"Radius"`, `null`).
- `issuer` (String / null): Identity issuer URL/URI or `null`.
- `authenticationProvider` (String / null): `"ACTIVE_DIRECTORY"`, `"FACTOR_PROVIDER"`, `"OKTA"`, `"FEDERATION"`, or `null`.
- `credentialProvider` (String / null): `"OKTA_CREDENTIAL_PROVIDER"`, `"RSA_CREDENTIAL_PROVIDER"`, `"DUO_CREDENTIAL_PROVIDER"`, or `null`.
- `credentialType` (String / null): `"PASSWORD"`, `"SMS"`, `"PUSH"`, `"OTP"`, `"FIDO_U2F"`, `"FIDO_WEBAUTHN"`, or `null`.

#### `securityContext`
Network routing and threat enrichment context.
- `asNumber` (Integer / null): Autonomous System Number (e.g., `12400`, `15169`, `null`).
- `asOrg` (String / null): ASN Organization name (e.g., `"Microsoft Corporation"`, `"example isp"`, `null`).
- `isp` (String / null): Internet Service Provider name.
- `domain` (String / null): Reverse DNS domain (e.g., `"example.net"`, `null`).
- `isProxy` (Boolean / null): `true`, `false`, or `null`.

#### `transaction`
Details linking multiple related log entries.
- `type` (String / null): `"WEB"`, `"JOB"`, or `null`.
- `id` (String): Transaction identifier or `"unknown"`.
- `detail` (Object): Custom metadata object, usually `{}`.

#### `request`
Contains the list of IP hops recorded by Okta edge infrastructure.
- `ipChain` (Array of Objects):
  - `ip` (String): IPv4/IPv6 address.
  - `version` (String): `"V4"` or `"V6"`.
  - `source` (String / null): Source indicator or `null`.
  - `geographicalContext` (Object): Same schema as `client.geographicalContext`.

#### `target`
Array of entities (or `null`) affected by or referenced in the event.
Each element contains:
- `id` (String): Unique identifier of target.
- `type` (String): `"User"`, `"AppUser"`, `"AppInstance"`, `"PolicyEntity"`, `"PolicyRule"`, `"UserGroup"`, `"code"`.
- `alternateId` (String / null): Email address, application key, or `null`.
- `displayName` (String / null): Target display label.
- `detailEntry` (Object / null): Specialized metadata (e.g., `{"policyType": "OktaSignOn"}`, `{"signOnModeType": "SAML_2_0"}`), or `null`.

#### `debugContext.debugData`
A key-value dictionary containing dynamic event-specific contextual attributes. Common keys include:
- `requestId` (String): Unique HTTP request identifier.
- `requestUri` (String): Internal API/endpoint URI (e.g., `"/api/v1/authn"`, `"/oauth2/v1/authorize"`).
- `url` (String): Full relative URL string.
- `threatSuspected` (String): `"true"` or `"false"`.
- `authnRequestId` (String): Authentication challenge tracking ID.
- `deviceFingerprint` (String): Hexadecimal device fingerprint hash.
- `privilegeGranted` (String): Administrator roles granted (e.g., `"Super admin"`, `"Read only admin, Group Membership administrator (all)"`).
- `signOnMode` (String): Application sign-on mode (e.g., `"SAML 2.0"`, `"OpenID Connect"`, `"WS-Federation"`).
- `behaviors` (String): Serialized behavioral risk flags (e.g., `"{New Geo-Location=NEGATIVE, New Device=NEGATIVE, New IP=NEGATIVE, New State=NEGATIVE, New Country=NEGATIVE, Velocity=NEGATIVE, New City=NEGATIVE}"`).
- `risk` (String): Risk score evaluation (e.g., `"{level=LOW}"`, `"{level=HIGH}"`).

## 4. Timestamp & Dynamic Time Templating

Okta logs natively use ISO 8601 extended UTC format with millisecond precision (`YYYY-MM-DDTHH:mm:ss.sssZ`). When streaming via certain collectors/APIs, it can also appear as integer Unix epoch seconds.

### Dynamic Time Tags
When generating synthetic logs for scenario test suites, use relative time template tags:
- **ISO 8601 Milliseconds**: `##$TimeStamp-0d0h0m0s$##` (Evaluates to `YYYY-MM-DDTHH:mm:ss.sssZ`)
- **Unix Epoch Seconds**: `##$Epoch-0d0h0m0s$##` (Evaluates to integer epoch seconds, e.g., `1710000000`)
- **Offset Examples**:
  - Current event: `##$TimeStamp-0d0h0m0s$##`
  - 10 minutes prior: `##$TimeStamp-0d0h10m0s$##`
  - 2 hours prior (Epoch): `##$Epoch-0d2h0m0s$##`

## 6. Key Constraints & Pitfalls

1. **Mandatory Top-Level Keys**:
   Parsers like Splunk Add-on for Okta (`Splunk_TA_okta`) or Elastic Okta integration fail if `uuid`, `eventType`, `published`, `severity`, or `version` are missing or improperly typed.
2. **Handling Nulls vs Missing Fields**:
   - `target` is explicitly `null` or a JSON array of objects (`[{...}]`), never an empty object `{}`.
   - `outcome.reason` must be `null` if the action succeeded without errors.
   - When geolocation is unavailable, coordinate objects must be `{"lat": 0.0, "lon": 0.0}` or `null`, and string fields (city, state) must be explicit `null`.
   - `zone` frequently contains the literal string `"null"` rather than JSON `null` when no specific named network zone matched.
3. **Array vs Single-Object Constraints**:
   - `request.ipChain` must always be an Array, even if it contains 0 items (`[]`) or 1 item.
   - `target` must always be an Array when populated, even if there is only 1 target entity.
4. **Context Dependency in `debugContext.debugData`**:
   - `threatSuspected` is a string (`"true"` / `"false"`), not a JSON boolean.
   - Admin privilege grants (`user.account.privilege.grant`) must include `privilegeGranted` in `debugData`.
   - End-user suspicious reports (`user.account.report_suspicious_activity_by_enduser`) contain nested sub-event coordinates prefixed with `suspiciousActivityEvent*` inside `debugData`.
5. **No Trailing Commas**: Ensure all JSON objects and arrays adhere to strict RFC 8259 syntax with zero trailing commas.
