# Google SecOps MCP Server Tool Categories

---

### 1. Case & Incident Management (11 Tools)

```json
[
  "create_case_comment",
  "execute_bulk_close_case",
  "get_case",
  "get_case_alert",
  "get_connector_event",
  "list_case_alerts",
  "list_case_comments",
  "list_cases",
  "list_connector_events",
  "update_case",
  "update_case_alert"
]
```

* **`list_cases`**: Lists and filters security cases with sorting and pagination.
* **`get_case`**: Retrieves complete case details, tasks, tags, and associated products.
* **`update_case`**: Updates case priority, stage, assignee, environment, or marks as incident.
* **`execute_bulk_close_case`**: Bulk closes multiple cases with root cause, reason, and comments.
* **`list_case_alerts`**: Lists alerts associated with a specific case.
* **`get_case_alert`**: Retrieves a single security alert from a case (including SLA and relations).
* **`update_case_alert`**: Modifies case alert status (e.g. `CLOSE`), priority, or closure reason.
* **`list_case_comments`**: Lists all analyst notes and comment history on a case.
* **`create_case_comment`**: Appends a new analyst note or comment to a case.
* **`list_connector_events`**: Lists raw connector events attached to a case alert.
* **`get_connector_event`**: Retrieves the raw JSON payload of an event triggering an alert.

### 2. Playbooks, SOAR Integrations & Response Actions (8 Tools)

```json
[
  "execute_actions",
  "execute_manual_action",
  "fetch_enrichment_actions",
  "list_integration_actions",
  "list_integration_instances",
  "list_integrations",
  "list_playbook_instances",
  "list_playbooks"
]
```

* **`list_playbooks`**: Lists configured playbooks (`REGULAR`, `NESTED`).
* **`list_playbook_instances`**: Retrieves historical execution instances and outcomes of playbooks.
* **`list_integrations`**: Lists available third-party response integrations.
* **`list_integration_actions`**: Lists specific actions exposed by an integration.
* **`list_integration_instances`**: Lists configured connections/instances for an integration.
* **`fetch_enrichment_actions`**: Retrieves available SOAR enrichment actions for a SIEM alert.
* **`execute_actions`**: Executes batch enrichment actions against an alert.
* **`execute_manual_action`**: Runs manual/custom response actions (e.g., Block IP, Isolate Host, custom scripts) on cases and entities.

### 3. Detection Engineering & Rule Management (8 Tools)

```json
[
  "create_rule",
  "fetch_alert_data",
  "generate_rules",
  "get_rule",
  "list_rule_detections",
  "list_rule_errors",
  "list_rules",
  "validate_rule"
]
```

* **`list_rules`**: Lists configured YARA-L detection rules in Chronicle SIEM.
* **`get_rule`**: Retrieves full YARA-L rule code, revisions, and deployment state.
* **`create_rule`**: Deploys a new YARA-L detection rule.
* **`validate_rule`**: Validates YARA-L 2.0 syntax and compilation without deploying.
* **`list_rule_detections`**: Queries historical detections generated by a rule over a time range.
* **`list_rule_errors`**: Retrieves compilation and runtime errors for a rule.
* **`generate_rules`**: Uses AI to generate draft YARA-L rules from a Threat Detection Opportunity.
* **`fetch_alert_data`**: Pulls an aggregated profile of a SIEM alert, detections, and execution history.

### 6. Threat Hunting, UDM Search & Entity Analysis (10 Tools)

```json
[
  "get_involved_entity",
  "get_ioc_match",
  "get_security_alert",
  "list_involved_entities",
  "list_security_alerts",
  "search_entity",
  "summarize_entity",
  "translate_udm_query",
  "udm_search",
  "update_security_alert"
]
```

* **`udm_search`**: Executes raw Universal Data Model (UDM) queries over ingested logs.
* **`translate_udm_query`**: Translates natural language into valid UDM syntax.
* **`summarize_entity`**: Aggregates historical activity across UDM logs for an entity (IP, domain, user, hash).
* **`search_entity`**: Searches for entities globally across all cases.
* **`list_involved_entities`**: Lists all entities involved in a case alert.
* **`get_involved_entity`**: Retrieves detailed entity metadata and context for an alert.
* **`get_ioc_match`**: Retrieves feed-based IOC matches observed in Chronicle logs.
* **`list_security_alerts`**: Queries SIEM engine security alerts over a time range.
* **`get_security_alert`**: Fetches detailed context and detection data for a SIEM alert.
* **`update_security_alert`**: Modifies SIEM alert status, verdict (`false_positive`, `true_positive`), root cause, or comments.

### 8. Ingestion, Feeds & Parser Management (16 Tools)

```json
[
  "activate_parser",
  "create_feed",
  "create_parser",
  "deactivate_parser",
  "delete_feed",
  "disable_feed",
  "enable_feed",
  "generate_feed_secret",
  "get_feed",
  "get_parser",
  "import_logs",
  "list_feeds",
  "list_log_types",
  "list_parsers",
  "run_parser",
  "update_feed"
]
```

* **`list_feeds`**: Lists all active and configured ingestion pipelines.
* **`get_feed`**: Retrieves details and health state of a specific data feed.
* **`create_feed`**: Sets up a new data feed (Amazon S3, Cloud Storage, HTTPS Push, APIs).
* **`update_feed`**: Updates data feed configuration fields.
* **`enable_feed`**: Enables or resumes a data feed.
* **`disable_feed`**: Pauses/disables a data feed.
* **`delete_feed`**: Deletes a data feed configuration.
* **`generate_feed_secret`**: Generates or rotates secrets for HTTPS push feeds.
* **`list_log_types`**: Lists supported Chronicle log types (e.g. `OKTA`, `WINEVTLOG_XML`, `AWS_CLOUDTRAIL`).
* **`list_parsers`**: Lists parser configurations for log types.
* **`get_parser`**: Retrieves parser metadata and Logstash transformation code.
* **`create_parser`**: Creates custom Logstash parsers for log normalization.
* **`run_parser`**: Tests and evaluates Logstash parser logic against raw sample logs.
* **`activate_parser`**: Promotes a parser version to active production ingestion.
* **`deactivate_parser`**: Deactivates a parser version.
* **`import_logs`**: Directly ingests raw test logs into Chronicle for pipeline testing.
